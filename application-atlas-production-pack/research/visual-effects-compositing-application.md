## Research Goal

Understand what a Visual Effects Compositing Application really is from real products: what "VFX compositing" means as a software job, what the core objects are (the comp/script, plates and elements, mattes/alpha, the merge, the render), what the canonical workflow is, which interfaces exist, which rules matter (alpha/matte logic, color management, resolution independence, offline render-to-files), and where the boundaries sit against the neighboring Types (Video Compositing, Motion Graphics, Video Editor/NLE, 3D Creation/Rendering, Raster Image Editor, AI Video Editing).

## Initial Boundary (hypothesis before research)

- What: software that integrates visual-effects elements (keyed live-action, CG renders, painted fixes, graphics) into photographed footage, shot by shot, offline — the film/TV VFX pipeline family the video-compositing pass named "Nuke/Flame/Fusion class".
- Users: compositors, roto/paint artists, VFX supervisors, studios; also broadcast/post houses and solo artists.
- Nearest neighbors: Video Compositing Application (sibling, processed — real-time program production), Motion Graphics Application (processed — graphic-first creation), Video Editor / NLE (04.06), 3D Rendering / 3D Modeling (04.13/04.14), Raster Image Editor (04.02), AI Video Editing (04.21).
- Open questions: is the shot/pipeline context definitional or common? is the node graph definitional? is the 3D workspace definitional? is multi-shot management definitional? does the real-time/offline seam hold from this side? is "video compositing" one Type or two?

## Research Questions

1. What do the products actually do — what are the core objects (comp/script, Read/Write, mattes, merge, render) and how are they related?

## Canonical Abstraction Hierarchy

### L0 — Defining Invariant (minimal)

Three jointly-held structures:

1. **Existing imagery as the primary material** — the application's working material is pre-existing motion imagery: photographed plates and/or separately produced elements (CG renders, keyed pulls, graphics), read in as frame sequences. The artist integrates; the application is not primarily a from-scratch graphic-creation tool and not a 3D scene-production tool. Remove → motion-graphics territory (graphic-first creation) or 3D application territory.
2. **The composite — multi-source integration into one image** — the central act: combining separate image sources into a single image with per-source control over how each combines (mattes/alpha, merge operations, transforms, color matching), so that separately produced elements read as parts of one scene. Remove → single-source effects filtering (below the Type) or a footage cleanup tool.
3. **Offline, shot-based operation** — work is organized around discrete shots (a comp bound to a bounded frame range) processed offline through an iterate→preview→render loop, delivering finished frames as files back into the production — not a live, continuously running program output. Remove the offline/shot basis and add live operation → real-time program production = Video Compositing territory.

Jointly-held is load-bearing: 1 alone = a footage/media manager or editor; 2 without 1 = graphic-design layer compositing (MG/design territory); 3 without 1+2 = an offline effects filter; 1+2 without 3 = live keying/mixing (the sibling Type); 1+3 without 2 = a cleanup/retouch specialist below the Type (the roto/paint-only generation of tools — Silhouette's own pre-2016 lineage — which the market treats as adjacent specialists until a compositing core is added); 2+3 without 1 = offline compositing of self-created graphics (MG territory).

### L1 — Common Mature Structure

- **Composition architecture** — a persistent, re-editable graph of operations: node graph (dominant in this sample) or layer stack (market-attested via the unreachable mass-market anchor and Fusion's own contrast). The architecture is the comp's recipe; the composite is recomputed from it.
- **The integration toolset** — keying (multiple keyer algorithms + matte-finesse/despill), rotoscoping/masks (splines, per-shape tracking), paint/cleanup (clone/repair, wire/rig removal), tracking & stabilization (point/planar; 3D camera tracking at advanced tiers), transform/reformat/warp/morph, temporal operations (retime, motion blur), color correction under color management.
- **2D/3D integration machinery** — 3D workspace (cameras/lights/cards, projection), deep data, multi-channel EXR/AOV workflows, stereoscopic views. Common in film-grade products; not required (Natron's documented core is 2D).
- **The preview loop** — processing viewer (exposure/gamma-class controls), flipbook/playback, A/B/wipe comparison, external broadcast-monitor check.
- **Render/write-out** — render nodes writing image sequences/files; render-all/selected; headless/CLI rendering; network/render-farm distribution.
- **Color management** — float/linear internal processing; OCIO/ACES-class pipelines; premultiplied-alpha convention.
- **Scripting/expressions + reusable macros** (gizmos/templates/presets).
- **Multi-shot management/conform/review layer** — timeline environments for shot management, conform, versioning/snapshots, annotations, review, and round-trip exports to editorial; or bridge tools (send clip from the edit → comp → rendered shots update back). Present in suite products; the single-shot compositor satisfies the core without it.
- **Plugin ecosystems** — OpenFX-class plugin support; bundled third-party effect libraries.

### L2 — Variant / Optional Structure

- Composition architecture: node graph vs layer stack.
- Packaging: standalone desktop app; page embedded in an NLE; multi-host plugin; suite with editorial/conform environment; free open-source.
- Customer tier: high-end film, broadcast/post, specialist roto/paint departments, indie/solo, education.
- ML/AI assistance (roto propagation, matting, tracking, denoise, upres) — era-current.
- Adjacent capability surfaces carried by some products: broadcast graphics/MG authoring; virtual-production real-time playback onto LED walls; editorial timeline editing.
- Deep compositing, USD scene round-trips, Gaussian splats — era-current advanced machinery.

### L3 — Vendor-specific (research notes only)

- Nuke: 1023-channel workflow; Graph Scope Variables; CopyCat/Inference ML; SmartRoto; Nuke Assist mode; Furnace tools; .nk script format; non-commercial mode; Nuke Stage; Hiero/HieroPlayer split; ~2-frame-class latency posture not applicable (offline).
- Fusion: Fusion Connect; bin server; macro templates consumed by Resolve's edit/cut pages; unlimited free render nodes; Delta keyer; Resolve-page embedding; $295 Fusion Studio activated via a Resolve license.
- Silhouette: multi-host plugin (AE/Premiere/Nuke/Fusion/Resolve/Flame); Mocha Pro node; bundled Sapphire/Continuum/Particle Illusion nodes; Power Matte; sessions; non-destructive AutoPaint recording; JSON-RPC + MCP servers; Cryptomatte data ports.
- Natron: NatronRenderer headless CLI; PyPlugs community gizmos; OpenFX support; premultiplied-alpha default documented as a project choice.

## Rejected Findings (not promoted to core)

- **"The node graph is definitional"** — rejected: the mass-market reference tool is layer-based (widely attested; Fusion's own page contrasts nodes with "stacks of layers"). The invariant is the composite and its re-editable recipe, not the architecture widget. Node-vs-layer = variant axis.
- **"A 3D workspace is definitional"** — rejected: Natron's documented core is a 2D compositing toolkit; Silhouette's 3D Scene node dates from 2025; early digital compositing was 2D. The 3D workspace serves integration (L1).
- **"Multi-shot management is definitional"** — rejected: Nuke's own User Guide documents plain Nuke as "a single shot compositor"; the timeline/conform/review layer is suite machinery (L1). A solo artist compositing one shot satisfies the core.
- **"Deep compositing / EXR / ACES / USD are definitional"** — rejected: era-current machinery; the 1990s generation composited without any of it.
- **"The film/TV studio pipeline is definitional"** — rejected as stated: the shot-based unit of work is definitional; the full pipeline machinery (conform, versioning, round-trip, farms) is L1/L2. Solo/indie use satisfies the core.
- **"Keying is definitional"** — rejected at the core: sources can be combined via roto mattes or render alpha without keying; keying is the standard route to transparency for photographed plates (L1, universal in the sample but not structurally required).
- **"Roto/paint alone is this Type"** — rejected: Silhouette shipped for 11 years as roto/paint before adding its compositor (v6, 2016); the market treats roto/paint specialists as adjacent to, not identical with, compositing applications. Paint serves the composite.
- **"This Type includes live mixing/keying on a running program"** — rejected: that is the sibling Type's population (vMix/OBS class); no sampled product here produces a live program output.
- **"This Type = 'video compositing' by name"** — rejected as a naming-based merge: the phrase spans both families (Natron's own docs use it for the offline family; the live family uses "live production/mixing"). Populations and operating modes are disjoint; see Boundary Findings #1.

## Boundary Findings

1. **vs Video Compositing Application (04.07 sibling, processed — REMAINING FLAG DISCHARGED from this side; seam RATIFIED)**: the sibling pass proposed the seam "operating mode and job" — real-time program production vs offline shot-based compositing — and asked this pass to ratify it. **Ratified.** From this side's evidence: every sampled product operates offline on discrete shots and delivers rendered files — Nuke's User Guide defines the comp by a frame range ("your 'shot'") and renders via Write nodes to image sequences; Natron documents headless render-farm rendering; Fusion Connect renders shots back into editorial timelines; none of the four documents a live program output, concurrent streaming destinations, or operator-directed live switching — the sibling sample's defining structures. Conversely, the sibling's sampled products (vMix/OBS/Ecamm/StreamYard) never describe shot-based compositing, roto, tracking, or render-to-files pipelines. Removal tests both directions hold: remove real-time program operation from the live family → offline compositing (this Type / editing territory); remove the shot-based offline basis and add live operation → the live family. **Naming note resolved: keep both Types, no alias.** The market phrase "video compositing" indeed spans both families — direct Tier-1 evidence: Natron's documentation self-describes this offline family as "video compositing software", while the live family's vendors use "live production/mixing" — but the phrase's ambiguity does not collapse the product populations, which are disjoint at their centers of gravity. Both research notes now carry the ratified seam.
2. **vs Motion Graphics Application (04.07 sibling, processed — joint-review flag DISCHARGED from this side)**: the MG pass's seam — "footage-first shot-based integration [keying/roto/tracking/cleanup] vs graphic-first creation of animated graphic material" — holds from this side. The sampled population is footage-first: plates and produced elements are the material; graphic authoring is absent or peripheral (Nuke has no MG authoring surface in its documented core; Silhouette's roto/paint is not graphic creation). The overlap is real at product level: Fusion carries a broadcast-graphics/titles surface and the unreachable mass-market anchor is dual-use (MG + VFX) — straddling products, not evidence of Type collapse. Element-level overlap confirmed: graphics appear inside shots as composited elements (the MG pass documented the same overlap from its side). Test both directions: remove graphic authoring → this Type stands (Nuke/Silhouette satisfy with none); remove footage-first integration → MG stands.
3. **vs Video Editor / NLE (04.06)**: the editor's unit of work is the timeline sequence of clips assembled into a program; this Type's unit is the within-shot composite delivered back to the edit. The seam is vendor-documented: Fusion Connect sends clips from Resolve/Avid timelines into Fusion and renders finished shots back; Nuke Studio's timeline exists for shot management/conform/review ("matching up the footage from a shoot with the required edit decisions") — pipeline machinery, not narrative editing. NLEs bundle compositing pages (Resolve's Fusion page) — packaging, not identity. Test: remove timeline sequencing → this Type stands; remove within-shot integration → editor territory.
4. **vs 3D Creation / 3D Rendering (04.13/04.14)**: vendor-authored seam (Natron docs): "A video compositing software is not a 3D computer graphics software… it is perfectly suited for combining computer-generated elements produced by other software with live-action video… assemble the elements produced separately." CG renders are inputs (EXR/AOV/deep data); the compositor may include a 3D workspace for scene assembly and projection, but its deliverable is the composite, not the CG asset or the render. Test: remove the footage-integration job → 3D territory; remove the 3D workspace → still a compositor.
5. **vs Raster Image Editor (04.02)**: shared primitives (layers/mattes/paint/clone) but different units: the still image vs the frame sequence with motion-dependent operations (tracking, roto over time, temporal ops) and shot/pipeline context. Test: remove the sequence/motion context → image editor territory.
6. **vs AI Video Editing / AI Video Generator (04.21)**: ML tools inside compositors (roto propagation, matting, denoise, upres) are capabilities serving the composite; prompt-generated footage is a different material model. Not sampled; adjacency noted only.
7. **Adjacent surface recorded (no taxonomy change)**: real-time broadcast compositing engines (virtual-set/AR systems driven on live programs) and virtual-production LED playback (Nuke Stage) straddle the real-time/offline seam from the broadcast side; the sibling pass noted the same. If a future pass covers broadcast graphics engines, the seam should be revisited from that side.

## Historical / Market-Sample Check

- **Pre-digital ancestry**: the job — combining separately photographed elements into one image, shot by shot — is the optical printer / matte-shot practice; the software Type begins with digital compositing. The three L0 legs describe the digital job directly.
- **1990s digital generation**: film-scan compositors (Cineon-class), tape/online finishing compositors (Quantel Henry/Domain class), SGI-based compositors (the Flame/Inferno lineage), early desktop compositors (After Effects 1993; Digital Fusion), and Nuke (born inside a film studio's pipeline, later productized) — all satisfy the three legs with none of the modern machinery (no deep data, no OCIO/ACES, no USD, no ML, no render clouds; node and layer architectures both present from the start).
- **The definition requires none of**: node graphs, 3D workspaces, deep compositing, multi-channel EXR, color-management standards, render farms, multi-shot suites, ML assistance, virtual production — all L1/L2/era-current.
- **Conclusion**: the definition is not over-fitted to the current film-pipeline market; the historical and tier poles (open-source 2D compositor; single-shot compositor; roto/paint specialist with an added compositor) all satisfy it.

## Final Synthesis

The Visual Effects Compositing Application is defined by a minimal core: existing imagery (photographed plates and separately produced elements) as the primary material; the composite — combining multiple image sources into one image with per-source control over mattes/alpha, merge operations, transforms, and color match, so separately produced elements read as one scene; and offline, shot-based operation — a re-editable comp bound to a bounded frame range, iterated through a preview loop and rendered out to files that flow back into the production. Around this core, mature products converge on a standard structure: a re-editable operation graph (node or layer architecture); the integration toolset (keying, rotoscoping, paint/cleanup, tracking/stabilization, transform/warp, temporal operations, color correction under float/linear color management); 2D/3D integration machinery (3D workspaces, deep data, multi-channel EXR) at the film-grade tier; the preview loop (processing viewer, flipbook, comparison, external monitor); render-to-files delivery with headless/network rendering; scripting and reusable macros; and — in suite products — a multi-shot layer (conform, versioning, review, round-trip to editorial) that the single-shot compositor does not require. Products differentiate along architecture (node vs layer), packaging (standalone, NLE-embedded page, multi-host plugin, suite), tier (film, broadcast, specialist roto/paint, indie, open-source), and era machinery (ML assistance, deep data, USD, virtual production). The boundaries are ratified: against real-time program production (the sibling Type — offline shot-based vs live continuous program; the shared "video compositing" phrase is a naming collision, not a Type identity), against motion graphics (footage-first integration vs graphic-first creation), against the NLE (within-shot integration vs timeline assembly, with vendor-documented round-trips), against 3D applications (assembly of produced elements vs production of CG scenes — a vendor-authored seam), and against the raster image editor (frame sequences vs stills). The historical check holds: the 1990s digital compositing generation and the pre-digital optical practice satisfy the same core with none of the modern machinery.
