# 现状分析：Application Atlas 项目创建与切换入口

## 改进目标

在现有 Application Atlas 中增加最小项目入口，让用户创建、列出和重新打开 U17 项目，为后续资料收藏与文档工作台提供项目上下文。

## 已观察事实

- EP-S1 `project_store.py` 已提供独立 SQLite 项目库和 `create_project`、`get_project`，但没有列表方法。
- EP-S2 `drafts_api.py` 是当前本地 JSON API，已有 drafts、sources、review 等路由，没有 `/api/projects`。
- EP-S3 `atlas.ts` 是前端数据访问层，尚无项目数据类型与请求方法。
- EP-S4 `search.tsx` 是现有搜索入口，尚无当前项目上下文。
- EP-S5 已确认 U17 同时支持新想法和已有项目，并要求项目数据独立持久化。

以上是代码与文档读取结果，没有把“未搜索到”写成系统绝对不存在。样例没有实际启动前端，因此不声明当前导航交互效果。

## 影响范围

后端需要项目列表查询、输入错误映射和 REST 路由；前端需要项目类型、创建表单、项目列表和当前选择。语料搜索、草稿生成和分类数据库不需要改变。OpenCode execution 也不在本次范围。

## 风险与未知

- EP-U1：入口放在全局侧栏还是搜索页上方，需要最小原型比较，当前技术任务不固定最终布局。
- EP-U2：原生目录选择器依赖桌面壳能力，归入后续 M3。本轮只接受明确字符串工作区并显示解析后的路径。
- 工作区路径可能不存在或暂不可访问。创建项目时记录意图，进入代码执行前再做访问与基线检查。
