# 技术方案：本地优先的个人日计划器

## 数据边界

使用本地 SQLite 保存 `project`、`task`、`daily_commitment` 与 `time_block`。对象使用稳定标识；`daily_commitment` 通过日期和 task ID 表达 NI-R1，不复制任务正文。`time_block` 引用 commitment，保存本地日期、开始分钟和结束分钟以支持 NI-R2。

NI-R3 要求每次创建、移动和删除在单一事务中提交。启动后从数据库重建当天视图，不依赖内存缓存。首版不保存外部日历凭据。

## 冲突规则

对同一天时间块按开始时间排序。任意相邻区间满足 `previous.end > current.start` 即产生重叠；开始早于可用时段或结束晚于可用时段产生越界。冲突计算是纯函数，返回涉及的 block ID 与原因。它只服务 NI-R4，不写回新的时间。

## 接口

- 项目和任务：创建、列出、更新。
- 日计划：读取某天、加入/移除任务。
- 时间块：创建、移动、删除；响应携带重新计算后的冲突。

写接口校验对象归属、时间范围和 `start < end`。本地单用户首版不引入账户、团队权限或同步服务。

## 需求映射

- NI-R1：`daily_commitment` 与日计划接口。
- NI-R2：`time_block` 与编辑接口。
- NI-R3：SQLite 事务和启动恢复。
- NI-R4：无副作用冲突计算。

NI-R5 和 NI-U2 不进入当前数据同步设计。NI-U1 只影响未来产品规则，不改变首版 schema。
