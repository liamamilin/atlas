# U17 产品打磨计划

日期：2026-09-20  
状态：产品打磨和核心发布复验已完成，M5 三个产品使用案例已完成当前范围内的记录与验收；进入发布收口和执行后端演进决策。  
目标：把已经能够走通的主线变成用户可以理解、顺利完成、出错可恢复、结果可信的完整产品。

## 1. 这次调整解决什么问题

U17 的核心能力已经可以连续完成“搜索阅读 → 项目资料 → 文档与范围 → 执行 → 应用 → 验收”。当前最有价值的工作不是继续追求生成结果的局部指标，而是把用户实际接触到的产品收口：入口清楚，状态一致，下一步明确，失败可恢复，输出可带走。

以下工作不回到产品功能调优主线，按 M5 评估阶段的证据协议推进：

- 普通生成对照、效果评分和重试成本的精细比较。
- 多类型案例作为评估样本的扩展。
- 多引擎产品化、云端执行和通用 coding agent harness。
- 只改善内部指标、但不改变用户完成任务体验的功能调优。

这些内容保留在 [M5 试点计划](U17_M5_PILOT_PLAN.md)；产品打磨进入条件已经满足，简单新想法和已有项目改进案例均已完成，下一项是多类型需求案例。

## 2. 打磨顺序

### P0：主路径完整且不迷路

- 首页、浏览类型、类型叶子、项目创建和项目工作台之间的入口关系一致。
- 每个页面都有明确的当前状态、下一步动作和返回路径。
- 新想法与已有项目两条入口都能从开始走到结果核对，不依赖开发者口头解释。
- 项目切换、刷新、返回和重复进入不会把旧项目状态带到当前项目。

### P0：状态、反馈和恢复可信

- 加载、空状态、错误、无权限、处理中、成功和失败有清楚且统一的文案。
- 所有可能改变数据的操作都显示正在进行、完成结果和失败后的下一步。
- 执行失败、应用失败、验收失败和基线过期保持不同含义，并提供可继续的动作。
- 删除、重试、应用和重新验收等高影响操作有明确确认和结果反馈。

### P1：界面和内容一致

- 默认中文，保留中英文切换；导航、按钮、状态、空状态、错误和帮助文字均通过同一套语言资源提供。
- 统一“资料、需求、决定、文档、迭代、任务、执行、验收、基线”等术语。
- 清理中英文混杂、内部字段名、调试信息和无法解释的 ID；必要的技术信息以可读标签呈现。
- Backup、Recently Deleted、Safety Backups 等安全能力说明“保存什么、何时产生、如何恢复、不会影响什么”。

### P1：工作台降低认知负担

- 项目详情页以“理解项目、确定范围、冻结计划、执行与验收”四阶段组织信息。
- 默认先展示当前状态和下一步，再展开历史、证据和高级操作。
- 对开放问题、冲突、待复核文档和过期基线提供稳定入口，不让用户靠浏览长页面寻找阻塞。
- 文档、需求和任务显示来源、版本和关联关系，用户能知道“为什么要做”和“做完如何判断”。

### P1：可交付与可维护

- 文档包、交接材料、执行结果和验收证据可以导出并在 Atlas 外阅读。
- 关键页面在常见窗口尺寸下可用，长内容、窄屏、返回和刷新不会破坏操作。
- 统一按钮、卡片、提示、表单和危险操作样式，减少页面之间的学习成本。
- 生产构建、类型检查、离线回归和核心浏览器路径形成可重复的发布检查。

### P2：细节优化

- 在不改变主线的前提下处理布局密度、动效、性能、bundle 大小和更深的资料展示。
- 只在真实使用中证明它能减少理解成本或等待成本后再纳入开发。

## 3. 完成定义

一次产品打磨项只有同时满足下面条件才算完成：

1. 用户可以从界面理解它解决的具体问题，不需要查看实现细节。
2. 正常路径、空状态和失败路径都有明确反馈。
3. 刷新、返回、切换项目或重新进入后，状态仍然正确。
4. 相关文案、术语和中英文版本已经同步。
5. 至少走过一次真实浏览器路径，并通过与该改动匹配的自动检查。
6. 文档记录了行为变化和仍然存在的限制。

## 4. 工作方式

每轮只选择一个用户可感知的打磨主题，先从真实页面找出断点，再完成页面、状态、文案和验证，不同时引入无关功能。阻断主路径、造成状态误导、破坏项目隔离或影响结果安全的问题优先级最高；纯指标优化和平台扩展排在后面。

当前已完成全局语言与反馈基础层、项目工作台首屏和下一步动作、业务页面文案、错误恢复说明、安全反馈及发布前检查。M5 三个核心案例和 Agent Harness 产品使用案例已按当前范围完成并封存；后续进入发布收口和独立后端演进决策。

## 6. 当前进度

第一轮基础层已完成：

- 中文默认和英文切换已在全局导航、首页和浏览页复验。
- 导航在窄屏下可横向滚动，语言切换按钮有明确的无障碍名称。
- 通用加载状态会跟随当前语言，并暴露 `status` 语义。
- 通用错误状态统一显示可理解的主提示，技术错误收进可展开详情，并提供刷新重试指引。
- 正式资料阅读器、首页搜索框和资料来源标题已接入统一文案。

第二轮工作台收口已完成：

- 项目工作台首屏显示四阶段位置、当前迭代、下一项动作和待处理事项；可直接跳转到对应阶段。
- 工作区基线异步检查完成前显示“正在检查工作区”，不把首屏暂态误报成正式阶段或下一步。
- 项目路径显示完成项数量，待处理事项为零时给出明确的完成状态。
- 没有活动迭代时区分“尚未建立”和“最近迭代已完成”，避免把历史完成状态显示成空白状态。

第三轮恢复反馈已开始：

- 通用错误页提供直接的“重新加载”按钮，技术细节仍可展开查看。
- 项目删除后显示结果提示，明确说明 Atlas 记录已删除、本地工作区和源码未受影响。
- 工作台中的生成模式、运行状态、任务类型、应用状态和验收状态按当前语言显示；内部 ID 继续保留为可展开或辅助核对信息。
- 需求、决定和关联文档列表增加数量摘要；有待确认或待复核内容时默认展开，已完成的长列表默认收起。
- 长列表的展开/收起选择会在数据刷新时保留，避免用户阅读过程中被页面更新打断。
- 顶部导航在窄屏下保持单行并支持横向滚动，避免菜单换行撑高固定高度的顶部栏。
- 草稿、项目列表和应用收藏的失败反馈不再直接暴露 `lint FAIL`、`ERROR`、`warn` 或原始异常字符串；默认中文文案保持一致，英文模式保留对应翻译。
- 草稿列表和详情页默认只显示可读的字符数、时间和状态；slug、引擎、门禁等内部值收进可展开技术信息，并把 `lint` 术语改为“正文检查”。
- 已把简单新想法试点提炼为已验证案例，并在教程中补充已有项目改进和多类型需求的待验证模板；案例状态与证据目录保持对应。
- 项目执行结果中的验收状态和输入指纹标签已按当前语言显示，减少内部字段名直接出现在用户界面中的情况。
- 项目工作台的执行、应用、生成和文档修订失败状态改用可恢复的中英文提示；HTTP 冲突、目标不存在和请求过期分别给出对应建议，原始技术信息收进可展开详情。
- 生成运行、开放项和文档版本中的内部 ID、会话 ID、输入指纹与版本标识默认收起；用户仍可查看执行器名称和按需展开技术信息。
- 版本历史与项目导出结果中的作者枚举、归档路径和哈希改为可读状态文案，技术值仅在展开详情后显示。
- 项目列表默认隐藏本地工作区绝对路径，只保留“工作区位置”折叠入口，降低项目卡片的信息噪声。
- 已记录决定和执行记录中的内部标识也默认收起，保留可读的决定内容、执行器和状态。
- 项目工作台的 Markdown 导出按钮补充只读范围说明，明确导出资料、需求、决定、文档和验收记录，不修改工作区或源代码。
- 项目工作区的“最近删除”“数据备份与恢复”和“恢复前安全快照”补充保存范围、创建时机、ID 冲突和替换影响说明；中英文文案保持同步，空状态也说明下一次快照何时产生。
- 分析运行、工作区基线、文件指纹与依据引用中的内部标识统一收进折叠技术详情，状态、数量、日期和可读内容保持直接可见。
- 类型叶子页的关联类型标识与正式资料版本指纹默认折叠；正文、关联名称、行数和字符数保持直接可见。

仍待完成的是少量历史页面和数据内容中的术语清理；长页面的信息分层和本轮发布前检查已经完成，已满足恢复 M5 的条件。

本轮发布前复验已完成：前端类型检查、生产构建、工作区静态脚本 `node --check`、后端 109 项回归和首页 → 浏览类型 → 类型叶子 → 项目创建入口的浏览器路径均通过；生产构建仍保留约 664 KB 主 JS 包的拆分优化提示，暂不阻断当前产品收口。
