# U17 M2 固定输入分析与文档生成验证

日期：2026-09-13  
状态：固定资料分析、依赖化文档集合生成、简化呈现及审阅后按序保存已完成；自然语言文档修改未完成。
依据：[产品设计](U17_DESIGN.md) · [开发规划](U17_DEVELOPMENT_PLAN.md) · [M2 基础闭环](U17_M2_FOUNDATION_VALIDATION.md)

## 1. 本阶段完成的能力

U17 现在可以从项目中已经固定的资料、需求、决定和文档版本建立不可变输入，调用 OpenCode 生成可审阅的分析或文档草案。Atlas 负责输入、状态、校验、版本与采用记录；OpenCode 只是首个可替换执行器。

- 分析模式输出关键问题、候选需求、明确冲突、参考建议和一份分析文档。候选需求逐条加入，始终只保存为 AI 推荐，不会获得用户确认。
- 文档模式只能读取用户已确认的本版需求。结果中的候选需求必须为空，避免在写文档时绕过范围确认。
- 用户可选择核心四件套、完整六件套或自定义文档集合。若某类型已有文档，结果必须指向已有文档作为新版本目标；没有同类文档时才允许新建。
- Atlas 要求每个选定类型恰好返回一份，并按 `调研分析 → 项目现状 → 产品需求 → 交互 → 技术方案 → 开发规划 → 验收方案` 的固定顺序整理结果。依赖关系由 Atlas 根据本轮实际选择计算，不接受模型自报顺序作为事实。
- 文档仍逐份审阅。下游必须等待本轮上游保存；保存时把上游实际产生的不可变 `dver_…` 加入依据，而不是引用同一生成结果中的临时文本或聊天上下文。
- 每个结果项目单独采用，未采用内容不会进入项目知识。重复采用同一项目会返回冲突。
- 已有人类编辑产生新版本后，基于旧版本生成的草案不能覆盖它。
- 最新一次完成的分析会进入“一致性信号”，分别统计明确冲突、待回答问题、未采用候选与参考建议；没有完成分析时继续显示“未检查”。

## 2. 固定输入与执行边界

每次运行建立独立目录，并保存以下文件：

| 文件 | 用途 |
|---|---|
| `input.json` | Atlas 校验用的规范输入和 SHA-256 指纹 |
| `input.md` | 提供给执行器完整阅读的等价可读输入 |
| `prompt.md` | 模式、输出契约和资料使用边界 |
| `run.json` | Atlas 拥有的运行状态、结果、采用记录和 OpenCode session ID |
| `engine/` | OpenCode 独立工作目录；只放本次输入、提示、配置和结果 |
| `engine.log` | 引擎原始事件，供失败排查和 session ID 提取 |

`input.json` 与 `input.md` 在执行前重新比对。任何固定内容或可读副本被修改都会使运行失败。长资料在 `input.md` 中分行呈现，避免 JSON 单行超过读取器可视上限；单次输入和结果分别限制为 500,000 字符与 2,000,000 字节。

OpenCode 配置只允许在独立工作目录内读取、写入、列举和搜索；拒绝 Bash、网络读取、网络搜索、外部目录、子任务和执行中提问。项目工作区路径不进入生成输入，也不作为 OpenCode 当前目录。

提示明确区分参考资料与项目规格：`Project note` 控制资料为何被引用；参考类型中的功能、示例和范围不能直接变成项目需求。候选必须用当前项目的产品语境表述，依赖未决问题的内容不能建议为本版。

## 3. 结果校验与有限容错

Atlas 要求固定的顶层结果结构，并验证输入指纹、模式、数量、文档类型、文档目标、作用域、文本长度和全部依据 ID。

- `ref_`、`req_`、`dec_`、`dver_` 只能引用本次固定输入中的对象；未知 ID 永远拒绝。
- 已知 ID 的类别若被模型误标，Atlas 只在该 ID 能唯一确定真实类别时修正标签。这是序列化修正，不会引入新依据。
- 嵌套对象的契约外字段会在持久化前丢弃；必填字段缺失、字段类型错误或正式依据字段含未知 ID 仍使整次运行失败。
- 更新已有文档时，目标文档自己的旧版本从上游依据中移除。v2→v3 的连续性由不可变版本链记录，旧版本不能成为使 v3 立即待复核的自依赖。
- 新版本采用使用运行开始时记录的 `current_version` 做乐观并发检查。
- 文档集合缺少任一目标、重复类型或包含未请求类型时整次运行失败。应用记录同时保存 `document_id` 和 `version_id`，供后续文档解析本轮真实上游。
- 依赖未满足时 API 返回冲突；即使绕过前端，也不能先写入下游文档。

## 4. API 与界面

新增接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/projects/<project-id>/generation-runs` | 列出运行和结果 |
| POST | `/api/projects/<project-id>/generation-runs` | 发起 `analysis` 或 `documents` 运行 |
| GET | `/api/projects/<project-id>/generation-runs/<run-id>` | 读取排队、执行、完成或失败状态 |
| POST | `/api/projects/<project-id>/generation-runs/<run-id>/apply` | 逐条采用候选需求或文档草案 |

本地 API 同时只执行一个项目文档任务；其它任务保持排队。API 进程中断后，无法恢复的 `queued/running` 记录会明确标为失败，不会把会话结束误判为完成。

项目页面的“资料分析与文档草案”区域显示 Atlas 运行 ID、固定输入指纹、执行器、模型和 OpenCode session ID。失败原因直接显示；完成后问题、冲突、建议、候选需求和文档正文分别呈现。文档集合提供核心四件套、完整六件套和自定义勾选，按钮文案区分“创建关联文档”和“保存为新版本”。

生成历史可切换查看，不再只能访问最新一次结果。简要视图折叠完整 Markdown，保留文档顺序、标题、依赖、待保存上游和采用动作；完整视图用于连续阅读。项目页顶部以六个步骤呈现“资料 → 需求 → 文档 → 迭代 → 执行 → 验收”，并提示当前建议动作。

## 5. 实际 OpenCode 与浏览器验证

使用临时项目库、实际 Vite/API 服务和 `opencode/big-pickle` 完成了多轮真实运行。迭代过程中保留失败结果，以验证安全边界而不是只记录成功样例。

### 5.1 固定资料分析

首次真实页面运行暴露两个问题：OpenCode 读取 `input.json` 的长单行时只看到前 2,000 字符；模型还把参考的任务管理类型直接当作项目规格。加入完整 `input.md`、完整性比对及“项目备注控制资料用途”规则后，最终运行结果为：

- Atlas run：`gen_974ee146b5914b4891306cfd1718bda7`
- OpenCode session：`ses_f66a01d7fffeyPXcrRR8sWFcXT`
- 5 个项目问题、6 条项目语境中的候选需求、1 个明确冲突、5 条建议、1 份分析文档
- 结果中不再出现 `2000`、`截断` 或 `truncated`
- 任务管理的快速捕获、同步、重复规则和模板没有再被当成本项目需求

页面正确显示 1 个冲突、5 个待回答问题和 11 个未处理建议（6 条未采用候选加 5 条参考建议）。分析文档经人工查看后保存为 AI 作者的关联文档 v1。

### 5.2 产品需求文档

文档模式的真实运行依次暴露并处理了四类执行器偏差：夹带候选需求、已有同类文档却请求新建、已知依据 ID 类别误标、问题对象附带契约外字段。前三者在当时均被后端拒绝，没有写入项目；随后分别通过更明确的模式约束、目标规则、唯一 ID 类别修正和契约字段投影解决。

最终运行结果为：

- Atlas run：`gen_1a8eb16d7b3b4d85b6b7c302b80c9236`
- OpenCode session：`ses_f66928596ffe28X3JuLhv7tN7c`
- 6 个问题、0 条候选需求、1 个明确冲突、5 条建议、1 份产品需求草案
- 草案目标为现有 `doc_673d046cba264899b91c2a96ccfd356a`，页面显示“保存为新版本”
- 保存后产品需求从人类作者 v2 进入 AI 作者 v3，没有创建平行的第二份产品需求

保存 v3 时发现模型把目标自己的 v2 列为上游依据，造成文档立即待复核。最终实现已在校验阶段移除此类自依赖，并加入离线回归；对上述真实 OpenCode `result.json` 重新执行最终校验后，目标自己的 v2 已移除，需求、固定资料和真正的上游分析文档依据仍保留。其它真正引用产品需求旧版本的分析文档继续按预期标记待复核。

## 6. 自动化验证

当前 Python 离线回归共 93 项通过。本阶段新增覆盖：

- 固定输入、可读 Markdown 完整性、长单行资料和输入篡改拒绝；
- 指纹、模式、证据归属、未知 ID 和结果结构校验；
- 分析候选逐条采用、AI 推荐与用户确认分离、重复采用拒绝；
- 文档模式只读取已确认本版需求，不能创建平行同类文档；
- 已知 ID 类别的唯一修正、契约外字段丢弃和未知依据继续拒绝；
- 目标文档旧版本自依赖移除；
- 人类在运行期间编辑文档时拒绝过期草案覆盖。
- 多文档目标缺失时拒绝整次结果，模型乱序输出按 Atlas 顺序归一；
- 依赖未满足时拒绝下游应用，上游保存后记录实际版本 ID；
- 下游文档依据包含本轮上游不可变版本，形成可复核的跨文档链。

前端 TypeScript 检查和生产构建通过。Vite 仍报告单个构建产物超过 500 kB 的既有体积提示，不影响本阶段行为验证。

## 7. 当前边界与下一步

- 关键问题在本阶段只呈现，尚未提供回答后自动重跑或局部更新。
- 文档支持完整 Markdown 人工编辑，尚未接入章节级自然语言修改。
- 运行尚无取消和断点续跑；OpenCode 子进程失败时保留 Atlas 失败记录与日志，用户可重新发起。
- 输出质量仍需人工审阅。Atlas 的校验保证来源、范围与版本边界，不能保证模型建议本身值得采用。
- 价值分析仍按需提供信息和建议，不自动否决项目。

下一步实现章节级与自然语言修改：用户指定目标章节和修改意图，Atlas 固定当前版本与依据，生成可比较候选；审阅后仍通过现有版本并发保护保存，并明确传播受影响的下游文档。
