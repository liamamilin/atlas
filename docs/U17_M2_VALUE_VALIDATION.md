# U17 M2-07 价值分析验证

日期：2026-09-13

## 产品边界

价值分析是独立、可选的 `value` 生成模式，输出 `value-analysis` 文档。它不加入默认开发文档包，不进入一致性信号，不创建或确认需求，也不设置分数、通过、否决或开发阻断状态。用户仍可继续资料分析、需求确认和文档工作。

报告固定分为七区：有依据的观察、用户与问题未知、现有替代、差异化假设、成本与风险信号、小型验证实验、建议摘要。每个实质段落必须用对应标记开头；`[Evidence: …]` 的 ID 必须存在于本轮固定输入。Atlas 还拒绝空依据建议、错误声称 pending 需求已确认、评分和开发裁决。

## 离线验证

`ProjectStoreTests.test_value_analysis_is_advisory_grounded_and_never_changes_scope` 覆盖：

- 合法报告保存为独立文档，保存前后需求记录完全一致；
- 伪造依据 ID、把 pending 需求说成已确认、产生候选需求、给出评分或“值得开发”结论时拒绝；
- 文档类型、章节顺序、逐段分类和固定资料依据由服务端校验，不依赖模型自觉。

完整回归为 95 个 Python 测试通过；TypeScript 类型检查和 Vite 生产构建通过。构建仍只有已有的单包大于 500 kB 提示。

## 真实 OpenCode 试点

执行后端：OpenCode 1.18.30，模型 `opencode-go/mimo-v2.5`。

严格化过程保留了模型局限的证据：早期结果曾引入未固定品牌、漏掉顶层建议依据、混淆 AI `recommended_scope` 与用户 `confirmed_scope`，或把建议放进有依据的观察区。Atlas 均未把最终不合格结果保存为项目文档。这些失败推动了逐段分类、依据 ID、需求状态和无裁决校验，未通过放宽规则掩盖问题。

## 浏览器验收

在隔离 API 和网页中打开该试点项目，实际确认：

- 页面有“评估想法价值（仅建议）”独立按钮和完整边界说明；
- 核心四件套与完整六件套均不包含价值分析；
- 生成历史显示 `value`、OpenCode 会话和“仅供参考，不改变范围”；
- 已保存价值分析显示为独立 v1 文档；
- 一致性信号仍为“未检查”，没有把价值建议当成正式范围分析；
- 没有需求时，开发文档和迭代仍按原规则等待用户确认，价值报告没有绕过门槛。

## 结论与限制

M2-07 的产品与安全闭环完成。OpenCode/Mimo 对长格式约束并非每次服从，因此失败是可预期状态；Atlas 会保留错误并要求重新生成，不自动采用不合格报告。报告的事实与建议分类是结构约束，内容质量仍需用户审阅。后续 M5 应记录严格校验首次通过率和重试成本，用于决定继续调整提示、加入受控修复轮次，或将这类边界明确的文档任务改用直接模型后端。
