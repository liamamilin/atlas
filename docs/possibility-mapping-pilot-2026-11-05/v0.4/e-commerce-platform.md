# B2C 电商商城 · 可能性图谱（v0.4）

## 可能性概览

| 期望状态：对象及可判别结果 | 对应期望变化：原情况 → 触发或条件 → 新结果 | 不满足陈述的近似情形 |
| --- | --- | --- |
| **商家能查询顾客在本商城提交的订单。** 例：顾客提交订单甲后，商家能打开订单甲。[A1][W4] | 原先商品站点不产生顾客订单；当站点接受结算并保存订单时，顾客购买成为商家可查询的订单。此处是交易能力的归纳。[A1][A2] | 商品页只有询价表单；表单记录不是订单。商家手工建立的订单也不能单独证明顾客可在店面提交订单。 |
| **设想：文章中的商品链接打开文章所介绍商品的购买页面。** 例：介绍杯甲的文章直接链接到杯甲商品页。[A1][A2] | 原文章没有杯甲入口；作者添加指向杯甲商品页的链接后，点击该入口可打开杯甲页面。这是导航关系设想，不宣称参考产品已验证此路径。 | 不相关商品广告不满足“对应商品”；只打开商城首页，也不能证明已直接指向杯甲。 |
| **商城的可售目录中含有可下载商品。** 例：电子书有售价，并配置用于交付的文件。[W1][W2] | 原目录仅有实物商品；商家发布配置了文件的电子书后，目录新增可购买的数字文件商品。 | 商品说明页附有免费使用手册，不等于目录增加了一项可购买的数字商品。 |
| **同一商家可为两个店面分别配置售价。** 例：店面甲和乙由商家 M 经营，各有价格配置；这是对多店面资料的归纳。[A2] | 原 M 只有店面甲的售价配置；M 增加店面乙的独立售价配置后，调价对象可以限定到乙。具体配置方式未核实。 | 两个网址都显示同一份不可分别设置的价格，不能证明店面价格可分别配置。 |
| **设想：商家能按销售来源区分汇入商城的订单。** 例：订单甲标明来自网店，乙标明来自线下。[A1][A2] | 原商城只保存网店订单；接收带来源标识的线下订单后，查询范围新增可辨认来源的线下成交。订单汇集机制未验证。 | 只提供线下门店地址不算；导入订单但丢失来源，也不满足按来源区分。 |
| **登录顾客能查看归属于其账号的历史订单。** 例：账号 U 的订单甲出现在 U 的订单历史中。[A1] | 原 U 的历史中没有订单甲；U 以该账号提交购买并形成订单后，其历史新增订单甲。这是账号与订单关系的归纳，不涉及旧游客订单补关联。 | 结算成功页面仅显示本次订单，不能单独证明账号历史可供以后查询。 |
| **相邻类型：平台商品可分别归独立卖家经营。** 例：商品甲归卖家 M，乙归入驻卖家 N。[A1][A2] | 原商品均由自营商家 M 经营；独立卖家 N 入驻并发布自有商品后，平台新增归 N 经营的商品。此处已越出单商家范围。 | 给 M 的员工开设第二个操作账号，没有引入另一个独立卖家。 |

## 期望状态

### 文章入口、店面与卖家归属分别描述什么

- **组合设想：文章入口指向同一商城中可下载商品的购买页面。** 正例是电子书介绍文章链接到该电子书商品页；反例是文章只链接到免费 PDF。这是前述两种可能性的组合设想，未验证某个产品的完整配置。[A1][A2][W1]
- **“只售实物”与“只售数字文件”是同一目录范围的替代取值。** 前者没有可下载商品，后者没有实物商品；同时含两类商品的目录属于兼售，不满足任一“只售”限定。该区分是概念归纳。[W1]
- **同一商城可以允许游客结算和账号结算两条身份路径。** 正例是订单甲以游客身份提交、订单乙归账号 U；只允许登录后购买的店铺不满足这项共存陈述。[A1]
- **两个店面不必对应两个独立卖家。** 正例是商家 M 经营中文与英文店面；两个卖家各自经营商品，则是另一种归属关系。不能从店面数量单独推断卖家数量。[A1][A2]
- **商家在外部市场销售，不等于商家运营该市场。** M 只在别人的市场发布自己的商品是正例；M 自行接受其他卖家入驻，才涉及平台经营者角色。角色区分为归纳。[A1][A2]
- **目录含数字商品，不代表某一订单已获下载资格。** 已发布电子书但订单尚待付款，就是反驳该推论的例子；授予资格的条件还需逐订单判断。[W1][W2]

### 一件商品或一笔订单可处于什么状态

以下是属性或结果的概念描述，不要求所有产品使用同名字段。

| 期望状态 | 成立例与不成立例 |
| --- | --- |
| **一个商品变体有可单独设置的售价。** [W2] | 例：蓝色 M 码与红色 M 码可分别定价；只有商品级统一价格，不能证明变体可单独定价。 |
| **订单的收款结果已确认为收到款项。** [A1][W3] | 例：网关确认订单甲收款成功；仅取得支付授权、仍待实际收款，不满足此陈述。 |
| **订单的实物交付仍被记录为未完成。** [A1][W3] | 例：商家仍需处理订单甲的实物履约；订单已被记录为实物履约完成，则不处于这一状态。付款是否确认是另一属性。 |
| **顾客已获得所购文件的下载资格。** [W1][W2] | 例：电子书订单已向该顾客开放文件；只看到商品预览不算。文件资格可另有次数或期限条件。 |
| **订单已记录为取消。** [W3] | 例：订单甲状态为 Cancelled；付款失败但未记录取消，不等于取消。 |
| **订单中已有一笔退款金额记录。** [W5] | 例：100 元订单中记有 20 元退款；只有退款申请、尚未记账，不满足。部分退款不等于全额退款。 |
| **支付网关已确认退款处理成功。** [W5] | 例：兼容网关返回退款成功并形成相应订单说明；仅执行手动退款记账，不能证明网关处理成功。此处不声称已核实顾客银行到账时间。 |

同一订单可以既已收款、又仍待实物交付。这两个属性可以分别判定。“商城含有可下载商品”描述目录范围。“订单甲已有文件资格”描述一次购买结果。二者不是互相替代的形态。[A1][W1][W3] 这些联系是归纳，不是统一订单字段的声明。

## 期望变化

### 商品售价与订单结果如何改变

概览已经列出整体形态变化。下面每行只追踪一种属性或结果；未列出的关联后果不由该行自动推出。

| 原情况与触发条件 | 改变后的属性或结果 | 不能当作同一变化的情况 |
| --- | --- | --- |
| 某变体售价为 100 元；商家将该变体售价保存为 120 元 | 该变体的售价变为 120 元。[W2] | 只修改商品说明中的文字，不算改动实际售价。既有订单如何处理改价，本轮未知。 |
| 顾客尚无本次正式订单；顾客提交结算且商城保存该购买 | 本次购买有可查询的正式订单。[A1][W4] | 提交前的临时 Draft 记录不能单独证明购买已提交。[W3] |
| 订单仍待付款确认；网关确认收到该订单款项 | 订单的收款结果变为已确认。[A1][W3] | 顾客只返回成功页面，尚不足以证明网关已确认。这一限制为归纳。 |
| 订单实物履约尚未记录完成；商家记录该订单实物履约完成 | 订单的实物履约记录变为完成。[W3] | 仅完成收款不算；记录完成也不证明物流签收或顾客满意。后两项不作等同推断。 |
| 顾客尚无所购文件资格；店铺采用付款确认后授予文件资格的规则，且本次付款已确认 | 该顾客获得对应文件资格。这是对数字交付的一种规则归纳。[W1][W2] | 免费预览不是所购文件资格；不把该规则推及全部服务或所有店铺配置。 |
| 订单未记录取消；管理员执行取消订单 | 订单记录为取消。[W3] | 支付失败并不自动等于管理员已经取消；取消也不能证明钱已退回。 |
| 某商品因该订单扣减 2 件；库存管理已启用；随后该订单取消，且没有其他库存变动 | WooCommerce 文档所述库存返还使该商品回补这 2 件；数量为判别用例。[W3] | 未启用库存管理，或该订单此前没有扣减这 2 件，不能据此断言回补 2 件。重复取消如何处理仍未知。 |
| 订单中没有该笔退款记录；商家手动记入 20 元退款 | 订单新增 20 元退款记录。[W5] | 只有退款请求不算记账；新增记录不能单独证明资金退回。 |
| 某笔退款尚无成功确认；支持自动退款的兼容网关确认该笔退款成功 | 该笔退款具有网关成功确认。[W5] | 直接把订单状态改为 Refunded，不能代替网关确认。 |

关于省略实物处理，本稿只引用 WooCommerce 中**订单所有商品均同时标为虚拟且可下载**的情形；还含实物项的订单不满足这个限定。[W3] 不据此判断其他服务是否已经交付。并发库存计算和自动超时取消的完整适用条件仍未逐项核实。
