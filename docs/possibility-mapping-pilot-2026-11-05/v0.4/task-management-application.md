## 可能性概览

| 期望状态：对象及可判别结果 | 对应期望变化：原情况 → 触发或条件 → 新结果 | 不满足陈述的近似情形 |
| --- | --- | --- |
| **用户可在一个筛选视图查看带同一标签的未完成任务。** 例：不同清单中带“采购”标签的待办被一起列出。[A1][A2] | 原任务甲不带“采购”标签；用户加上该标签后，甲进入按该标签筛选的未完成集合。此处为筛选关系的归纳。 | 只修改清单名称、没有改变任务标签，不是该变化；只逐个翻阅清单也不能证明跨清单筛选。 |
| **FlowWeek 中归属周五的任务可在周视图的周五列查看。** 例：任务甲所属日为周五，周五列列出甲；依据 README 的任务日期与周视图描述。[P1] | 原甲归属周五；用户将甲改到周一后，周视图的周一列列出甲。此处追踪任务所属日，不将其推广为所有工具的截止日期语义。 | 只在任务标题中输入“周一”，但未改变任务所属日，不是这项日期变化。 |
| **本次重复事项完成后，下一次待办仍可查看。** 例：按固定周周期、在周一完成本周事项后，下一次日期为下周一。[T3][V1] | 原显示本周待办；重复规则仍有效且用户完成本次后，软件按该规则确定可查看的下一次日期。 | 用户手工复制一份任务，不证明软件按重复规则生成了下一次；只发提醒也不等于形成下一次待办。 |
| **TickTick 用户可在记录任务的同一应用内启动专注计时（研究笔记描述）。** 例：应用中的专注计时器由未启动变为计时中；组合依据为 TickTick 研究记录。[A1][A2] | 原同一应用内的计时器未启动；用户启动该计时器后，它进入计时中。此处是文档能力的归纳，未核验界面数值。 | 另开一个独立时钟应用计时，不满足“同一应用”；任务被勾选完成也不证明计时已启动。 |
| **文档归纳：Microsoft To Do 的标记邮件列表中有源自已标记邮件的待办项。** 例：列表项指向邮件甲；依据为仓库研究记录。[A2] | 连接行为设想：原列表没有邮件甲对应项；在已连接账号中标记甲后，列表新增甲对应项。完整账户适用条件未核实，不写成任意邮箱都成立的产品保证。 | 手工复制邮件文字为任务，不证明标记邮件连接生效；给任意邮箱加星标也不能据此断言会进入 To Do。 |
| **FlowWeek 用户断网后仍可保存一项新任务（README 描述）。** 例：FlowWeek 文档描述离线工作和本地存储，按此描述新任务可保存于本机。[P1] | 原本机没有任务甲；断网时用户提交甲后，本机保存甲。这是依据 README 的预期行为，未运行验证。 | 只能阅读缓存列表、不能保存新任务，不满足离线保存这一陈述。 |
| **文档归纳：同一账号的两台设备在同步完成后显示同一任务的已保存标题。** 例：手机把甲的标题由 A 改为 B，电脑随后可见 B；为跨设备同步的归纳。[A1][A2] | 原两端同一任务标题为 A；手机保存 B，且该修改同步完成后，电脑端标题变为 B。具体冲突与同步时机未验证。 | 一次性导出副本仍显示 A，不算同一任务的修改已同步；离线本地保存也不能单独证明另一端收到修改。 |
| **受限清单可供已加入的受邀成员查看。** 例：原仅 A 能访问的清单 L，成员 B 加入后可打开 L。[A1][T2] | 原 B 不是 L 的成员且不能访问；A 邀请 B、B 成为成员后，B 可访问 L。此处限定受限共享清单。 | B 只收到普通文字副本，不算获得 L 的访问权；公开清单不属于这个受限共享例子。 |

## 期望状态

### 标签筛选、日期视图与任务完成分别表达什么

- **同一任务可以既带“采购”标签，又安排在周五。** 正例是任务甲同时出现在采购筛选与周五视图；反例是两个同名但独立的任务各满足一项，不能证明同一任务具有两属性。此处为组合归纳。[A1][A2]
- **列表与看板可以是同一任务集合的替代布局。** 正例是切换布局后仍查看原任务；若移动卡片实际改了任务日期或分区，则还发生了属性变化，不能只算切换布局。[A1][A2]
- **Todoist 的 every week 与 every! week 可计算出不同的下一次日期。** 例：两项任务均在本周一到期并于周二完成，前者下一次为下周一，后者为下周二。若都在周一完成，两种结果可以相同；仅观察一次相同日期不能证明规则相同。[T3]
- **组合设想：另一设备可见本机离线期间保存的任务修改（联网同步后）。** 正例设想是手机离线保存甲，联网后将甲传到电脑；只能本地保存、不能传出修改的产品不满足这个组合。此处仅是组合设想，不把 FlowWeek 声称为该组合的实现。[A1][A2][P1]
- **任务的完成标记与专注计时器的运行状态可以分别判定。** 正例是任务未完成而计时正在进行；一次计时结束不能单独证明任务已完成。这是语义归纳，未断言具体产品自动联动。[A1][A2]
- **私人清单与共享清单可以存在于同一账号中。** 正例是 A 的清单 L 只供自己访问、清单 K 向 B 分享；若两份都公开，就不能用作私人和共享共存的例子。[A1][T2]
- **相邻类型：一个项目可以有独立于任务列表的交付计划。** 正例是项目有自身的计划范围及据此调整工作的记录；仅将清单命名为“项目”不算。该边界来自 ATLAS 的项目管理区分，不将其当作个人任务工具的默认能力。[A1][A2]

### 一项任务可被判定为何种状态

| 期望状态 | 成立例与不成立例 |
| --- | --- |
| **一项已保存任务尚未设置日期。** [T1] | 例：任务甲能被重新打开，但日期为空；只在输入框写了文字而未保存，不算已保存任务。 |
| **到期日期早于今天的未完成任务被列为逾期。** [A1][V1] | 例：甲昨天到期，今天仍未完成；明天才到期不满足，已经完成的历史任务也不是此处的未完成逾期任务。 |
| **任务被列入 My Day。** [M1] | 例：用户将甲加入 My Day 后，该列表可见甲；甲仅在今天到期，不能单凭日期证明用户已将它加入 My Day。 |
| **Vikunja 中设置提醒的用户已收到该任务的应用内通知。**[V1] | 例：用户 U 的应用内通知中出现任务甲的提醒；只有未来提醒设置、尚未触发，不算已通知。通知出现不证明 U 已阅读。 |
| **普通任务的完成标记为已完成。** [T1] | 例：用户完成甲后其完成标记改变；仅删除甲使列表不再显示它，不能证明甲已完成。 |
| **共享任务的被指派人为 B。** [A1][T2] | 例：任务甲的指派记录指向成员 B；B 只是清单成员、甲没有指派人，不满足。指派记录不证明 B 已接受工作。 |

Vikunja 区分截止日期与计划开始、结束日期。[V1] 例如截止日为月底、计划处理日在本周的任务，不必把两个日期设为同一天；此例说明日期含义区别，不声称所有任务工具都有相同字段。

## 期望变化

### 任务、提醒与每日视图如何改变

概览已列出标签、安排日期、重复、计时、邮件入口、存储和共享的变化；下表只展开其他需要明确前后差异的操作。

| 原情况与触发条件 | 改变后的属性或结果 | 不能当作同一变化的情况 |
| --- | --- | --- |
| 原无任务甲；用户提交标题非空的新任务，未设置日期 | 新增一项未设置日期的任务甲。[T1] | 输入文字但未提交，不算已形成任务。自然语言解析出的日期还须与用户意图区分。 |
| 甲未完成且尚未到期；应用所采用的今天已晚于甲的到期日期 | 甲由未逾期变为逾期。这是日期与完成状态的归纳。[A1][V1] | 只因用户改了优先级，不是跨过到期日期；逾期也不等于完成失败判定。 |
| My Day 中有未完成任务甲；该列表发生每晚重置，且用户尚未在新一日再次选入甲 | 甲不在新一日的 My Day 中。[M1] | 这不是删除甲；Microsoft 说明未完成事项仍保存在任务列表并可成为次日建议。 |
| 用户 U 在 Vikunja 为任务甲设定截止前一小时提醒，截止时刻为周五 18:00；应用所用时间达到周五 17:00 | U 收到甲的应用内提醒通知。[V1] | 未设置对应截止日期，不能计算这个相对提醒；不从触发通知推出 U 已阅读。例中时间只是判别用配置。 |
| 普通任务甲未完成；用户执行完成操作 | 甲的完成标记变为已完成。[T1] | 只结束专注计时，不等于执行了完成操作。 |
| 普通任务甲已完成；产品允许该任务撤销完成，且用户执行撤销 | 甲的完成标记恢复为未完成。[T1] | Todoist 的历史重复次数不能一概按普通任务撤销；本行不适用于那些不允许撤销的次数。 |
| Todoist 中父任务已完成；用户取消其某个子任务的完成 | 父任务随之恢复未完成。[T1] | 只编辑子任务标题不是取消完成；不把此级联规则推广到所有工具。 |
| Todoist 中任务甲仍存在于项目；用户确认删除甲 | 甲从该项目的任务记录中删除。[T1] | 标记完成后隐藏在活动列表之外，不等于删除；已完成任务仍可按产品功能查看。 |
| 共享任务甲尚未指派；有权操作的参与者将甲指派给成员 B | 甲的被指派人变为 B。[A1][T2] | 只把 B 加入清单，没有将甲指派给 B，不是这项变化。 |

Todoist 帮助描述把重复任务移到下一日期。[T3] Vikunja 帮助描述创建下一次事项。[V1] 因而本文的“下一次待办”不规定必须新建记录或复用原记录。仅手工复制任务不属于这里的规则触发。归档对容器内任务的影响、删除恢复条件、停止未来重复对历史次数的影响，本轮没有统一证据，不给出跨产品的统一转换。
