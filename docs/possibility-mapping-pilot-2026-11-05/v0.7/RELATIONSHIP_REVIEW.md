依据技能 `4b6ecb3`，先保留并复核[主要领域](COVERAGE.md)和逐条表达，再为[图谱](e-commerce-platform.md)增加“小林买两本书”的关联情境。关系解释只连接期望状态与期望变化，不增加第三个核心概念。

## 本轮改变了什么

v0.6 的 46 对局部及整体状态、对应变化保持原文；其[逐条理解与反例记录](../v0.6/READABILITY_REVIEW.md)继续适用，本轮检查了每对内容的对应关系。正文原来的六条关系提示改为一笔交易的前后变化，而非再追加一张关系名称清单。逐行对应和文件校验见 [INPUTS.json](INPUTS.json)。数量仅用于查漏。

同一交易的付款、库存、发货、退货和退款，采用 Adobe Commerce 文档。纸书兼售文件、第二网站和多卖家边界是同一家书店的能力变化归纳，明确放在对照段落；没有把 PrestaShop 的店面关系或 WooCommerce 的 Processing、下载开关拼成 Adobe Commerce 的运行规则。

## 关联认知检查：每种联系都回到同一情境

一项结果不能代替另一项证据，同时仍可能有前提约束。例如已付款不能证明已发货，发货仍需满足本例的销售单据前提。这种检查不声称任意状态组合都可发生。

| 正文中的联系 | 对象与条件 | 改变的结果 | 没有因此改变或不能推出的结果 |
| --- | --- | --- | --- |
| 独立结果：实际收款后仍未发出一本 | 同一订单甲已扣收 100 元，并有已付款单据；尚无发货事件。 | 收款记录与单据成立。 | 仓库仍 10、占用仍 2、可售仍 8；不能由钱已收推出书已寄出或顾客已收到。 |
| 条件依赖：发货先有相应销售单据 | 采用文档描述的 Adobe Commerce 实物流程。 | 单据具备后，商家才在本例记录分批发货。 | 单据或付款本身不自动形成发货；不把这一情境写成所有店铺必须先付款的普遍规则。 |
| 共同影响：付款前取消订单甲 | 从提交后、无已付款单据及实际收款的同一节点分出。 | 订单改取消；抵消 2 本占用，可售恢复 10。 | 仓库记录始终 10；没有实际收款便没有本例的成功退款。取消分支不再继续走主线。 |
| 共同影响：发出第一本 | 仓库原 10、本订单占用 2、可售 8；本例无其他变化。 | 仓库 10→9；尚未发的占用 2→1。 | 可售仍 8，收款仍 100；不能把可售再减一次，也不能把第一批当整单交付。 |
| 独立结果：申请、许可、收到包裹 | 实际收货后，本例订单已记 Complete，纸书已开放退货。 | 依次形成待处理申请、许可、退件收到记录。 | 没有各自证据前，不推出钱已退、书已重新可售；原购买历史仍在。 |
| 条件依赖及结果区分：退款与加回库存 | 原付款达到服务退款条件；支付方式支持在线退；自动加回关闭。 | 退款单据记录 50；情境另给定服务退款成功。明确选择加回 1 本时，仓库及可售 8→9。 | 单据不等于外部资金已退；未选择加回且自动加回关闭时，可售仍 8；不保证各处同时成功。 |
| 组合与边界：同一家书店增加电子版或第二网站 | 同一商家继续经营商品；具名产品的不同规则分别保留。 | 商城可组合纸书、文件及不同网站的展示范围。 | 纸书发出不证明文件已授权；两网站不等于两卖家；纸书 RMA 不自动涵盖下载品。 |
| 组合与边界：其他独立书店入驻 | 商品与收入分别属于各卖家，平台增加分配款项的关系。 | 研究中心跨向多卖家市场。 | 不能只因自营店多开网站，就宣称已具备这种卖家关系。 |

## 关键段落逐项复读

| 段落 | 语言与证据检查 |
| --- | --- |
| 起点与条件 | 只有同款纸书、一个仓库、一个订单；10 本、2 本、50 元、无其他占用及进出货均明示。自动加回关闭、不能零库存接单也已明示。 |
| 扣款许可与实际收款 | 把银行卡允许之后扣款解释为支付授权；没有把授权金额当成已扣收金额。取消分支也没有据此声称银行卡授权已撤回。 |
| 取消分支与主线 | 分支起点相同；前者取消后终止，主线选择未取消，不出现一笔订单取消后仍被当正常订单发货的跳跃。 |
| 已付款单据与发货前提 | 文档中先有销售单据的条件保留；未把“Invoice 存在”一概当资金成功证据，主例另外给定实际扣收成功。 |
| 分批发货与数量表 | 仓库登记数和未完成占用同步减少；可售保持 8。表格统计的是软件登记数量，不声称库存账等于任何时刻盘点实物。 |
| 顾客收到两本 | 明确是后续给定事实，不由“已发”标签推断；不把未研究签收机制算作已覆盖。 |
| 退货申请与许可、接收 | 顾客选择退 1 本；保留订单完成及开放退货的条件。申请、许可、接收各自成立，未用客服或退款标签代替。 |
| 收到退件后尚未重新可售 | 本例在明确加回前暂不将退件计入可售记录；没有说退款失败、质量不合格等所有情况均采用这一策略。 |
| 退款前提与成功证据 | 已读资料要求在线退款前原交易已结算。本例表述为扣款后的必要处理阶段已完成、服务允许退款；未承诺统一时长。服务成功为构造情境的额外事实，未指定网关回执协议或验证实际产品。 |
| 退款金额与库存加回 | 原金额 100、退 50；库存多 1 来自单独加回选择。反例保留“自动加回关闭”，避免未勾选就必定不加回的错误。 |
| 同书店的能力组合 | 仍从同一家书店出发；兼售文件不自动得到下载资格，多网站不自动产生其他卖家的商品与收入。边界判断明确为归纳。 |
| 可迁移认识 | 用当前结果不足以判定其他结果的方式归纳；不要求把每个条目连接，也未改为按钮清单、SOP 或架构图。 |

## 用新情形检查是否理解

以下题目可供后续真实读者独立回答。**本轮没有收集答题结果；参考答案是作者依据文档和声明条件的推导。**

| 新情形 | 作者参考答案与判别依据 |
| --- | --- |
| 小林已付 100 元，但没有发货记录，能说两本已经寄出吗？ | 不能。确认付款只给出钱款结果，还需发货依据；也不能据此判断银行最终到账。 |
| 同样从 10 本起，小林改买 3 本，先发 1 本，其余条件不变，可售该是多少？ | 下单后可售 7；发第一本后仓库 9、仍占用 2，可售仍 7。不能再减到 6。 |
| 取消分支之后，能说“已经退回 100 元”吗？ | 不能。本分支未实际扣收款项；订单取消和占用抵消不证明有成功退款。 |
| 仓库收到了退回一本的包裹，能马上把“退款成功 50、可售 9”都写上吗？ | 不能。收到证明实物接收；还缺本例要求的退款成功和明确加回可售记录的依据。 |
| 只看到一张金额 50 元的退款单据，能认定原付款渠道已退 50 元吗？ | 不能。单据列应退金额；在线服务结果或实际线下返款需另有依据。 |
| 把“自动加回”改成开启，只因这次没有手动选择加回，能断言可售仍 8 吗？ | 不能照搬关闭时的反例。按该文档的自动设置、且本例其他条件相同，应加回 1 本、可售变为 9；不能只看手动选择。 |
| 同一家书店又经营一个网站，是否已经是多卖家市场？ | 网站数不足以作此判断；还要看是否有独立卖家的商品、收入和平台分配关系。 |
| 纸书已寄出，是否意味着同单电子书也已获准下载？ | 不能据此推出。要看文件授权的具体产品和设置；本例未拼接另一产品的开关。 |
