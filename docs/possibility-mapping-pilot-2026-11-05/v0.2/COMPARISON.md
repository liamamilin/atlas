# 可能性图谱 v0.1 / v0.2 · 两案例比较

**本轮判断：两份 v0.2 在文本所呈现的认知空间上都有扩展，主要收益是补出了整体能力的组合与变化条件。电商的新增覆盖更明显；任务管理有较多旧内容被重新组织，不能把它们全部计为新增。** 局部状态的关键区别仍然保留。

这个判断来自作者逐段核对，不是用户理解测验或对技能效果的因果证明。两份新稿均待人工内容审查。

比较关心四件事：读者能否认识不同整体形态；能否解释它们形成、组合和维持的条件；能否把整体能力落到重要对象关系；是否仍能区分事实、推断和相邻类型。条目数、文档长度和小标题数量不作为认知增益的证据。原本已经表达清楚的内容，只能算保留或重组。

## 电商：从单笔交易的状态，扩展到同一经营的多种组织方式

| 要回答的认识问题 | v0.1 实际覆盖 | v0.2 的对应内容与增量判断 |
| --- | --- | --- |
| 同一类商城能形成哪些经营组合？ | S01 说明完整自有商城及不同承载方式；S07 说明数字交付，整体可能形态没有单独展开 | F01–F06 先说明完整经营、内容与交易、混合交付、多店面、多渠道、持续客户关系，再说明可组合。新增的是组合关系，不能把“完整商城”或“数字商品”说成首次出现 |
| 实物与数字商品放在一起，改变的是什么？ | S02、S07、C07 已有数字资格、虚拟与可下载区别 | F03、G02、L04 解释同一经营中不同商品的交付义务，以及某项交付不能代表全体交付。属于已有题目的机制深化；分项交付与权限撤销仍有未验证处 |
| 多个店面、多个销售渠道、多个卖家有什么不同？ | S01 有不同部署方式；末尾将多卖家放在范围外，没有展开多店面与渠道关系 | F04、F05、R01 与 G03、G04、G07 分别按经营归属、受众入口、销售来源及独立卖家关系说明。多店面和渠道是叶子内的新增认识；多卖家只算边界说明 |
| 商城是否只能围绕一次游客购买？ | S04 保留这次订单的联系信息和记录，未展开跨访问的客户关系 | F06、G05、L06 说明游客路径与账号历史可以并存，持续服务依赖购买与客户的正确关联。属于新增覆盖，旧客补关联和跨店身份合并仍未验证 |
| 形态出现后，怎样理解它的维持和缩减？ | C02 已解释商品条件更新和既有订单不是一回事 | G04、G06 把条件更新放到多个入口与交付形态中，并解释关闭渠道不抹去原交易责任。这是关系推断带来的扩展，不是跨渠道产品机制已经验证 |
| 跨到相邻产品后，是否被算作商城内部更丰富？ | 末尾有范围排除 | R01、G07 正面解释单商家到独立卖家的角色与经济关系变化，并明确不算入单商家内部增益。边界表达改善，题目范围没有随之扩成所有电商软件 |

**一个可以由新稿回答得更完整的问题**：同一品牌在不同受众店面同时售卖电子书与实物，又有外部销售渠道时，为什么不能用一条“待付款—已发货—完成”的流程解释全部经营？新稿可以分别从店面关联、销售来源、商品交付义务及订单持续性解释；旧稿主要回答每笔购买的内部区别。

上述组合只是基于既有资料的认知推断，未证明某款参考产品在一个已运行部署中完整实现了这一组合。

## 任务管理：从单项操作的连续性，扩展到多种个人工作形态

| 要回答的认识问题 | v0.1 实际覆盖 | v0.2 的对应内容与增量判断 |
| --- | --- | --- |
| 个人可以围绕任务形成哪些完整工作方式？ | S01–S04 已有记录、组织、日期与关注视图；没有缺少这些基础认识 | F01、F02 将它们组织为按上下文行动与按时间安排的整体形态。主要是表达和组合改善，不把基本任务管理重新记作新增 |
| 周期事务是否只是反复出现的通知？ | S07、S08、C06、C09 已充分区分重复规则、提醒和下一次 | F03、G03 把它提升为持续管理的时间跨度；L03、L04、C03、C04 保留原区别。主要是已有内容的整合，不是新发现了重复能力 |
| 与日历、专注计时和习惯放在一起，会得到什么形态？ | C03 说明任务改期不必生成日历事件，没有展开整体工具组合 | F04、G04 正面认识任务为中心的组合，并区分任务、会话、习惯结果。属于新增关系；来源是旧资料中的 TickTick 观察，精细联动为推断 |

| 本机独立工作与跨设备延续是什么关系？ | C12 已有离线、本地保存，也已指出不能推出同步或恢复 | F06、G06 把本地和跨设备作为可认识的不同形态，并说明连续性需要额外关系。新增了对照和扩展条件，不能把离线本身算作新能力，亦未验证迁移可行性 |
| 私人任务和共同待办如何共存？ | S10、C11 已有私人容器、共享、指派与完成区别 | F07、G07、L06 继续解释选择性共享及维持私人范围。主要保留并结构化旧内容；R01、G08 的团队流程延伸只算边界，不计入个人范围增益 |

**一个可以由新稿回答得更完整的问题**：来自邮件的事项按周安排，再搭配专注工具，为什么不能把“邮件处理完、计时结束、任务完成”看成同一件事？新稿可以说明整体组合中的来源、时间、会话和完成关系；旧稿虽有外部捕获和改期，却未把这些关系放在一起解释。

这并不证明参考产品具有自动关联上述全部对象的机制。新稿的价值在于让这种关系问题变得可见，同时明确还有哪些未验证。

## 可以得出什么，尚不能得出什么

**可支持的结论**：在这两个样本中，v0.2 的输出覆盖了更多整体关系和能力变化，而没有只增加状态码或罗列产品名称。电商增加的多店面、渠道、客户连续性较清楚；任务管理增加的内容更集中于工具组合及嵌入式入口。旧稿已有的数字交付、重复、共享、离线应得到保留与深化的评价，不能重复计作全部新增。

**效力边界**：两次由同一作者在同一对话中生成，作者看过旧稿和技能差异；新稿更长，也花了额外时间重新审视同一资料中的整体形态段落。来源集合未变，仍不等于严格控制了注意力、长度和生成过程。因此不能据此证明“技能修改单独造成了增益”，不能推算理解提升百分比，也不能推广为所有 ATLAS 叶子已经验证有效。

**尚未验证**：读者能否更准确地产生不同构想、解释能力组合和边界，或者在实际工作中作出更好判断，本轮没有用户测验或产品运行证据。两个版本均仍是认知文稿。本轮未接入网页、未扩大批量生产，也未改动分类；这些属于本次验证范围的事实记录。
