# 个人任务管理软件 · 可能性图谱

对应 ATLAS 叶子：**Task Management Application**，标识 `task-management-application`，分类 `03.06`。本文聚焦个人组织工作与生活任务，沿用现有叶子；轻量共享仅作为可选扩展。生成日期：2026-11-05；状态：人工审查试点草稿。

这类软件帮助人把需要做的事保留下来，组织成能行动的集合，并持续辨认什么已做、什么仍待处理。以下状态可以组合：一项任务能够同时属于某个清单、有截止日期、出现在今日视图并处于未完成状态。日期标签、视图归属与完成状态不应被混成一条必经流程，这是对 ATLAS 对象关系的**综合归纳**。[A1]

## 期望状态

### S01 · 一件要做的事已成为可再次找到的独立任务

用户不必继续靠记忆保存它。任务有可以辨认的内容，可以附带说明或资料，即使尚未安排时间、优先级和归属，也能够作为未完成事项存在。捕获一件事与承诺什么时候做，是两个可以分开的结果。[A1][T1]

### S02 · 任务集合已经组织到适合理解和行动的粒度

相关任务能够按清单、项目容器、分区或标签聚合；较大的事项能够分解为可分别处理的子任务。用户可以辨认每件事属于什么、下一步是什么。这里的“项目”可以只是组织容器，不必因此具备项目预算、交付计划和整体进度审批。[A1][A2][T2]

### S03 · 任务有可解释的时间安排，未安排的任务也有位置

用户能够区分没有日期、计划在某日处理、必须在某时前完成以及有提醒的任务。这些含义可在具体产品中由不同字段承担。Vikunja 将截止日期与计划开始、结束日期分开；不能据此假定每个个人任务工具都有三种日期。[V1]

### S04 · 当前需要关注的任务可从合适的视图中找到

用户能够从今日、未来安排、标签或筛选视图理解眼下的工作，而无需逐个翻阅全部容器。视图可以基于日期计算，也可以容纳用户主动选择的每日重点。Microsoft To Do 的 My Day 支持主动加入，因此“出现在今日视图”不总意味着“今天到期”。[A1][M1]

### S05 · 时间已经过去，但未做完的任务仍被明确保留

有截止日期而尚未完成的任务可以被识别为逾期；用户仍可完成、改期或决定不再处理它。跨过日期本身不证明工作失败，更不会自动证明工作已经完成。逾期是时间与未完成事实组合得到的结果。[A1][V1]

### S06 · 完成的事项与仍待处理的事项已经分开

用户标记完成后，任务不再混在普通待办中；支持历史的产品还可回查完成事项。允许撤销完成的产品，能够把误勾选的普通任务恢复为未完成。任务被勾选完成记录的是用户作出的完成判断，本身不等于第三方验收已经发生。[A1][T1] 最后一项是**语义边界判断**。

### S07 · 周期性事务能够继续出现，并有可解释的下一次安排

完成这一次，不意味着以后不再需要做。重复规则使下一次可处理事项得到日期；按固定节奏重复与按实际完成日再间隔一段时间，会得到不同结果。它可以表现为原任务移到下一日期，或产生下一次事项，不宜强行把某一种实现当作定义。[T3][V1]

### S08 · 任务在需要时重新引起注意，提醒与完成仍可区分

用户可以给任务设置提醒，使它在指定时刻或相对日期临近时发出提示。提示已经触发，并不证明用户已经看见，更不证明事项已完成。相对提醒依赖相应的任务日期；例如没有截止日期时，基于截止日期的提前提醒没有计算依据。[V1] 对提示、知晓与完成的区分是**综合判断**。

### S09 · 不再需要行动的事项有合适的退出方式

做完、删除误建任务、停用重复安排或归档已结束的容器，表达的是不同结果。用户应能理解退出之后还有没有任务或历史可找，以及重复事务是否会继续。这是对任务和容器操作的**综合归纳**；删除恢复能力和归档规则随产品而异，不能承诺通用回收站。[A1][T1][T2]

### S10 · 个人安排可以在需要时延伸为有边界的共同待办

在支持共享的产品中，用户可以保留私人容器，也可以把特定容器分享给他人，让相关任务的归属和完成变化可见。共享与指派是可选能力，不是个人任务管理成立的必要条件；也不能把“指派给某人”直接理解为对方已接受或已完成工作。[A1][T2] 后一项是**综合判断**。

## 期望变化

### C01 · 意图被记录，成为可继续处理的任务

**关联：S01、S03。** 触发来自用户输入、快捷捕获或产品支持的外部入口。内容保存后形成任务；自然语言识别若提取了日期，时间属性也随之形成。识别出的日期是否符合原意仍需区分，不能把解析成功自动解释为排程合理。[A1][T1] 后一句是**综合判断**。

### C02 · 整理或分解改变任务的上下文和行动粒度

**关联：S01、S02、S04。** 移入清单、调整分区、增加标签或拆出子任务，会改变任务如何被组织、筛选和理解，而不必改变它是否完成。切换列表与看板布局也可能只是换一种观看方式。父子任务的完成联动须单独确认，不能从层级关系推导出所有产品必然采用相同级联规则。[A1][A2]

### C03 · 安排日期或改期，改变任务何时进入关注范围

**关联：S03、S04、S05。** 用户增加、移除或调整日期后，相关日历与筛选结果随属性重算。原本逾期的任务被移到未来，可以不再显示逾期，但工作仍未完成。拖动任务到另一日期可能就是改期；它不一定意味着创建了日历事件或保证为这项工作留出了可用时间。[A1][P1] 最后的日历区分是**综合判断**。

### C04 · 时间推进，使同一项未完成任务变得临近、到期或逾期

**关联：S03、S04、S05。** 即使用户没有编辑任务，当前日期越过它的截止日期，也会改变紧迫性及相应视图中的呈现。必要条件是存在可解释的截止日期且尚未完成。跨设备时区、只有日期与精确时刻的区别，会影响具体判定；本轮未验证各产品全部边界。[A1][V1]

### C05 · 每日重点更新，改变今天的工作集合

**关联：S01、S04、S05。** 用户主动把任务纳入每日重点，或日期规则使任务进入今日范围，都能形成今天的关注集合，但二者触发不同。Microsoft To Do 的 My Day 每晚重置，尚未完成的任务仍保留并可成为次日建议；它退出某天的焦点，不等于任务被删除或完成。不能把这一产品规则推广到所有 Today 视图。[M1]

### C06 · 提醒条件满足，形成一次提示

**关联：S03、S08。** 对设定了提醒的任务，到达绝对时间或满足相对时间条件，会触发产品支持的通知。Vikunja 的相对提醒要求相应日期存在；邮件通知还受邮件设置影响。任务的行动状态不因发出提示自动变成完成。设备离线、投递失败与实际阅读如何处理，本轮没有足够依据给出统一规则。[V1]

### C07 · 用户确认完成，使这项工作退出当前未完成集合

**关联：S02、S04、S06。** 用户执行完成动作后，该任务的完成事实变化，并影响引用它的列表、筛选与历史呈现。普通任务的完成与重复任务本次完成要分开理解。若有子任务，产品还可能施加联动；例如 Todoist 取消子任务的完成会连带取消父任务完成，这只是一个具体产品规则。[A1][T1]

### C08 · 误完成被撤销，原任务重新成为待办

**关联：S04、S05、S06。** 在允许撤销的条件下，用户重新打开已完成任务，它按现有日期和其他属性回到相应视图；若原日期已过，重新出现时仍可能逾期。后一结果是从属性与完成事实组合得到的**推断**。Todoist 的历史重复事项撤销存在限制，不能把普通任务的可逆性套用于所有重复次数。[T1]

### C09 · 本次周期工作完成，按规则确定下一次

**关联：S03、S06、S07。** 完成当前重复事项后，重复规则决定下一次日期或事项。例如 Todoist 的 `every` 以任务日期为基准，`every!` 以实际完成日为基准；固定每周一与完成一周后再做，可能产生不同安排。[T3]

Vikunja 的当前帮助则描述为完成后创建下一次事项。因此共通结果是周期事务得以继续，不能一律写成“每次都新建独立任务”，也不能一律写成“同一个任务只有日期变化”。漏做补齐、系列结束和历史撤销的完整规则仍需分别核对。[V1]

### C10 · 计划被放弃或容器结束，任务退出活跃工作范围

**关联：S01、S02、S07、S09。** 用户删除误建或不再相关的事项、调整重复规则，或在支持的产品中归档容器，会改变哪些事项还需要行动、还能从哪里找到。删除不等同于完成，停止未来重复也不等同于撤销已经发生的完成记录，这是**综合归纳**。[A1][T1][T2] 各操作的恢复和历史保留细则未统一验证。

### C11 · 共享或归属调整，改变谁可以参与处理

**关联：S02、S06、S10。** 当用户明确分享容器，或把其中任务指派给参与者，可见范围与处理责任发生变化；完成和讨论可在该共享范围中被看到。个人容器不会仅因其中某项任务有日期就自动共享。成员退出、链接权限及是否可以撤回既有内容，须按具体产品说明判断。[A1][T2]

### C12 · 本地操作保存，使用户在断网时仍能组织任务（可选形态）

**关联：S01、S02、S03、S06。** FlowWeek 的 README 描述按周组织、完成、阻塞、改期和本地存储，说明个人每周规划可以以离线形式存在。由此可以认识“没有持续联网仍能处理本机任务”这一形态；不能进一步推断跨设备同步、备份恢复或冲突合并已经得到保证。本次未运行它来验证具体保存行为。[P1]

### 覆盖边界

ATLAS 正文以“未完成/已完成”为核心抽象，有助于区分完成事实和日期紧迫性；但它不能被读成所有实现只能有两个字段值。FlowWeek 的 README 就明确列出 `todo / done / blocked`。因此本文保留阻塞这类附加表达的可能性，没有将这种差异直接裁决为分类错误。[A1][P1]

本图谱尚未覆盖团队审批、复杂依赖、资源容量、自动排程、完整通知投递、跨设备冲突、删除恢复及所有重复日期边界；也不把“记录完成”写成现实工作质量或目标达成的保证。个人任务管理与轻量待办清单有连续地带，本次选择组织与执行视图较明确的现有叶子，未创建重复分类，也未对邻近叶子作合并决定。
