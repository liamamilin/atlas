# 可能性图谱 v0.2 / v0.3 · 两案例比较

**作者复核结论：v0.3 更直接地呈现已有可能性，并把组合、替代、观察尺度和相邻类型边界放在一起解释。没有因此新增已验证的软件形态；本轮的主要收益是让原有认知空间更容易把握。** 关键机制经对照保留，新稿仍待人工内容审查。

## 比较范围

| 案例 | v0.2 基线 | v0.3 对照稿 |
| --- | --- | --- |

v0.2 案例固定在提交 `3c8244b5`，其技能为 `5260567e`；v0.3 技能为用户指定的 `8bcc304`。两个叶子、关注范围和已读资料集合保持相同。v0.1、v0.2 的案例及 v0.2 比较、输入记录均不改写；[INPUTS.json](INPUTS.json) 保存版本与文件校验依据。本轮没有加入新的项目或外部文献。

## 阅读组织与关系表达

| 检查点 | v0.2 的实际表现 | v0.3 的变化及判断 |
| --- | --- | --- |
| 能否先看见状态及其变化 | 先逐个展开整体和局部状态，变化集中在后面的章节 | 开篇直接并排展示整体结果和相应变化；不必先读完全部状态才知道能力怎样形成。结构已改善，实际扫读速度未测量 |
| 哪些能够组合 | 两稿都有独立的组合段落，组合认识并非缺失 | 保留组合，进一步放到与选择、尺度、边界相接的解释中；属于表达改善，不把组合本身重新计作新知识 |
| 哪些选择相互替代 | 不同承载、视图、重复基准等分散在多个条目中 | 电商明确只售实物与只售数字、单次游客与账号路径的选择范围；任务明确可替代的观看布局和不同重复基准。没有把整款软件强行分为互斥类型 |
| 哪些不在同一观察尺度 | 有整体与局部两组条目，也有相关说明 | 直接解释数字商城与一笔下载资格、工具组合与一次完成的区别。整体支持某能力，不能代替局部事实已发生 |
| 相邻类型如何理解 | 已明确 Marketplace 和团队工作管理等边界 | 边界进入概览，并在关系段中解释。此项主要是更早可见，不能算新增类型覆盖 |
| 重复是否减少且仍有机制 | 整体形态、对应能力变化、局部动作中有多次相似说明，并多次重复证据限制 | 概览说明方向，状态段解释关系，变化段保留条件与结果，证据限制集中放末尾。仍保留必要的概览与详解衔接，不以篇幅或条目数作为质量得分 |
| 是否引入新框架 | F、R、L、G、C 编号可用于回查，正文也依赖这些编号串联状态与变化 | 新案例用自然语句组织，核心仍只有期望状态与期望变化；没有要求读者另外学习关系分类或编号体系 |

## 电商：压缩后保留了哪些认识

| v0.2 要点 | v0.3 中的承接位置与检查结果 |
| --- | --- |
| F01、F02、G01：完整经营与内容体验 | 概览首行、状态中的组合段、变化中的经营扩展段；保留目录、结算和持续订单相接的条件 |
| F03、G02、L01、L04、C03：实物、数字与混合交付 | 概览商品范围行、局部结果、购买变化表；保留虚拟不等于文件、文件条件、混合订单与全部虚拟且可下载的特例 |
| F04、F05、G03、G04、G06：店面、渠道及持续经营 | 概览、状态中的归属区别、变化中的维持和缩减；保留目录价格关联、销售来源、关闭渠道后的既有订单，以及同步规则未知 |
| F06、L06、G05：客户连续关系 | 概览客户行与经营变化段；游客路径、购买与账号关联、历史回查及操作权限保留，身份合并没有写成既定能力 |
| L02、L03、C01、C02：订单、付款和履约 | 局部结果与购买变化表；保留草稿不等于提交、有订单不等于付款、授权与收款可能分开、履约不证明签收 |
| L05、C04、C05：取消、库存和退款 | 购买变化表及表后说明；保留有条件的库存处理、部分与全额、手动记账与实际退款的区别，以及退货和权限撤销的缺口 |
| R01、G07：独立卖家参与 | 概览末行及类型关系段；明确多店面和同店员工不等于多卖家，边界延伸未计为单商家内部增益 |

一个关键的关系检查是：**“同一商家开第二个店面”与“让另一个卖家经营”是否被写成一回事？** 新稿明确区分经营归属；这一认识在旧稿已经存在，v0.3 的改进是让区别与其他可能性同时可见。

| v0.2 要点 | v0.3 中的承接位置与检查结果 |

| F03、G03、L04、C04：持续周期事务 | 概览周期行、重复基准区别、任务变化表及表后说明；保留两种日期基准、记录实现差异与撤销限制 |
| F04、F05、G04、G05：工具组合与平台入口 | 概览两行、整体与局部尺度段、扩展工作方式段；保留任务、邮件、会话和日历结果的区别，未补写自动联动 |
| F06、G06：本地与跨设备延续 | 概览存储连续性行及关系段；更明确地说明二者不必互斥，又不能相互保证；同步、恢复与迁移仍未验证 |
| F07、L06、G07：私人和选择性共享 | 概览、参与范围结果、扩展工作方式段；保留可见、可编辑、指派与完成的区别，以及私人范围需要维持 |
| L02、L03、C01–C03：日期、今日与提醒 | 局部结果与任务变化表；保留截止与计划日期、My Day 重置后任务仍在、相对提醒需要对应日期、提示不等于阅读或完成 |
| L05、C05：退出活动范围 | 任务变化表及缩减能力段；保留移出今日、删除、归档、停止重复与完成的区别，恢复和共享退出细则仍未知 |
| R01、G08 及来源边界 | 概览末行与相邻类型说明；保留审批和整体计划成为中心的边界，FlowWeek 的 blocked 观察仍在依据中 |

一个容易制造错误替代的问题是：**“支持离线”与“支持跨设备”是否必须二选一？** 新稿明确不是；它们可以组合，但任何一项单独存在也不能证明另一项成立。另一个区别是列表、看板、日历可以替代观看同一任务，不能据此说任务本身被另一类工作取代。

## 结论的效力

本轮支持“概览更直接、关系更集中、重复说明得到收束且关键机制仍在”的作者内容判断；不支持认知提升百分比、阅读速度提升或 v0.3 必然适用于所有叶子的结论。判断依据是上述内容承接，而非新稿更短、标题更少或表格更整齐。

两次生成在同一对话中完成，作者读过旧稿，未做盲评或读者测验；资料集合相同也不意味着生成过程已被严格控制。概览适合先扫读，但无法替代条件和机制的阅读，手机上的表格阅读效果也未验证。没有运行参考产品、接入网页、批量生产或改动 ATLAS 业务代码。
