## 可能性概览

| 期望状态：商城可以是什么 | 期望变化：怎样形成或改变 |
| --- | --- |
| 商家经营自己的完整商城，内容阅读与购买也可以相接 | 商品展示接上可售目录、结算和持续订单处理，才能形成完整售卖。[A1][A2] |
| 只售实物、只售数字文件，或兼售不同交付类型 | 经营范围改变时，购买后的结果需能分别表达配送、文件资格或另行约定的服务结果。[W1][W2] |
| 同一商家面向不同受众经营多个店面 | 增加店面时，确定其与目录、价格和订单的关系，而不只是复制页面。[A1][A2] |
| 商城与线下、社交或外部市场等销售入口相接 | 接入或关闭渠道，需要继续解释销售来源、记录归属及已有订单的处理。[A1][A2] |
| 游客可以成交，老客户也可以延续购买和服务 | 购买与账号适当关联后，地址、历史订单可跨访问使用；游客路径仍可保留。[A1] |
| 相邻可能性：经营独立卖家共同参与的交易场所 | 引入卖家及其商品、履约、佣金或结算关系后，中心可能转向 Marketplace Platform。[A1][A2] |

表中是材料支持的可能形态及其**综合归纳**，不是一个参考产品已经实现全部组合的承诺。

## 期望状态

### 这些可能性怎样放在一起理解

同一品牌可以在内容站点内兼售电子书和实物，用不同店面服务不同受众，再连接其他销售渠道。**内容体验、商品交付、店面、渠道和客户关系可以组合**，不必选定其中一种后放弃其余。WooCommerce 的内容站点商店、研究笔记中的 BigCommerce 多店面和 Shopify 渠道范围，为这些不同方向提供依据；上述完整组合属于推断。[A1][A2]

也有需要具体选择的地方：商城只售实物还是只售数字文件，是经营范围上的替代方案；兼售则同时保留两类交付条件。支持游客与账号购买的商城，在一次购买中采用哪种身份路径，与整个商城能否同时服务两类消费者，是不同尺度的问题。托管、自行管理或 CMS 插件承载又是另一层安排，不能据此推导商品范围或经营能力。PrestaShop 只在这里作为独立开源商店的存在依据。[A1][A2][P1] 对选择与尺度的解释为**综合判断**。

**多店面、多渠道和多卖家不等同**：前两者可仍由一个商家经营；独立卖家参与后，商品与履约归属及平台经济关系发生变化。给同店员工增加账号，不等于引入独立卖家；商家在外部市场销售，也不等于它自己经营市场。ATLAS 的单商家与 Marketplace 边界支持这种区别，具体准入、退出与售后治理尚未核实。[A1][A2]

### 这些形态内部，需要能辨认的结果

- **商品在具体条件下可售**：规格、售价、启用情况及库存政策有明确含义；允许缺货预订时，零库存不必意味着不能买。虚拟商品不一定是可下载文件，文件资格也可受期限或次数约束。[W1][W2]
- **购买已有记录，但款项与交付仍可分别待处理**：购物车、提交前的临时草稿与正式订单不同；正式订单可以未付款，也可以已付款待履约，且不依赖消费者保持页面打开。[A1][W3][W4]
- **相应交付已经得到满足**：实物有店铺记录的履约结果，数字文件有相应访问资格；某项交付完成不自动代表混合购买全部完成。这一分项理解是推断，统一拆单规则未验证。记录为已履约也不证明签收或满意。[A1][W3]
- **交易结束后仍知道哪些事没有结束**：取消、付款失败、部分或全额退款，以及实际资金返还可分别辨认；原订单仍能承载后续处理。商家人员按相应权限操作，启用客户账号时消费者可回查自身历史。[A1][W4][W5]

“具有数字商城能力”与“这一笔购买已获得下载资格”，是整体与局部的观察，不是互相替代的软件形态；一次付款结果也不能代替整个商城的经营能力。这是上述状态关系的**综合理解**。

## 期望变化

### 扩展与维持经营时，变化的是哪些关系

概览中的内容、店面和渠道扩展，成立的条件是它们仍能通向商家可处理的交易。增加数字商品时，要把相应商品与文件或其他交付条件关联；增加店面时，要知道各处呈现和销售的范围；持续客户服务则依赖购买与客户的正确关联。渠道和客户的精细同步机制，资料没有提供统一答案。[A1][A2][W1][W2] 这里说明的是**能力形成所需关系的推断**，不代表各产品自动具备这些联动。

形态也需要维持或缩减：规格、价格、库存政策或可售范围调整，会改变后续购买条件；关闭销售入口，不使它原来的订单自动消失。当前购物车怎样重算、既有订单能否改价、旧游客订单能否补关联，仍须具体规则。若引入独立卖家，需要改变的是经营归属及平台与卖家的关系，不能用“多开一个店面”替代这一变化。[A1][A2][W2] 上述维持、缩减和边界解释为**综合判断**。

### 一笔购买如何形成、推进或停止

| 触发与必要条件 | 影响的期望状态及变化结果 |
| --- | --- |
| 消费者选规格、改量并提交满足购买要求的结算 | 购买意图成为可持续处理的正式订单，付款仍可在之后发生；临时草稿不能单独证明已提交。[A1][W3][W4] |
| 网关确认款项，或商家核实线下付款 | 未付款或待确认转为款项已确认，再按商品条件判断待交付内容。延迟确认、授权与实际收款可能分开；返回成功页面不足以证明款项已确认，后者为综合判断。[A1][W3] |
| 商家记录实物履约，或数字交付条件已满足 | 对应交付得到记录或开放文件资格；WooCommerce 对全部商品均为虚拟且可下载的订单可跳过通常实物处理阶段，不能推广到全部服务或混合订单。[W1][W2][W3] |
| 付款未成功、符合条件的待付款订单保留时间届满，或发生取消 | 交易停止原处理方向；库存释放或回补取决于管理设置及先前扣减，已收款时仍可能需要退款。这里的付款被拒不指事后银行卡争议。[W3] |
| 商家作出部分或全额退款，或补充后续核实记录 | 原订单继续承载金额调整。兼容网关的自动退款与手动记账不同；手动记录不保证资金已经返还。[W4][W5] |

付款、库存、实物交付和文件资格各有自己的结果；退款不能单独证明商品已退回、已适合入库或下载资格已撤销。这是对多种交付路径的**综合边界判断**。[W2][W5]
