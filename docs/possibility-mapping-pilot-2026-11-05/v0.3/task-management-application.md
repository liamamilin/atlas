## 可能性概览

| 期望状态：个人可以怎样组织工作 | 期望变化：怎样形成或改变 |
| --- | --- |
| 从有组织的任务集合中行动，也能按日或周理解安排 | 事项被保存、归类或分解，再通过日期、优先级和视图形成可行动的集合。[A1][T1][T2] |
| 持续管理周期事务 | 增加重复规则后，本次完成还会确定下一次；固定节奏和完成后再间隔会得到不同安排。[T3][V1] |

## 期望状态

### 这些可能性怎样放在一起理解

一个人可以按周组织工作，对其中部分任务设重复规则，只与家人分享另一份清单，再搭配专注工具。**时间组织、周期事务、工具组合和选择性共享可以共存**，并非四种互斥产品；完整组合是基于材料的推断，未作为实际运行配置验证。[A1][A2][T2][T3]

有些替代发生在更小的范围：支持多布局的产品，可以用列表、看板或日历观看同一批任务；切换观看方式不等于改变完成事实，拖动改期则可能改变任务日期。按周展示也未证明安排已符合实际时间容量。对一条重复规则，按原日期继续和按实际完成日再间隔是不同计算基准，也不是两类必须分开的软件。[A1][A2][T3] 时间容量的区别为**综合判断**。

**本地可用与跨设备延续不必互相排斥**，但也不能相互推出：FlowWeek 的本地离线形态，不证明它提供同步或恢复；其他样本的同步记录，也不证明所有离线变更都能无冲突合并。独立使用或嵌入邮件环境是另一条选择，不决定能否设置重复任务。[A1][A2][P1] 这些选择及组合含义是**综合判断**。

工具组合和单项结果还处于不同尺度。具备专注工具，不使一次计时结束自动等于任务完成；邮件、任务、日历事件也有各自含义。ATLAS 的 TickTick 与 Microsoft To Do 观察支持组合及连接的存在，具体相互完成或删除的机制未验证。[A1][A2]

轻量共同待办仍可围绕个人任务展开；当审批、团队流程或项目整体计划成为核心，才可能转向相邻的工作管理、流程管理或项目管理。一个容器被叫作“项目”，不单凭名称就具备整体交付计划；一个任务多了协作者，也不自动变成组织流程。[A1][A2][T2] 这是类型边界的**综合理解**。

### 这些形态内部，需要能辨认的结果

- **事项已记录并有可继续整理的上下文**：可以尚无日期或标签，也可以已归入容器、分解为子任务；捕获不必同时完成全部安排。[A1][T1]
- **任务仍未完成，但有不同关注理由**：可能到期、逾期、被选入今日重点或已发出提醒。日期紧迫性、关注集合、提醒和完成分别表达事实；Vikunja 还区分截止与计划开始、结束，不能假定每个工具都有相同日期字段。[A1][M1][V1]
- **工作被记录为完成，但重复事务还会继续**：普通完成、误完成撤销、本次周期完成和下一次安排需要能区分，历史也不能一概假定可逆。[T1][T3][V1]
- **本人和他人的参与范围明确**：可看见、可编辑、被指派与已完成是不同关系；私人容器与共享容器可同时存在。[A1][T2] 对这些关系的区分为综合判断。

## 期望变化

### 扩展工作方式时，要保持什么关系

任务进入日周安排或其他工具时，仍需能辨认原来的工作：日期视图不必占用一段日历时间，专注会话也不必代替完成判断；来自邮件的事项则需要足够来源上下文。加入共享后，还要知道谁参与哪些容器、任务归谁处理。以上是对概览中能力扩展的**必要关系推断**，不是自动排程、双向同步或自动完成的产品承诺。[A1][A2][T2]

跨设备延续还要保留同一任务及修改、完成的连续性；停止某种连接、归档容器或退出共享，也不能仅凭入口消失就认定原事项已完成。资料分别支持这些形态或操作，迁移、冲突汇合与退出共享的细则未统一核实，缩减能力后的后果保留为**关系判断**。[A1][A2][T1][T2][P1]

### 一项任务怎样改变，以及什么不会随之自动改变

| 触发与必要条件 | 影响的期望状态及变化结果 |
| --- | --- |
| 用户捕获、归类、分解或改期；入口可能使用自然语言识别 | 形成任务或改变上下文、日期及相应视图。提取日期不保证符合原意；改到未来也没有完成工作。父子关系存在，但完成联动须看产品规则。[A1][T1] |
| 有截止日期且时间越过该日期，或每日重点按自身规则更新 | 未完成任务可以变为逾期；My Day 每晚重置时，未完成事项仍保存并可成为次日建议。关注变化不能代替完成或删除。[A1][M1][V1] |
| 到达绝对提醒时间，或满足相对某日期的提醒条件 | 产生产品支持的提示；相对提醒需要对应日期，邮件提示还受设置影响。发出提示不证明已阅读或已完成，这一区分是综合判断。[V1] |
| 用户完成普通任务，或在允许条件下撤销完成 | 完成事实及相应活动视图变化；重新打开后，原日期仍可能影响紧迫性。Todoist 取消子任务完成会影响父任务，不能推广为通用级联规则。[A1][T1] |
| 重复事项本次完成，且重复规则仍有效 | 依据规则确定下一次。Todoist 的 `every` 取任务日期基准，`every!` 取完成日基准；Vikunja 帮助描述创建下一次事项。不能假定所有产品都新建记录，或都只修改原记录。[T3][V1] |
| 用户删除误建事项、归档容器或停止未来重复 | 活动范围或未来安排变化，不代表完成了原工作。移出今日不等于删除，停止未来重复也不等于撤销历史；恢复规则随产品而异。[A1][T1][T2][M1] 后两项关系为综合判断。 |

普通任务可以重新打开，不保证任意历史重复次数都能撤销；Todoist 对重复完成有撤销限制。[T1] 记录完成也只是软件中的完成判断，不能代替现实工作质量或第三方验收，这是**语义边界判断**。
