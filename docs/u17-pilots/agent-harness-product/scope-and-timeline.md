# Agent Harness 产品调研与开发文档生成：范围与时间记录

状态：已完成真实调研、文档生成、文档批准、冲突处理、Markdown 导出和独立界面复核；首版实现迭代已完成，M0 CLI、provider 配置、连通性冒烟和兼容基线均已通过；M1 CLI 适配器、显式 CLI 执行分支、启动前 preflight、运行证据索引、固定验证步骤、显式清理、最小终端入口和完整只读 TUI 路径已实现并验收。变更任务的停止和应用尚未在本案例中覆盖，另立任务后再验收。

## 目标

验证 Atlas 能否把“想做一个 Agent Harness”的模糊想法，转成有来源、有边界、可开发、可验收的文档包。这里的 Agent Harness 是被研究的软件主题；Atlas 是执行搜索、阅读、分析和文档生成的产品。

## 固定流程

1. 搜索相关类型和应用，记录查询、结果、筛选理由和未命中范围。
2. 阅读正式类型正文、应用文档和产品资料，保存来源版本、章节定位、读取深度和关键摘录。
3. 分栏记录资料事实、当前项目假设、推断、未知和待用户决定的问题。
4. 生成并逐份审阅产品需求、用户流程、技术方案、开发计划和验收计划。
5. 检查需求 → 文档 → 任务 → 验收的关联；缺少依据或边界的内容退回修改。
6. 导出文档包，由不依赖原会话的新会话核对目标、范围、依赖、风险和下一项任务。

## 范围边界

首轮只验证调研和文档生成，不直接实现完整 Harness。短期 OpenCode 集成与长期独立 Harness 的取舍保留为架构决策输入；只有在资料和案例证据足够时才形成建议。
