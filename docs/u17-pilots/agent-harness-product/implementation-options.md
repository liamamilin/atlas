# Agent Harness 首版实现默认与待决事项

下表中的首版默认已由 Atlas 项目决定固定，并已写入最新技术、开发和验收文档；它们仍需在实现时验证。27 项决定已经收敛自治姿态、证据导出、steering、项目级指令、配置文件格式、分发和实现边界。当前只保留后续产品路线问题，不应在本案例阶段误当作已经实现。

| 主题 | 建议首选 | 选择理由 | 备选或后置 |
| --- | --- | --- | --- |
| 隔离执行 | Git 项目优先使用 `git worktree`；非 Git 项目使用目录副本 | 已固定；差异、清理和回滚边界清楚 | 统一目录副本列为后置备选 |
| OpenCode 集成 | CLI 子进程适配器 | 已固定；短期复用现有 OpenCode，边界和失败重试容易记录 | SDK 或直接内嵌待后续评估 |
| 验证命令 | 项目配置显式声明，任务可临时覆盖 | 已固定；验收可复现，覆盖动作必须留下证据 | 自动探测只作为提示 |
| 上下文表达 | 首版只支持文件/目录路径和文本说明 | 已固定；与 TUI、权限范围和证据记录一致 | 符号选择、搜索和语义索引后置 |
| 会话持久化 | 保存任务记录、步骤证据和导出结果，但不支持重启续跑 | 已固定；先保证可复核和可导出 | 后续增加会话恢复、暂停和续跑 |
| 分发与环境 | 首版保证 macOS/Linux 本地可重复运行 | 已固定运行环境边界；具体分发包和最低终端要求仍待决定 | 二进制、包管理器和更广泛兼容后置 |

## 采用条件

实现前的首版边界已处理并建立活动迭代；M0 CLI、provider 配置、连通性冒烟和兼容基线已通过，M1 CLI 适配器基础已实现。后续路线问题仍需在独立迭代中决定，不改变当前纵向切片。

## 后续产品路线问题

1. 是否支持多个并行任务会话。
2. 是否提供暂停后的用户接管（take-over）交互。
3. 是否需要任务历史/会话列表界面。
4. 是否允许在 TUI 内编辑 `.atlas/harness.json`。
5. IDE、Web、聊天和 CI 入口是否进入近期路线。

这些问题不阻塞本案例的文档最佳实践收口；如果进入实现迭代，再单独建立路线决策并更新文档版本。
