# M5 案例三 · 客户项目交付与个人排程 — 产品需求

## 1. 产品概述

本产品通过三类数据源——敏捷项目管理（Agile PM）、日历（Calendar）和审批工作流（Approval Workflow）——明确客户项目交付、个人排程和客户决定之间的数据归属、流程交接、权限与失败恢复，形成可执行且可验收的产品范围。

### 1.1 目标用户

- **项目经理 / Planner**：管理项目 backlog、分配迭代、追踪交付进度
- **团队成员 / Team Member**：执行工作项、推进状态、标记阻塞
- **请求者 / Requester**：提交审批请求（如资源申请、变更请求）
- **审批者 / Approver**：审批/拒绝/退回请求
- **个人用户**：管理个人日历事件、查看项目相关时间块

### 1.2 产品边界

- 不涉及客户认证或计费
- 不涉及资源级自动排程
- 不承诺自动双向同步
- 审批退回与日历同步为手动或只读引用

## 2. 需求清单

### PR-001：三类资料的主记录归属

**优先级**：P0（核心）

明确三类资料的系统记录归属：
- Agile PM 系统为项目交付和工作项的系统记录
- Calendar 为个人时间锚点和可用时段的系统记录
- Approval Workflow 为审批决定和审计轨迹的系统记录

任何跨系统引用均以引用方式链接，不复制主记录。

**验收条件**：
1. 每个数据实体有且仅有一个系统记录归属
2. 跨系统引用使用稳定 ID 链接而非数据复制
3. 三个系统的 project note 范围约束被文档化

**来源**：req_a8038841aea54049acda239ef0e6a5c0

### PR-002：跨系统稳定 ID 映射

**优先级**：P0（核心）

为跨系统引用定义稳定 ID 映射规则：审批请求 ID、工作项 ID、日历事件 ID 各自作为稳定标识符，通过关联表记录三者之间的链接关系，不合并为统一 ID。

**关联表字段**：source_system、source_id、target_system、target_id、relation_type（triggers/references/schedules）、created_at、created_by。

**验收条件**：
1. 关联表记录跨系统 ID 映射
2. ID 映射可审计且不可变
3. 任一系统 ID 变更不影响其他系统的引用

**来源**：req_8d71b08faa644d9591a08e39921bac89

### PR-003：审批决定到项目工作项的状态交接

**优先级**：P0（核心）

定义审批决定到项目工作项的状态交接协议：

| 审批决定 | 工作项动作 |
|---|---|
| Approved | 创建工作项或推进状态至 In Progress |
| Rejected | 关闭工作项或标记为 Rejected |
| Return for revision | 标记工作项为 In Revision（reopened） |
| Withdrawn / Cancelled | 取消相关工作项 |

交接为单向触发（审批到项目），不自动反向同步。交接事件同时记录在审批审计轨迹和工作项历史中。

**验收条件**：
1. 每种审批决定有对应的工作项状态转换
2. 交接事件被记录在两个系统的审计轨迹中
3. 交接失败有明确的回滚或通知机制

**来源**：req_bdc3a472862e440bb2cc5f1726ceb23d

### PR-004：跨系统权限边界

**优先级**：P0（核心）

定义跨系统权限边界：

| 系统 | 角色 | 核心权限 |
|---|---|---|
| 审批工作流 | Requester | 提交请求、查看状态、修订退回的请求 |
| 审批工作流 | Approver | 审批/拒绝/退回请求、查看请求详情 |
| 审批工作流 | Admin | 配置审批流程、管理用户和角色 |
| 敏捷 PM | Team member | 创建/编辑工作项、推进状态 |
| 敏捷 PM | Planner | 管理 backlog 优先级、分配迭代 |
| 敏捷 PM | Team lead | 管理节奏、查看团队指标 |
| 日历 | Owner | 创建/编辑/删除事件、管理共享 |
| 日历 | Delegate | 代表 owner 管理日历 |
| 日历 | Invitee | 响应邀请、propose 新时间 |

跨系统权限隔离规则：
- 审批 Approver 不自动获得对应工作项的编辑权限
- 项目 Team lead 不自动获得审批请求的查看权限
- 日历 Owner 的共享权限不跨系统传递
- 跨系统权限提升需要显式授权且可审计

**验收条件**：
1. 每个系统的角色权限被独立定义
2. 跨系统操作的权限提升有显式审批
3. 权限变更可审计

**来源**：req_f3a3f6d8e46a47e9b0ee0f821ad89692

### PR-005：失败恢复协议

**优先级**：P1（重要）

定义三类失败场景的恢复协议：

| 场景 | 检测条件 | 恢复机制 | 自动化程度 |
|---|---|---|---|
| 审批请求停滞 | 超过 SLA 时限无决定 | 提醒后升级到更高审批者 | 自动提醒，半自动升级 |
| 工作项阻塞 | 状态停留在 Blocked 超过阈值 | 看板标记，团队 standup 协调 | 手动 |
| 跨系统交接失败 | 交接事件未在目标系统创建 | 通知相关角色，手动重新触发 | 通知自动，恢复手动 |
| 日历同步失败 | 只读引用未更新 | 手动重新同步或事件重建 | 手动 |

每类恢复保留完整审计轨迹。

**验收条件**：
1. 每类失败有定义的检测条件
2. 恢复步骤被文档化且可执行
3. 恢复操作被记录在审计轨迹中

**来源**：req_846261511acb4fd1a31d9dad57e4e71f

### PR-006：跨系统同步取舍

**优先级**：P0（核心）

明确跨系统同步的取舍原则：

| 源系统 | 目标系统 | 同步方向 | 同步类型 | 边界 |
|---|---|---|---|---|
| 审批工作流 | 敏捷 PM | 单向（审批到项目） | 事件触发 | 不反向同步 |
| 敏捷 PM | 日历 | 只读引用 | 时间块显示 | 不自动创建事件 |
| 审批工作流 | 日历 | 不同步 | N/A | 无直接关联 |

不自动同步的场景：
- 审批退回不要求自动更新工作项历史（由用户决定详细程度）
- 工作项完成不要求自动关闭相关审批请求
- 日历事件修改不要求自动更新项目迭代日期

**验收条件**：
1. 同步方向和范围被显式定义
2. 不自动同步的边界被文档化
3. 同步失败有降级方案

**来源**：req_daef6b4dd9804830bc377c4317c1dd33

## 3. 非功能性需求

### 3.1 审计

- 所有跨系统交接事件需在源系统和目标系统均有审计记录
- ID 映射变更可审计且不可变
- 权限变更可审计

### 3.2 可观测性

- 审批请求的当前状态和待审批者对所有相关方可见
- 工作项阻塞状态在看板上显式标记
- 同步失败通过通知告警

### 3.3 降级

- 同步失败时保留手动恢复路径
- 审批系统不可用时不影响项目工作项的本地编辑
- 日历引用不可用时不影响项目迭代的正常管理
