# M5 案例三 · 客户项目交付与个人排程 — 验收计划

## 1. 验收目标

验证产品需求 PR-001 至 PR-006 的所有验收条件均被满足，确认三类系统之间的数据归属、流程交接、权限隔离和失败恢复机制可执行且可验收。

---

## 2. 验收策略

### 2.1 验收层次

1. **需求验收**：逐条验证每个 PR 的验收条件
2. **集成验收**：端到端场景验证
3. **非功能验收**：审计、可观测性、降级能力

### 2.2 验收环境

- 审批工作流系统实例（含测试审批流程）
- 敏捷 PM 系统实例（含测试项目和工作项）
- 日历应用实例（含测试事件）
- 关联表服务实例
- 集成服务实例

### 2.3 验收角色

- **验收负责人**：确认验收标准和通过条件
- **测试执行者**：执行验收场景并记录结果
- **审计审查者**：验证审计轨迹的完整性和可追溯性

---

## 3. 验收场景

### 3.1 PR-001：主记录归属验收

**场景 1.1**：数据实体归属唯一性
- 创建审批请求，验证审批平台为主记录
- 创建工作项，验证敏捷 PM 为主记录
- 创建日历事件，验证日历为主记录
- 验证跨系统引用使用 ID 链接而非数据复制

**场景 1.2**：project note 范围约束
- 审核文档中三个系统的范围约束是否被记录
- 验证无超出范围的推断或假设

### 3.2 PR-002：稳定 ID 映射验收

**场景 2.1**：关联表创建
- 通过 API 创建跨系统映射记录
- 验证 source_system、source_id、target_system、target_id、relation_type 字段正确

**场景 2.2**：映射不可变性
- 尝试物理删除映射记录，验证被拒绝
- 通过 status 字段标记废弃，验证历史记录保留

**场景 2.3**：ID 变更隔离
- 修改审批请求 ID（如可能），验证关联表中的映射不受影响
- 验证其他系统通过旧 ID 仍可追溯

### 3.3 PR-003：状态交接验收

**场景 3.1**：Approved 决定
- 提交审批请求 → Approver 批准 → 验证工作项创建或状态推进至 In Progress
- 验证审批审计轨迹记录该决定
- 验证工作项历史记录该交接

**场景 3.2**：Rejected 决定
- 提交审批请求 → Approver 拒绝 → 验证工作项关闭或标记为 Rejected

**场景 3.3**：Return for revision 决定
- 提交审批请求 → Approver 退回 → 验证工作项标记为 In Revision（reopened）
- 验证工作项保留修订历史

**场景 3.4**：Withdrawn 决定
- 提交审批请求 → Requester 撤回 → 验证相关工作项取消

**场景 3.5**：交接失败
- 模拟目标系统不可用 → 验证交接失败通知触发
- 验证可通过手动重试接口重新执行

### 3.4 PR-004：跨系统权限验收

**场景 4.1**：角色权限隔离
- 以 Approver 身份尝试编辑工作项，验证被拒绝
- 以 Team lead 身份尝试查看审批请求，验证被拒绝
- 以日历 Invitee 身份尝试编辑他人事件，验证被拒绝

**场景 4.2**：服务账户最小权限
- 检查服务账户权限配置，验证仅拥有 handoff 所需权限
- 验证服务账户无法执行超出范围的操作

**场景 4.3**：权限变更审计
- 执行一次权限提升操作
- 验证权限变更被记录在审计日志中

### 3.5 PR-005：失败恢复验收

**场景 5.1**：审批停滞恢复
- 创建审批请求后不操作，等待超过 SLA 时限
- 验证自动提醒通知发送
- 验证超过升级阈值后自动转派

**场景 5.2**：工作项阻塞恢复
- 将工作项状态设为 Blocked 并等待超过阈值
- 验证看板上显示告警标记

**场景 5.3**：交接失败恢复
- 模拟交接失败场景
- 验证通知相关角色
- 验证可通过手动接口重新触发
- 验证失败事件记录审计日志

### 3.6 PR-006：同步取舍验收

**场景 6.1**：审批到项目单向同步
- 验证审批决定触发工作项状态变更
- 验证工作项状态变更不触发审批状态变更

**场景 6.2**：项目到日历只读引用
- 修改 Sprint 时间，验证日历只读引用更新
- 验证不自动创建可编辑的日历事件
- 验证用户可隐藏或删除项目时间块

**场景 6.3**：审批与日历不同步
- 验证审批决定不触发任何日历变更

## 4. 审计验收

### 4.1 审计轨迹完整性

- 验证每个 Handoff 事件在审批系统和项目系统均有审计记录
- 验证关联表变更记录审计事件
- 验证权限变更记录审计日志

### 4.2 跨系统审计关联

- 通过 correlation_id 查询跨系统审计记录
- 验证审计记录不可修改、不可删除

## 6. 验收流程

1. **准备阶段**：确认验收环境就绪、测试数据准备完成
2. **执行阶段**：按场景逐条执行验收测试
3. **记录阶段**：记录每个场景的执行结果和问题
4. **评审阶段**：评审验收结果，确认通过或提出问题
5. **闭环阶段**：问题修复后重新验收，直至全部通过
