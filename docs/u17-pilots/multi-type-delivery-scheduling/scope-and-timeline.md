# 案例三范围与时间线

## 固定目标

为小型客户交付团队设计一条从项目 backlog 到个人可用时段，再到客户反馈与验收的可追踪流程。首轮确认数据归属、交接标识、状态映射、权限、同步和失败恢复；不承诺自动双向同步或完整客户门户实现。

## 来源事实边界

- Agile Project Management：项目管理类型的主线是团队拥有的有序 backlog、工作项、工作流状态、明确完成状态和有边界的交付节奏。它没有直接定义个人日历或客户审批记录。
- Calendar：日历类型的主线是持久化、带时间锚点的事件和可导航时间网格。它没有直接定义项目工作项完成或客户授权。
- Approval Workflow：审批工作流的主线是结构化请求、路由、可归因的 approve/reject/return 决定、显式状态和审计历史。批准本身是授权结果，不等于下游工作已经执行。

## 产品假设（已确认并转为实现约束）

1. 项目工作项持有交付范围和完成条件，是交付主记录。
2. 日程事件只持有时间承诺和冲突事实，引用工作项 ID，不复制完整项目状态。
3. 审批请求持有客户决定和审计历史，引用交付物或工作项 ID。
4. 状态映射先采用显式单向交接，避免首轮引入隐式双向同步。
5. 退回、超时、重复回调和日程冲突均需要人工可见的恢复路径。

## 首轮范围

- 三类记录的主记录表和稳定 ID 规则。
- 项目 → 日程、项目 → 审批、审批 → 项目的交接状态表。
- 责任人、权限、时间戳、来源和审计字段。
- 失败恢复和人工接管流程。
- 可导出的产品、技术、开发和验收文档，以及一项结构化开发任务。

## 后续与排除

后续可评估供应商日历/审批接入、通知和更完整客户门户。首轮排除自动双向同步、资源级自动排程、客户认证/计费、多租户和自研通用 Harness。

## Atlas 分析后的待审阅范围

以下范围已经确认并写入 Atlas 工作区：

- 当前：主记录归属、稳定 ID 映射、审批到项目的单向状态交接、跨系统权限边界、失败恢复协议、同步取舍原则。
- 后续：真实供应商连接、通知与升级自动化、客户侧外部审批、日历只读时间块的产品化实现。
- 明确排除：自动双向同步、资源级自动排程、客户认证与计费、自研通用 Harness。

已收口的实现决策：日历项目时间块为系统维护的只读投影；审批批准优先使用已有工作项 ID，没有 ID 时进入人工确认队列；失败恢复阈值采用可配置的初始默认值（审批 24/48 小时、Blocked 2 个工作日、自动重试 3 次）。
