## T1：跨系统关联表与稳定 ID

**目标**：建立审批请求、工作项和日历投影之间的不可变关联。

**工作内容**：

- 建立 `cross_system_mapping` 数据结构和唯一约束。
- 支持创建、查询、软废弃，不允许物理删除。
- 记录来源系统、来源 ID、目标系统、目标 ID、关系类型、责任人和时间戳。

**验收**：重复映射被拒绝；软废弃保留历史；任意映射可通过来源 ID 和目标 ID 追溯。

## T2：审批到项目的单向 handoff

**目标**：把审批决定安全地交接到项目工作项。

**工作内容**：

- 支持 Approved、Rejected、Return、Withdrawn 四种决定映射。
- 优先使用审批请求中的工作项 ID。
- 缺少工作项 ID 时进入人工确认队列，禁止自动创建。
- 使用审批请求 ID 加决定版本作为幂等键。

**验收**：重复回调不重复更新；缺少关联 ID 时不会自动产生工作项；失败事件可人工重试并保留审计记录。

## T3：日历只读投影

**目标**：让项目节奏可见，同时保持项目系统的日期主权。

**工作内容**：

- 将 Sprint 和里程碑映射为系统维护的只读时间块。
- 用户可以隐藏或删除个人显示，但日历修改不反向修改项目日期。
- 记录投影 UID、来源项目 ID 和最后同步时间。

**验收**：项目日期变更可更新投影；日历端修改不会回写项目；投影同步失败可见并可手动重试。

## T4：权限、审计与失败恢复

**目标**：让跨系统操作可控、可追踪、可恢复。

**工作内容**：

- 为服务账户配置最小权限。
- 审批停滞默认 24 小时提醒、48 小时升级。
- Blocked 默认 2 个工作日告警。
- 交接失败最多自动重试 3 次，之后进入人工队列。
- 所有阈值可配置，所有恢复动作带 correlation ID。

**验收**：角色越权被拒绝；阈值触发正确；重试达到上限后转人工；审计记录包含操作者、来源、目标、时间和结果。
