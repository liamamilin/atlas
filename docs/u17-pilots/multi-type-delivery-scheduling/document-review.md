状态：四份文档已生成并应用；T1–T5 已完成并通过当前范围验收。下面的 P1/P2 是后续真实实现范围的决策清单，不是当前案例未完成项。

- 决策记录已明确：审批到项目采用单向 handoff；暂不实现双向同步、资源级自动排程、客户认证和计费。
- 产品需求、技术方案、开发计划和验收计划已按依赖顺序应用到 Atlas 工作区。

## 实现前需要收口的事项

### P1：日历引用的编辑权

产品需求把项目时间块定义为“只读引用”，技术方案又写到用户可以直接编辑日历事件。实现前应固定为：系统生成的项目时间块由集成服务维护，用户可以隐藏或删除本地显示，但不能通过日历反向修改项目日期；如需改期，应回到项目系统修改。

### P1：批准后的工作项创建方式

PR-003 同时允许“创建工作项”或“推进既有工作项”。首轮实现需要选择一种默认行为，并定义重复审批回调的幂等键。建议以审批请求中的工作项 ID 为主；没有 ID 时由人工确认后创建，避免自动产生重复工作项。

### P1：恢复阈值与责任人

失败恢复表已定义场景和动作，但 SLA、Blocked 阈值、升级对象、重试次数仍未定。开发前应为每类失败补齐阈值、责任角色和审计字段。

### P2：接口实现边界

技术方案中的 API 是契约草案，不代表已经接入真实供应商。首轮先实现本地契约、模拟适配器、幂等和审计，再评估真实 provider 接入。

## 后续若立项的开发顺序

1. 固定上述三个 P1 决策并补入需求与验收条件。
2. 先实现关联表、稳定 ID 和审计事件。
3. 实现审批到项目的单向 handoff、幂等和人工重试。
4. 实现项目到日历的只读投影及隐藏/删除偏好。
5. 按验收计划执行权限、失败恢复和端到端场景。
