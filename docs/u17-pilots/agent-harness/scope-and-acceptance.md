# Agent Harness 架构评估：范围与验收

状态：架构决策输入协议草案，不属于产品使用最佳实践。

## 对照任务

选择一个允许写入路径不超过两个文件、固定回归命令、可在隔离副本完成的局部代码任务。先使用现有 Atlas + OpenCode 路径完成一次，再用最小 Harness 重跑同一任务。

## Harness 最小职责

- 把 Atlas 已批准的任务、文档版本、需求、基线和写入范围组装成执行输入。
- 在隔离副本运行 OpenCode，限制读取、写入、命令和网络权限。
- 记录事件、权限请求、停止原因、验证命令和输出文件。
- 支持停止后恢复；旧会话不可访问时，使用交接包继续，不重放已确认的副作用。
- 输出可由 Atlas 核对的差异和机器可读执行摘要。

## 不纳入 Harness 的职责

- 需求确认、文档批准、基线采用和产品验收。
- 业务范围裁决和跨项目资料管理。
- 将某个引擎的私有会话或提示格式写入 Atlas 核心状态。

## 验收条件

| 编号 | 条件 |
|---|---|
| AH-R1 | 同一固定输入下，Atlas + OpenCode 与 Harness 的写入范围、验证命令和结果可并排比较 |
| AH-R2 | 越权写入、未授权命令和网络请求在 Harness 控制面被阻止并留下证据 |
| AH-R3 | 中断、权限等待和验证失败均能安全结束，旧工作区和新副本状态可区分 |
| AH-R4 | 旧会话不可访问时，仅凭 Atlas 交接包完成下一步核对，不重复副作用 |
| AH-R5 | Harness 的额外首次通过率、重试、恢复时间或成本改善达到可解释阈值；否则记录为不值得独立抽象 |

## 决策门槛

- 若 Atlas 已能提供可靠的权限、隔离、验收和交接证据，Harness 只保留为薄适配层。
- 若多个任务持续暴露同一控制或恢复缺口，才提炼最小共享组件。
- 不因为实现了 Harness 本身就判定案例成功。
