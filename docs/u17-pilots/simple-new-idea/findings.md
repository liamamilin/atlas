# 试点发现

状态：两轮试点已完成；普通生成与 Atlas 结果均已封存。

| 编号 | 阶段 | 级别 | 事实 | 影响 | 处理与复验 |
|---|---|---|---|---|---|
| M5-NI-P01 | 普通生成调用 | 过程 | 两次 CLI 调用在模型请求前因附件路径和参数顺序失败；第三次保持同一输入并成功 | 增加约 1 分钟操作时间，不影响模型结果或对照输入 | 原始 stderr 保留；`ordinary-run.json` 区分未调用模型的失败和唯一模型调用 |
| M5-NI-O01 | 普通生成输出 | 待比较 | 输出给出 Tauri/Electron、纯 Web、Python GUI 多套方向，没有单一实现选择 | 不能直接据此创建可执行开发任务 | Atlas 通过项目约束固定为 Python 标准库 + SQLite + 原生 Web |
| M5-NI-O02 | 普通生成输出 | 待比较 | 输出声称现有工具偏团队、缺少跨项目当天聚合或锁定云端；附件未提供产品级证据 | 市场判断可能被误当作来源事实 | Atlas 文档把这类说法标为未知/推断，不作为需求依据 |
| M5-NI-A01 | 第一轮执行 | 过程 | 首次执行把运行时 `planner.db` 带入声明范围，Atlas 拒绝应用；另一次完成报告 JSON 无效 | 暴露“源码路径”和运行产物隔离、机器可读报告约束 | 清理数据库后重试；严格 JSON 重试通过，9/9 固定测试通过 |
| M5-NI-A02 | 第二轮执行 | 过程 | OpenCode 修改 5 个声明文件并通过固定测试，但 agent 完成报告仍缺失 | 不能只依赖 agent 自报完成 | Atlas 独立核对快照、测试输出和真实页面，验收标记 passed |
| M5-NI-A03 | 第二轮产品 | 设计 | 时间块关系、移除承诺级联、首尾相接边界、时间表示等仍是开放问题 | 扩展多时间块或外部同步前可能返工 | 当前实现采用承诺外键、分钟字符串和只读冲突检测；后续轮次先补决策 |
| M5-NI-A04 | 工具稳定性 | 过程 | Atlas 后端在长轮询期间曾退出，导致确认 API 临时 500 | 页面错误可能被误判为产品 bug | 重启 `drafts_api.py` 后重试；确认和生成流程恢复，未改动产品代码 |

## 设计结论

本试点验证了“先固定资料与范围，再生成文档，最后由 OpenCode 执行并独立验收”的闭环。短期集成 OpenCode 足够支撑开发，但 Atlas 仍需保留独立的基线、快照、测试和产品验收层，避免把模型报告当作完成事实。
