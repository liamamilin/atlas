# 试点发现

状态：两轮试点已完成；普通生成与 Atlas 结果均已封存。

| 编号 | 阶段 | 级别 | 事实 | 影响 | 处理与复验 |
|---|---|---|---|---|---|
| M5-NI-P01 | 普通生成调用 | 过程 | 两次 CLI 调用在模型请求前因附件路径和参数顺序失败；第三次保持同一输入并成功 | 增加约 1 分钟操作时间，不影响模型结果或对照输入 | 原始 stderr 保留；`ordinary-run.json` 区分未调用模型的失败和唯一模型调用 |
| M5-NI-O01 | 普通生成输出 | 待比较 | 输出给出 Tauri/Electron、纯 Web、Python GUI 多套方向，没有单一实现选择 | 不能直接据此创建可执行开发任务 | Atlas 通过项目约束固定为 Python 标准库 + SQLite + 原生 Web |
| M5-NI-O02 | 普通生成输出 | 待比较 | 输出声称现有工具偏团队、缺少跨项目当天聚合或锁定云端；附件未提供产品级证据 | 市场判断可能被误当作来源事实 | Atlas 文档把这类说法标为未知/推断，不作为需求依据 |
| M5-NI-A01 | 第一轮执行 | 过程 | 首次执行把运行时 `planner.db` 带入声明范围，Atlas 拒绝应用；另一次完成报告 JSON 无效 | 暴露“源码路径”和运行产物隔离、机器可读报告约束 | 清理数据库后重试；严格 JSON 重试通过，9/9 固定测试通过 |
| M5-NI-A02 | 第二轮执行 | 过程 | OpenCode 修改 5 个声明文件并通过固定测试，但 agent 完成报告仍缺失 | 不能只依赖 agent 自报完成 | Atlas 独立核对快照、测试输出和真实页面，验收标记 passed |
| M5-NI-A03 | 第二轮产品 | 设计 | 时间块关系、移除承诺级联、首尾相接边界、时间表示等仍是开放问题 | 扩展多时间块或外部同步前可能返工 | 当前实现采用承诺外键、分钟字符串和只读冲突检测；后续轮次先补决策 |
| M5-NI-A04 | 工具稳定性 | 过程 | Atlas 后端在长轮询期间曾退出，导致确认 API 临时 500 | 页面错误可能被误判为产品 bug | 重启 `drafts_api.py` 后重试；确认和生成流程恢复，未改动产品代码 |

## 设计结论

本试点验证了“先固定资料与范围，再生成文档，最后由 OpenCode 执行并独立验收”的闭环。短期集成 OpenCode 足够支撑开发，但 Atlas 仍需保留独立的基线、快照、测试和产品验收层，避免把模型报告当作完成事实。

| M5-NI-A05 | 第三轮测试环境 | 过程 | 固定测试中的 HTTP 用例首次因沙箱禁止临时端口绑定失败，并非代码断言失败 | 容易把环境限制误判为产品回归 | 在允许本地端口的环境复跑 43/43；保留首次失败证据并在验收记录中区分 |
| M5-NI-A06 | 第三轮服务层 | 产品 | 第二轮功能可通过页面创建时间块，但服务层原先未约束 `HH:MM` 格式和结束时间顺序，直接 API 调用存在数据污染风险 | 非法时间可能进入本地数据库，影响后续冲突计算与读取 | 增加 API/数据层双重校验和回归测试；非法请求返回 400 且不写入，合法请求 201 |

| M5-NI-A07 | 第四轮执行 | 过程 | 首次任务声明写入范围遗漏 `static/index.html`，Atlas 正确拒绝应用越界结果 | 任务边界遗漏会造成可用实现无法应用，并增加一次重试 | 新建完整范围任务，应用成功；首个结果保持未应用并记录为重复任务 |
| M5-NI-A08 | 第四轮产品 | 可用性 | 原页面 API 失败时没有用户可见反馈，冲突横幅与列表共享渲染区域 | 网络或 API 错误会表现为无响应，冲突提示可能被重绘覆盖 | 增加统一错误 toast、HTTP 错误解析和独立冲突区域；页面实测与 54/54 测试通过 |

| M5-NI-A09 | 第五轮执行 | 过程 | OpenCode 初始固定测试发现两条测试夹具错误，随后修正并报告 80/80；机器可读完成报告仍为无效 JSON | 代理报告不能单独作为完成事实，且测试夹具错误会掩盖真实回归 | 应用后独立在允许本地端口的环境复跑 80/80，并补做 node 语法检查和真实页面验收 |
| M5-NI-A10 | 第五轮页面 | 产品 | 应用后的 `static/app.js` 少一个模板字符串结束反引号，导致页面脚本不执行、项目列表为空 | 后端测试全通过仍可能出现核心 UI 完全不可用 | 独立 `node --check` 定位并修复；重启服务后页面编辑、取消删除、确认删除均通过 |
| M5-NI-A11 | 第五轮数据 | 过程 | 页面验收产生本地 `planner.db`，直接删除会有未知数据丢失风险 | 临时验收产物可能污染基线，也不应未经确认删除 | 将数据库可逆移出工作区，再接受最终基线；未删除未知数据 |

| M5-NI-A12 | 第六轮数据迁移 | 产品 | 完成状态需要在已有单文件 SQLite 上增列并兼容旧数据 | 直接改表可能破坏既有项目和任务 | 使用 `completed DEFAULT 0` 迁移并用跨连接测试验证旧记录和新状态均可读取 |
| M5-NI-A13 | 第六轮边界 | 产品 | 完成状态若自动移除承诺会破坏用户手工安排语义 | 用户无法在完成后回看当天承诺或时间块 | 明确完成/恢复只修改任务状态，103/103 测试和页面验收确认承诺及时间块保持 |

| M5-NI-A14 | 第七轮执行 | 过程 | OpenCode 完成报告缺失且 requirement IDs 不完整，机器状态一度显示验证证据不足 | 代理状态不能替代产品验收和完整测试 | 应用结果后独立运行 117/117 测试、Node 语法检查、真实 API 结构与只读比对，并在 Atlas 标记产品验收通过 |
| M5-NI-A15 | 第七轮备份 | 产品 | 本地优先数据缺少用户主动备份出口，丢失会破坏项目上下文 | 用户无法把当前计划保存到工作区外 | 增加只读 `GET /api/export` 和页面 JSON 下载，固定 `schema_version` 与 `exported_at`；导入覆盖、自动备份和云同步继续排除 |
