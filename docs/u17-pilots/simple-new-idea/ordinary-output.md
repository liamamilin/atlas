# 本地优先个人日计划器实施方案

## 目标用户与需要解决的问题

**目标用户：** 同时推进多个个人项目的独立开发者。

**需要解决的问题：** 当个人项目数量超过单列表可管理范围时，开发者需要将不同项目的任务汇总到当日视图中执行，同时保持项目结构完整。现有工具要么偏向团队协作（重量过重），要么缺少跨项目的当天聚合能力，要么将数据锁定在云端。

> **来源说明：** 用户画像和问题描述基于 NI-S1（任务管理应用的核心模型：容器化组织与执行视图）和 NI-S3（个人集成应用：多领域记录整合）综合推断；"本地优先"和"多项目开发者"场景为本项目假设。

## 本轮范围

### 本轮包含

1. 创建和管理多个项目（作为任务容器）
2. 在项目下创建、编辑、完成、删除任务
3. 从不同项目中选择任务，形成指定日期的"当天承诺"清单
4. 当天承诺视图：展示所选任务、支持标记完成
5. 从当天承诺中移除任务（不影响原项目任务）
6. 本地数据持久化（SQLite 或 JSON 文件）
7. 进程重启后数据保持一致

### 明确不做的内容

- 手动时间块（时间块创建、拖拽、时长估算）
- 冲突提示与工作量预警
- 外部日历集成
- 自动排程与 AI 建议
- 账号系统
- 云同步
- 团队协作与共享

> **来源说明：** 范围界定直接依据 `ordinary-input.md` 的项目目标描述。"不做的内容"列表取自原文，补充了与 NI-S2（时间块应用）重叠的排除项。

### 主要用户流程

```
创建项目 → 在项目下创建任务
     ↓
选择日期 → 从各项目中勾选任务加入当天承诺
     ↓
当天承诺视图：按日期查看/完成/移除任务
     ↓
返回项目视图：任务状态同步（已完成的项目任务标记为完成）
```

## 核心数据模型及对象关系

### 数据实体

```
Project（项目）
├── id: UUID
├── name: String
├── description: String?（可选）
├── createdAt: Timestamp
└── updatedAt: Timestamp

Task（任务）
├── id: UUID
├── projectId: UUID → Project.id
├── title: String
├── description: String?（可选）
├── status: enum { pending, completed }
├── createdAt: Timestamp
└── updatedAt: Timestamp

DailyCommitment（当天承诺）
├── id: UUID
├── date: Date（YYYY-MM-DD）
├── taskId: UUID → Task.id
├── addedAt: Timestamp
└── removedAt: Timestamp?（软删除标记）
```

### 对象关系

- **Project → Task**：一对多。一个项目包含多个任务。
- **Task → DailyCommitment**：一对多（按日期）。一个任务可在不同日期的承诺清单中出现。
- **DailyCommitment → Task**：多对一。一条承诺记录引用一个任务。
- **移除承诺 ≠ 删除任务**：移除 DailyCommitment 记录不影响 Task 记录。

> **来源说明：** 数据模型设计来源于 NI-S1 的核心模型（任务作为基本单元、容器化组织）和 NI-S3（本地数据库存储理念）。"当天承诺"作为独立实体（而非任务的日期属性）是本项目假设，目的是满足"移除承诺不删任务"的需求，同时保留承诺历史。

## 页面或交互结构

### 页面划分

```
1. 项目列表页
   - 项目卡片/列表
   - 操作：新建项目、编辑、删除

2. 项目详情页
   - 项目名称与描述
   - 任务列表
   - 操作：新建任务、编辑任务、完成任务、删除任务

3. 当天承诺页（主工作面）
   - 日期选择器
   - 来自各项目的任务列表（按项目分组）
   - 操作：从项目中选择任务加入、移除承诺、标记完成

4. 全局导航
   - 切换：项目列表 / 当天承诺
```

### 交互要点

- **任务选择流程**：在当天承诺页，用户点击"添加任务"→ 弹出项目/任务选择器 → 勾选任务 → 确认加入
- **承诺完成**：勾选任务复选框，状态同步回原任务
- **承诺移除**：滑动或点击移除按钮，仅删除承诺记录，任务回到项目列表中

> **来源说明：** 页面结构参考 NI-S1 的执行视图（Today 视图、容器列表视图）和 NI-S3 的模块视图与组合视图设计。"按项目分组展示承诺任务"是本项目假设。

## 适合本地运行的技术方案

### 推荐技术栈

| 层次 | 选择 | 理由 |
|------|------|------|
| **运行环境** | Tauri（Rust + Web 前端）或 Electron | 本地桌面应用，打包后无需服务器 |
| **前端框架** | React / Vue / Svelte | 成熟的组件化开发 |
| **数据存储** | SQLite（通过应用内嵌） | 结构化数据、关系查询、本地文件单库 |
| **ORM** | Drizzle / Prisma（SQLite 模式）或原生 SQL | 简化数据访问层 |
| **状态管理** | Zustand / Pinia / 内置方案 | 轻量客户端状态 |
| **打包分发** | Tauri build / electron-builder | 生成平台安装包 |

### 备选方案

- **纯本地 Web 应用**：HTML + JS + IndexedDB，浏览器内运行，无需安装，但功能受限
- **Python + SQLite + tkinter/PyQt**：纯 Python 方案，适合快速原型

> **来源说明：** 技术选型基于 NI-S3 的本地存储原则（"local database file"、"privacy is structural"）和本项目"本地优先"约束。具体框架选择为本项目假设。

## 可独立执行的验收办法

### 验收测试场景

**场景 1：项目与任务 CRUD**
1. 启动应用 → 创建项目 A → 创建任务 A1、A2
2. 验证：项目列表显示 A，项目详情显示 A1、A2
3. 编辑任务 A1 标题 → 验证更新生效
4. 完成任务 A2 → 验证状态变为 completed
5. 删除任务 A1 → 验证任务消失

**场景 2：当天承诺核心流程**
1. 选择日期 2026-09-15
2. 从项目 A 选择任务 A2 加入承诺
3. 验证：当天承诺页显示 A2（来源项目 A）
4. 在当天承诺中标记 A2 完成 → 验证项目详情中 A2 也变为 completed
5. 从承诺中移除 A2 → 验证：承诺页不显示 A2，项目 A 中 A2 仍然存在

**场景 3：数据持久化**
1. 完成场景 1 和 2 的操作
2. 关闭应用
3. 重新启动应用
4. 验证：项目、任务、承诺记录全部保留，状态一致

**场景 4：跨项目承诺**
1. 创建项目 B，创建任务 B1
2. 在同一天承诺中加入 A2 和 B1
3. 验证：承诺页按项目分组显示 A2（来自 A）和 B1（来自 B）

### 验收方式

- 每个场景编写自动化测试脚本（如 Playwright 或 Cypress）
- 手动执行场景清单，逐项确认
- 检查 SQLite 数据库文件，验证数据完整性

## 关键风险、假设和待决定项

### 关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| "当天承诺"模型复杂度 | 承诺与任务的双向同步可能引入一致性问题 | 采用事务性操作；承诺完成直接更新任务状态 |
| 跨日期承诺管理 | 同一任务可能出现在多天承诺中，状态冲突 | 承诺仅引用任务，任务状态以最新操作为准 |
| 本地文件损坏 | 数据丢失 | 实现自动备份（复制 SQLite 文件） |

### 假设

| 假设 | 依据 |
|------|------|
| 用户是技术开发者，可接受命令行或桌面应用安装 | 项目目标描述 |
| 任务无子任务需求（首轮简化） | `ordinary-input.md` 未提及子任务 |
| 单用户场景，无并发问题 | 明确排除团队协作 |
| 日期精度到天，不含时间块 | 范围明确排除手动时间块 |
| 当天承诺与任务是独立实体，非任务的日期属性 | 满足"移除承诺不删任务"需求 |

### 待决定项

| 待决定项 | 影响范围 | 建议 |
|----------|----------|------|
| 桌面框架选型（Tauri vs Electron vs 纯 Web） | 开发复杂度、打包体积 | 原型阶段可用纯 Web（IndexedDB），后期迁移 Tauri |
| UI 组件库选择 | 开发速度、视觉一致性 | 根据前端框架选择对应的成熟组件库 |
| 任务是否需要优先级/标签属性 | 数据模型、UI | 首轮可不实现，列为后续扩展 |
| 是否需要任务描述（多行文本） | 数据模型 | 建议首轮包含，成本低且实用 |
| 本地数据文件存放位置 | 用户体验、备份 | 使用应用标准数据目录（如 `~/.config/应用名/`） |
