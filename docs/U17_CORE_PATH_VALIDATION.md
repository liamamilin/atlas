# U17 核心主线验证

日期：2026-09-13
状态：结构与前置条件已收口；最小真实开发冒烟待执行
依据：[产品设计](U17_DESIGN.md) · [开发规划](U17_DEVELOPMENT_PLAN.md) · [M5 试点计划](U17_M5_PILOT_PLAN.md)

## 核心路径

当前核心路径定义为：

> 搜索或浏览类型 → 阅读类型叶子 → 创建或选择项目 → 固定资料 → 确认需求与当前文档 → 接受工作区基线 → 建立迭代和任务 → OpenCode 在隔离副本执行 → 核对并应用结果 → 独立产品验收 → 完成迭代。

效果对照、价值评分、多类型复杂组合、多引擎和云端执行不作为这条路径可用的前置条件。

## 已收口能力

- 类型叶子提供“基于此类型创建项目”；名称和目标预填，创建时固定完整类型正文并直接进入项目工作区。
- 已有当前项目时可把当前类型加入项目后继续开发；重复固定同一版本不会阻断进入项目。
- 新想法创建时实际建立工作区目录；已有项目入口拒绝不存在的目录。
- 类型起点固定失败时，项目记录及本次新建的工作区一并回滚，不留下半创建状态。
- 项目路径显示工作区确认、结果应用、产品验收和迭代完成，并按当前或最近一次迭代计算状态，不使用其他历史迭代误报新一轮进度。
- 活动迭代要求至少一份当前文档、至少一条用户确认的本版需求和一份已接受工作区基线。页面在提交前列出缺失项，服务端执行同样约束。
- 产品验收失败后可启动新的执行，也可在补充证据后重新确认；通过或免验仍会关闭任务，迭代只有在所有任务通过或免验后才能完成。
- 删除项目需要项目 ID 确认；活动生成或执行会阻止删除；Atlas 项目记录删除后，本地工作区和源码保留。

## 验证结果

- Python 离线回归：99 项通过。
- TypeScript：`npm run typecheck` 通过。
- Python 语法检查与 `git diff --check` 通过。
- 浏览器验证显示完整项目路径：收集资料、确认需求、形成文档、确认工作区、建立迭代、执行改动、应用结果、产品验收、完成迭代。
- 在没有基线、当前文档和确认需求的真实项目页，迭代按钮保持禁用，并一次列出三项缺失条件。

新增或扩展的测试覆盖：默认及指定新想法工作区创建、已有项目无效目录拒绝、起点资料失败的项目与目录回滚、空文档/空需求/无基线迭代拒绝、验收失败后的执行重试，以及既有执行和项目删除回归。

## 下一步

下一项只做一个最小真实开发冒烟，不同时进行普通生成效果比较。冒烟必须保存项目 ID、来源版本、需求和文档版本、基线、迭代、任务、执行、应用、验证命令、验收和完成状态。

冒烟中发现的问题按以下顺序处理：

1. 阻断连续完成或造成错误状态的缺陷。
2. 可能混用项目、覆盖外部变化、越界写入或误报验收的安全边界。
3. 用户不知道下一步或只能在执行阶段才看到的前置条件。
4. 布局、操作效率和扩展能力。

前三类修复并从头复验后，才开始 M5 的普通生成对照和三个评估案例。
