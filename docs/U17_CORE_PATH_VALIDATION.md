## 核心路径

当前核心路径定义为：

> 搜索或浏览类型 → 阅读类型叶子 → 创建或选择项目 → 固定资料 → 确认需求与当前文档 → 接受工作区基线 → 建立迭代和任务 → OpenCode 在隔离副本执行 → 核对并应用结果 → 独立产品验收 → 完成迭代。

效果对照、价值评分、多类型复杂组合、多引擎和云端执行不作为这条路径可用的前置条件。

## 已收口能力

- 类型叶子提供“基于此类型创建项目”；名称和目标预填，创建时固定完整类型正文并直接进入项目工作区。
- 已有当前项目时可把当前类型加入项目后继续开发；重复固定同一版本不会阻断进入项目。
- 新想法创建时实际建立工作区目录；已有项目入口拒绝不存在的目录。
- 类型起点固定失败时，项目记录及本次新建的工作区一并回滚，不留下半创建状态。
- 项目路径显示工作区确认、结果应用、产品验收和迭代完成，并按当前或最近一次迭代计算状态，不使用其他历史迭代误报新一轮进度。
- 活动迭代要求至少一份当前文档、至少一条用户确认的本版需求和一份已接受工作区基线。页面在提交前列出缺失项，服务端执行同样约束。
- 产品验收失败后可启动新的执行，也可在补充证据后重新确认；通过或免验仍会关闭任务，迭代只有在所有任务通过或免验后才能完成。
- 删除项目需要项目 ID 确认；活动生成或执行会阻止删除；Atlas 项目记录删除后，本地工作区和源码保留。

## 冒烟发现与修复

| 发现 | 影响 | 修复与复验 |
|---|---|---|
| 嵌套项目工作区读取了父仓库全部 `git status` | 执行隔离副本的运行文件被误判为源工作区变化，首次应用被错误阻止 | Git 状态改为仅检查项目路径 `-- .`；新增父仓库兄弟变化回归；后续两轮执行结果均首次应用成功 |
| 页面打开后新增需求和文档时，迭代表单的默认选择仍保留初始空状态 | 按钮可点，但提交后才由服务端拒绝“缺少已确认需求” | 选项集变化时同步默认勾选，且按钮直接校验实际选中集合；最终复验中需求和文档自动勾选，创建迭代首次成功 |
| 验收默认文本把 agent 额外命令也称为“固定验证命令” | 可能夸大事先约定的验证证据 | 验证汇总现在仅统计任务预先固定的命令；额外命令仍保留在完整工具记录中；新增计划外成功/失败命令回归 |
| 全部九步骤完成后仍显示“走到产品验收” | 完成状态文案落后一步 | 改为“当前迭代已完成”，浏览器最终页已确认 |
