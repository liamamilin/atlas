# U17 M3 项目工作区基线验证

日期：2026-09-13  
状态：项目接入、证据分层和外部变化核对已完成；目标驱动的改进方案仍在开发。  
依据：[产品设计](U17_DESIGN.md) · [开发规划](U17_DEVELOPMENT_PLAN.md) · [M2 生成验证](U17_M2_GENERATION_VALIDATION.md)

## 1. 本轮完成范围

U17 现在可以为已有项目或 U17 新建项目的本地工作区建立不可变基线。基线由 Atlas 保存，不依赖 OpenCode 的会话或 diff：

- 扫描全部常规文件和符号链接，记录内容 SHA-256、大小、读取错误及忽略目录。
- 读取 README、`docs/` 文档、工程清单和用户指定重点路径内的受支持文本；记录读取文件、部分读取、跳过原因及上限。
- 以只读 Git 命令记录仓库根、分支、HEAD 和未提交路径；非 Git 目录仍可用文件指纹建立基线。
- 现状报告分别列出“文档描述（尚未验证）”“代码线索（不等于运行事实）”“运行验证”和“未知与未检查范围”。首次接入不会执行项目命令，因此运行验证明确为空。
- 变化检查只生成临时比较结果，不修改已接受基线。用户审阅后才能采用当前状态，并保留所有旧基线。

## 2. 变化范围与并发保护

比较使用上一份基线的读取范围：

- 已读取文件或重点路径内的变化进入 `reviewed_scope_changes`，提示复核相关现状。
- 其余变化进入 `outside_review_scope_changes`。这只表示本次没有读取正文，不会把文件判定为无关，也不会强制重做整个项目分析。
- Git 仓库边界、分支或 HEAD 变化会提示重点复核。单纯的 Git dirty 列表变化作为补充信号，不越过文件范围判定。
- 快照读取出错时明确标记比较受限。

采用操作同时提交两项预期值：已审阅的基线 ID 和检查结果的工作区内容指纹。如果其他进程在检查后又修改了文件、Git 状态或基线，服务返回冲突，要求重新检查；未审阅的新状态不会被悄悄接受。

## 3. 安全与读取边界

- 重点路径必须是工作区内真实存在的相对路径，最多 20 个；拒绝绝对路径和 `..` 越界。
- 快照不跟随符号链接，不读取 `.git`、`.venv`、`node_modules`、`dist` 等默认忽略目录。
- 正文最多读取 80 个文件、总计 400,000 字符、单文件 60,000 字符。文件内容以流式限量读取，不会为了判断截断而先把大文件全部载入内存。
- 基线只形成观察证据，不执行测试、构建或项目脚本，也不把文档声称的能力转换为运行事实。

## 4. 接口与界面

本地项目 API 新增：

- `GET /api/projects/<id>/workspace-baselines`：列出不可变基线摘要。
- `GET /api/projects/<id>/workspace-baselines/<snapshot-id>`：读取一份完整基线记录。
- `POST /api/projects/<id>/workspace-baselines`，`action=capture`：建立或采用基线。
- `POST /api/projects/<id>/workspace-baselines`，`action=check`：对已接受基线做只读变化检查。

项目页新增“项目工作区基线”区域，显示文件和正文读取数量、Git 状态、内容指纹、证据报告、重点路径以及历史数量。变化结果分别列出重点范围和当前审阅范围外的路径，采用按钮只在完成检查后出现。该区域不按 `new` / `existing` 模式分叉，因此 U17 生成后的项目继续使用同一套迭代基线。

## 5. 自动验证

`python3 -m unittest application-atlas-production-pack/tests/test_reliability.py`：68 项通过。新增覆盖包括：

- 文档、清单和重点代码的读取范围及四类证据输出。
- 重点范围与范围外变化分流，变化检查不创建新基线。
- 审阅后采用、不可变历史、陈旧基线冲突和检查后再次变化冲突。
- 重点路径越界和不存在路径拒绝。
- HTTP 建立、检查、列表、采用及冲突状态。

`npm run typecheck` 和 `npm run build` 均通过。Vite 仍报告现有的单个主包超过 500 kB 提示，不影响本轮功能。

## 6. 浏览器实测

在隔离数据库和临时 Git 项目上实际打开项目页完成以下流程：

1. 输入重点路径 `src` 并建立基线。页面显示 5 个文件、4 个正文读取、`main` 分支和 HEAD；报告包含两条文档描述、代码线索、空的运行验证及 1 个未读取文件。
2. 同时修改 `src/app.ts` 与 `assets/logo.bin` 后检查。页面把前者列入“已读取或重点范围内”，后者列入“当前审阅范围外”，状态为“重点范围需要复核”。
3. 采用后生成第二份不可变基线，最新记录显示相同 HEAD 和 dirty 状态，历史数量为 2。
4. 仅再次修改 `assets/logo.bin` 后检查。页面显示“重点范围未变化”，仍保留范围外路径和“不据此断言无关”的说明。

API 日志对应一次初始建立、两次只读检查和一次采用，HTTP 状态依次为 201、200、201、200。测试页面、服务、数据库及临时 Git 项目随后已清理。
