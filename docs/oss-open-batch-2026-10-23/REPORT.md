# 开放批量工作流与三个叶子剩余队列验收

日期：2026-10-23。本次按“先完成，再完善”调整工作流，仅守住真实仓库、实际来源、明确不确定性和不误标许可证的底线。实际采集范围仍为阅读器、图表应用、密码管理器，没有自动扩展到其他叶子。

## 已完成的流程

- 取消三个试点叶子的白名单；现有 1,805 个叶子均可指定，未知叶子和路径穿越仍拒绝。
- 取消最低 Stars 要求；支持查询分页。Stars 可以决定排序，不决定是否收录。
- CLI 与页面均可指定多个叶子。每次任务固定有限候选集，自动续批，单项失败记录后跳过，全部目标处理后结束。
- 默认每批 8 个是执行单元，不是每个叶子的完成上限；新版流程也没有旧版每叶子模型调用上限。
- 每项完成即保存 SQLite 和本机 JSON 进度。重启同一任务只处理未完成目标，已结束任务的恢复操作不重新采集。
- README、许可证或模型整理不完整时，先依据已验证的公开仓库资料生成初步卡片，显示待补充字段；没有场景关联也能浏览、搜索和收藏。
- 支持应用、库、资源和集合，标明类型；直接用途、条件用途及待核实推断分开显示。争议能力保留为推断，不因允许收录而升级成事实。
- 原模板工厂仍在历史入口；个人知识管理的事实、关联、核验时间和收藏保留。

## 核心底线与资料复核

- 新版先核验仓库 numeric ID 和公开状态，之后才读取和发送官方资料。模型不能添加候选之外的仓库。
- 146 个项目记录完成来源绑定核对，264 处非空摘录核对了实际内容；许可证文件存在时也检查内容摘要对应真实缓存。这验证出处，不等同于逐项部署或人工证明全部模型概述。
- 未附逐字摘录的内容标明“资料概述”；推断标“待核实”。没有原文支持的引文丢弃，缺项使用公开元数据或待补充说明，不能虚构补齐。
- Bitwarden Android 保留为项目卡片；依赖说明不能证明实际功能实现，相关功能和场景标为待核实推断。
- Quick RSS 保留初步记录及“未确认应用实现”的已有复核说明，有争议的功能和关联标为待核实，类型保持待确认。
- 旧版排除的库、图表资源、密码生成器等重新读取后可收录，避免把“不是完整独立应用”当作排除底线。
- GitHub 返回空文件、符号链接或 `encoding:none` 时，改为标注缺少可读文本，不再因此整项拒收。对历史场景缺少内嵌 `leaf` 字段的情况完成兼容与快照往返验证。

逐项目程序核对见 [SOURCE_INTEGRITY.json](SOURCE_INTEGRITY.json)，重点纠正见 [MANUAL_REVIEW.json](MANUAL_REVIEW.json)。

## 不需要人工逐批驱动

实际在主任务完成 36 个目标后终止采集进程，再用相同 job ID 恢复。已完成目标保留，继续其余目标，最终达到 133/133。记录见 [INTERRUPT.json](INTERRUPT.json) 和 [jobs/](jobs/)。补跑任务达到 14/14，见 [RETRY_RESULT.json](RETRY_RESULT.json)。

自动续批由程序执行，不依赖对话模型持续操作。页面启动的后台任务由 Atlas API 进程执行，CLI 任务由 CLI 进程执行；进程停止时进度保留，恢复需要点击继续或运行 `resume`。当前没有另加系统级自动重启服务。

首轮验收期间修正了解析、缺文本和快照兼容问题，因此首次实跑包含人工检查与修复；这些不是日常运行所需的人工逐批步骤。每个任务都有有限范围，失败不会无限重试。

## 操作

在 [项目库](http://127.0.0.1:5188/discover) 展开“批量采集”，加入叶子后启动。可以选择仅处理已有候选，避免本次扩大搜索。

```sh
python3 application-atlas-production-pack/oss_batch.py start \
  --leaves feed-reader diagramming-application password-manager --existing-only

python3 application-atlas-production-pack/oss_batch.py resume --job batch_<id>
```

完整参数与接口见 [操作说明](../OSS_CATALOG.md)。本轮三个叶子的既有队列已完成；其他叶子具备启动能力，留待本轮验收后按指定范围运行。
