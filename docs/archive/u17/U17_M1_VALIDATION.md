## 已实现流程

M1 已形成可操作的“项目 → 搜索 → 阅读 → 收藏 → 复核”闭环：

1. 用户创建新想法或已有项目并设为当前项目。首次创建后直接选中并进入工作区，不依赖列表刷新时序；无效项目 ID 通过项目读取接口核对。类型叶子可作为创建入口，预填名称和目标，并在创建时固定完整类型正文。新想法的工作区目录会同步建立，已有项目必须指向已存在目录。
2. 搜索页在同一结果中展示软件类型和真实应用。类型使用名称、中文名、slug 与定义摘要匹配；应用使用名称、厂商、简介、任务标签和归属类型匹配。
3. 类型页的正式资料阅读器直接调用来源 API，可在类型正文与研究笔记之间切换，并读取全文或一个标题及其全部子章节。界面显示文档行数、字符数、目录和来源指纹。
4. 类型全文或章节由服务端重新读取后收藏，客户端不能自行提交摘录或来源版本。应用可收藏当前目录记录，记录明确说明只有名称、厂商、简介、任务标签和 Atlas 归类，不能被当作深度产品分析。
5. 项目资料集显示固定摘录、收藏版本、当前版本、阅读状态和借鉴点/备注。更新状态时只合并该条记录，不刷新整表覆盖尚未保存的备注；用户可显式刷新版本状态。

网页无匹配结果时，如果已有当前项目，会提供返回项目继续记录调研和决定的入口。无匹配不是项目自动否决条件。

项目工作台提供删除入口。删除前明确说明会移除项目的 Atlas 文档、需求和执行记录，同时保留本地工作区和源码；请求必须用项目 ID 显式确认。存在活动生成或 `queued`、`running`、`waiting_permission`、`waiting_input` 执行时返回冲突，不会部分删除。

## 数据与接口边界

新增项目资料接口：

- `GET /api/projects/<id>/references`：返回收藏记录，并比较 Atlas 正式来源的当前版本。
- `POST /api/projects/<id>/references`：接受 `kind=application|research|app`、slug、可选章节和备注。类型资料从正式 Markdown 读取；应用目录资料从 `mvp_apps.json` 与 `mvp_apps_classified.json` 构建。
- `PATCH /api/projects/<id>/references/<reference-id>`：更新备注或 `unread/read/reviewed` 状态。

收藏记录固定 `source_kind`、`source_ref`、`source_version`、章节定位与完整摘录。同一项目、来源、版本和范围只能收藏一次。来源改变时旧摘录不被重写；`stale` 只用于 Atlas 可跟踪来源，用户访谈等外部资料不会因无法自动检查而被误报为过期。

应用目录记录使用逐条规范化 JSON 计算版本，并把资料深度写进摘录。分类或目录字段变化会产生新版本；当前设计不会据此生成不存在的产品功能细节。

## 实际验证

真实 HTTP 冒烟测试在隔离项目库完成：

- 创建项目返回 201。
- 收藏 `task-management-application#core-model` 返回 201，保存完整 4,399 字符章节摘录和正式来源 SHA-256。
- 再次查询返回 `source_available=true`、收藏版本等于当前版本、`stale=false`。
- PATCH 后备注持久化，阅读状态变为 `reviewed`。

浏览器实际页面验证覆盖：

- 搜索 `Notion` 得到 0 个软件类型和 1 个真实应用，并显示目录级资料说明与归属类型入口。
- 创建第一个项目后立即显示“当前项目”，复现并修复了旧项目列表短暂清空选择的竞态。
- 类型页切换到 `Core Model`，正文只包含该章节及子章节；填写借鉴点后收藏成功。
- 项目页显示固定章节摘录、收藏版/当前版、阅读状态和备注；备注保存后刷新仍保留。
- 收藏 Notion 目录资料后，项目页显示 `应用目录资料`、固定摘录和匹配的当前版本。
- 从 `task-management-application` 类型叶子进入项目工作台，页面正确显示项目起点，预填名称和目标；创建临时项目后直接进入项目工作区，并显示 1 条已固定的完整类型正文。
- 项目列表显示删除入口和“保留本地工作区和源码”的确认说明；通过本地 API 删除临时验收项目后，返回 `workspace_preserved=true`，其 1 条固定资料被删除，原有用户项目仍保留。

临时 API、Vite 服务和测试项目库已停止并清理。页面验证没有调用外部模型。

## 当前限制与下一阶段

真实应用只有 33 条目录记录，没有逐产品深度文档。M1 如实显示并保存现有深度；需要某个产品的详细机制时，应在项目调研中定向补充来源，不能把目录简介扩写成事实。

网页搜索是本地确定性文本匹配；现有 MCP 提供语义检索。是否把语义搜索加入网页，应根据真实查询失败案例决定。

M2 将在已收藏并复核的资料上形成分析、需求、交互、技术方案、开发规划和验收文档，区分 AI 推荐与用户确认，并将每条采用或排除理由关联到固定资料版本。
