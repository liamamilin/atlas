## M0-01：完整资料与引用链路

状态：核心读取能力已实现；界面接入留在 M1。

新增 `atlas_sources.py`，直接读取正式 Markdown 内容真相源，不以 SQLite 摘要字段作为生成证据。能力包括：

- 查询一个类型现有的 application 与 research 文档、全文长度、行数、SHA-256 指纹和标题目录。
- 按标题读取该标题及所有子章节，在下一个同级或更高层级标题前停止。
- 按字符偏移分页，返回 `complete` 和 `next_offset`，不会静默截断。
- 返回本次内容的起止行号、整篇文档指纹和选择范围长度。
- 拒绝未知资料类型、路径型 slug、负偏移及越界偏移。

接入位置：

- 本地 API：`GET /api/sources/<slug>`。
- 本地 API：`GET /api/sources/<kind>/<slug>?section=<outline-id>&offset=0&limit=12000`。
- MCP：`get_atlas_source_manifest`、`read_atlas_source`。

实际样例：读取 `raster-image-editor` 的 research `boundary-findings`，返回 2,332 字符，从原文第 256 行开始，包含嵌套的 `vs Digital Painting Application` 等章节，并在 `Uncertainties` 前停止。结果标记 `complete: true`。这覆盖了此前结构化导出未保留嵌套边界正文的问题。

验证：4 个新增单元测试覆盖双资料清单、嵌套章节边界、分页拼接和非法请求。项目完整离线回归 22 项通过，三个相关 Python 模块编译通过。

HTTP 冒烟测试通过：临时启动本地 API 后，manifest 返回 application/research 两类资料及各自目录；章节接口返回 `boundary-findings` 的完整 2,332 字符、起始行 256 和 `complete: true`。临时服务测试后已停止。

尚未包含：应用实例深度资料的新增生产、前端阅读界面、项目资料收藏和引用版本持久化。这些分别属于现有资料限制、M1 和后续项目存储任务。

## M0-02：OpenCode 接入探测

状态：核心链路验证完成；失败任务、引擎提问等边界继续随 M4 集成验证。

环境：本机 OpenCode `1.18.30`，使用 `opencode serve --pure` 在 `/private/tmp` 启动临时服务。服务仍会读取本机 OpenCode 配置；`--pure` 不能理解为完全不读取配置或完全隔离。

已观察：

| 能力 | 结果 | 证据 |
|---|---|---|
| 健康与版本 | 通过 | `/global/health` 返回 healthy 及 1.18.30 |
| 创建、读取会话 | 通过 | 临时会话绑定 `/private/tmp`，能读取 ID、目录、用量和时间 |
| 会话状态 | 通过基础接口 | 无运行任务时 `/session/status` 返回空对象 |
| 停止会话 | 通过 | 对临时会话调用 abort 返回 true |
| 文件差异 | 通过基础接口 | 未执行任务时 diff 返回空数组；有实际修改时的归属仍待验证 |
| 事件订阅 | 通过连接 | SSE 返回 `server.connected`；任务事件顺序与断线续接仍待验证 |
| 清理 | 通过 | 临时会话删除返回 true，服务已停止 |

首次在受限环境启动失败，因为 OpenCode 要写入用户目录中的日志。经授权在本机环境启动后成功。这说明实际集成需要明确运行权限、日志位置和隔离边界，不能仅凭 `--pure` 假设服务是无状态进程。

仍需验证：

- 只读分析、文档写入和小型代码修改各一次，分别记录请求、事件、文件差异和验证结果。
- 权限请求与用户输入事件的实际结构。
- 客户端断开后重连事件流，以及服务进程重启后的会话可见性。
- 取消执行时已发生文件修改的保留与归属。
- 失败任务的消息、产物、退出状态及用量信息。
- 会话不可访问时，从 Atlas 持久化记录生成任务交接材料。

这些结果确定后再固定 U17 的引擎适配接口。公开 API 存在只证明接入可行，不代表长期恢复和替换能力已经通过。

### 实际任务验证

随后在独立临时目录中使用 OpenCode `1.18.30` 和 `opencode/big-pickle` 执行了三类任务。模型报告费用为 0；这只记录本次模型与结果，不推断其他模型的费用。

| 任务 | 结果 | 独立核对 |
|---|---|---|
| 读取 README 与 Python 文件 | 完成，使用 glob/read 工具，未修改文件 | 回答与原文一致；会话 summary 为 0 个文件变化 |
| 新建 NOTES.md | 完成，内容符合要求 | 文件实际存在且正文正确；会话 `diff` 仍返回空数组 |
| 修改已有代码并补测试 | 两个文件修改完成；运行测试时等待 Bash 权限，任务保持 busy | 停止任务后文件仍保留；独立运行 3 项测试全部通过 |

关键发现：

- 权限请求是必须处理的一等状态。本次 Bash 工具产生 `per_...` 请求，服务日志显示 action=ask；同步消息请求持续等待，直到调用 abort。界面不能把它长期显示为普通“运行中”。
- 中断返回 `MessageAbortedError`，正在等待的 Bash tool part 标记 `status: error`、`interrupted: true`；此前完成的文件编辑没有回滚。
- `GET /session/<id>/diff` 在新文件和两个已有文件实际修改后仍返回空数组；具体 edit message part 内含 `filediff`。因此 Atlas 必须保存自己的文件基线并核对实际工作区，message part 可作为补充证据。
- 停止服务后在同一目录重启，会话、消息、编辑详情和中断错误仍能按原 session ID 读取，当前状态恢复为 idle。
- SSE 能提供工具、消息、busy/idle、permission 等细粒度事件，但全局流包含大量插件与 catalog 事件。重连只观察到新的 `server.connected`，没有历史事件重放；重连后必须调用状态、消息、权限和文件基线进行对账。

已新增 `opencode_client.py` 作为首个适配模块：

- 仅接受本机 HTTP 地址，并为请求绑定项目目录。
- 支持健康检查、会话创建/读取/删除、消息、状态、停止、权限查询与回复、引擎差异和 SSE 解析。
- 提供 `reconcile()`，重连后重新读取会话、状态、最近消息、待处理权限和引擎差异。
- 明确声明空的引擎 diff 不能证明文件未变化；文件基线由 Atlas 层负责。

适配器单元测试覆盖目录作用域、同步与异步消息、重连对账、当前非弃用权限回复接口、SSE 会话过滤及本地地址/标识校验。适配器已连接重启后的真实服务完成一次 `reconcile()`。

本次创建的 OpenCode 会话、服务与临时样例目录均已清理。

### 异步、权限回复与断线恢复

又在独立临时目录中执行了完整的非阻塞链路：

1. `prompt_async` 提交任务后立即返回 HTTP 204，不占用请求连接。
2. 会话状态变为 `busy`，`GET /permission` 返回与该会话、assistant message 和 Bash call 关联的 `per_...` 请求，包含待执行命令和可持久授权模式。
3. 通过当前接口 `POST /permission/<request-id>/reply` 回复 `once` 后，原任务继续执行；Bash part 返回退出码 0 和输出 `42`，随后产生 `finish: stop` 的最终 assistant message，待授权列表清空，会话回到 idle。
4. SSE 客户端主动超时断开时，服务和会话保持存在；重新连接后通过会话、状态、消息和权限快照完整恢复到已完成状态。事件流仍只作为低延迟通知，不作为可重放状态库。

新增 `execution_state.py`，把引擎记录投影为 U17 稳定状态：`queued`、`running`、`waiting_permission`、`waiting_input`、`completed`、`failed`、`stopped`、`unknown`。待授权和待输入优先于引擎的笼统 `busy`；`idle` 本身不等于完成，只有绑定到当前 Atlas 任务的 completed + `finish: stop` 消息才投影为 `completed`；`MessageAbortedError` 与一般失败分开处理。投影同时保留用于判断的消息、权限、问题或错误标识。

5 个状态投影测试覆盖权限优先级、严格完成条件、空闲但未完成、中止/失败区分以及其他任务权限隔离。加上适配、资料、快照及既有回归，完整离线测试现为 37 项通过。

M0-02 的首个执行后端核心链路已经足以固定适配边界。尚未真实观察的引擎提问结构、provider 失败结构和长期运行资源限制，保留为 M4 集成期边界测试，不阻塞 M0-04 项目持久化工作。

## M0-04：Atlas 自有项目状态与文件基线

状态：首版持久化边界和核心存储已实现；需求/决策对象及大仓库优化继续补齐。

由于真实验证证明引擎 `diff` 可能遗漏已发生的文件修改，新增 `workspace_snapshot.py`：

- 对工作区普通文件做 SHA-256 指纹，不依赖修改时间判断内容变化。
- 不跟随符号链接，单独记录其目标，防止读取工作区外内容。
- 默认跳过 `.git`、依赖、虚拟环境、缓存和构建产物目录。
- 比较同一工作区的两个快照，明确返回 added、removed、modified 和读取错误。
- 拒绝比较不同根目录或未知 schema 的快照。

新增 4 个单元测试，覆盖新增/删除/修改、仅时间变化、符号链接和根目录不一致。后续需要把执行前后快照原子写入 Atlas 项目数据，并定义大仓库的增量与排除策略。

新增 `project_store.py`，确定首版持久化边界：

- 项目资产使用独立的 `projects/atlas-projects.sqlite`，可由 `ATLAS_PROJECT_STORE` 改址；它不写入、也不随导出流程重建 `atlas/atlas.sqlite` 语料库。
- Atlas 自己生成 `prj_`、`ref_`、`req_`、`dec_`、`doc_`、`dver_`、`tsk_`、`snap_`、`exe_` 标识；OpenCode session/message ID 只保存在 execution 的适配字段。
- 参考资料保存来源类型、定位、版本/指纹、摘录、备注和阅读状态，并拒绝跨项目引用。需求分别保存 AI 推荐范围与用户确认范围；推荐为 `current` 不会自动成为确认，绑定未确认需求的任务不能启动 execution。项目决定只通过显式记录入口写入。
- 文档更新始终新增不可变版本，并可用 `expected_current_version` 拒绝基于旧版本的覆盖；任务绑定具体文档版本，而不是浮动的“最新文档”。
- 工作区基线可绑定项目和任务，执行记录保存执行前后快照、归一化状态和原始判断证据。
- execution 完成与产品验收分开存储。任务在 agent 返回 `completed` 后仍保持 `acceptance_status: pending`，只有附带验收证据的独立记录才能变为 passed/failed；waived 需要显式记录。
- 所有复合写入使用 SQLite `BEGIN IMMEDIATE` 事务，外键在每个连接启用；失败时整笔回滚。

9 个项目存储与交接测试覆盖跨进程重开、文档版本冲突、跨项目引用拒绝、推荐与确认分离、快照/执行关联、事务回滚，以及“执行完成不等于验收通过”。完整离线回归现为 46 项通过。

仍需补充：迭代关系；大仓库快照需要在真实项目上测量后再决定增量索引或外置清单，当前不预设复杂方案。

## M0-05：不依赖旧会话的任务交接

状态：核心交接包与离线校验已实现。

新增 `handoff_bundle.py`，只从 Atlas 项目库生成 JSON 真相包和适合人工阅读的 Markdown：

- 包含项目目标与工作区、任务目标、确认需求、项目决定、固定文档版本和正文指纹、执行前后工作区快照、归一化执行证据、产品验收状态及缺失证据。
- 引擎 session ID 可作为历史关联保留，但 `old_engine_session_required` 固定为 false；构建和校验过程都不会调用旧引擎。
- 对 stopped/failed/running/unknown 状态明确要求先核对当前工作区，禁止盲目重放旧操作；执行完成但尚未验收时，下一步是核对基线并运行验收。
- 离线校验会检查项目/任务归属、任务输入版本顺序、文档和工作区清单指纹、execution 的任务及快照引用，以及旧会话依赖标记。篡改正文会使校验失败。
- JSON 与 Markdown 使用原子写入，避免交接文件只生成一半。

测试模拟一个旧 OpenCode session 已不可用的 stopped 任务，仅凭 Atlas 记录成功构建并校验交接包；包内保留来源、已确认需求、项目决定和用户文档内容，并指出缺少执行后快照和产品验收证据。完整离线回归为 46 项通过。

## M0-04 补充：迭代边界

项目库 schema 升级为 v2，新增 `itr_` 迭代对象：

- 迭代固定输入文档版本和已确认的本版需求；后续产生新文档版本不会静默改变已开始迭代。
- 一个项目同时只能有一个 active 迭代，任务只能使用该迭代范围内的文档与需求。
- 全部迭代任务取得产品验收 passed/waived 后才能完成迭代；agent 执行结束仍不足以完成迭代。
- v1 数据库可原地升级，已有任务保留并以无迭代关联状态继续读取。
- 交接包同步携带和校验迭代关系。

大仓库增量快照继续归入 M3 的真实项目测量；provider 失败和引擎提问结构归入 M4 边界测试。这些不再阻塞项目工作台开发。
