# 决策与默认值

## D01 · 保存遇到已存在的相同 URL 时应如何处理？

推荐默认：显式提示“可能已存在”并保留一个显式“仍然保存”动作，允许用户确认后保存为另一条记录；比较键仅做最小规范化（scheme/host 小写、去默认端口、去路径末尾多余斜杠，保留 query 与 fragment），原因是不自动丢弃用户数据、可逆。

When to ask / 询问条件: 当用户明确反馈希望自动合并重复项，或希望默认直接拒绝重复保存时。

影响保存流程的交互与数据完整性；变更会影响已有库中重复记录的处理预期。

proposed

## D02 · P0 是否由服务端自动抓取网页标题等元数据？

推荐默认不抓取，标题仅取用户输入或回退为 URL；原因是避免 SSRF、超时、反爬与响应体积等失败模式，并保持仅回环、无后台外发。

When to ask / 询问条件: 当用户明确要求自动标题并接受服务端对目标站点发起请求时，再引入并同时加内网拦截、超时与体积上限。

决定是否新增网络依赖与安全防护；关闭时保存流程完全离线可用。

## D03 · 分类的默认落点如何表示？

推荐以 category_id 为 NULL 表示“未分类”并在界面显示为“未分类/以后看看”，不预置可删除实体；原因保证未归类落点始终存在。

When to ask / 询问条件: 当用户希望自定义默认分类名称或希望默认落点可被重命名/删除时。

影响数据模型与列表查询；改动涉及迁移与既有表单默认值。

proposed

## D04 · 备注长度上限与超限行为？

推荐设定一个明确的较大上限并在超限时显式报错且不落库，绝不静默截断；具体数值在实现时按合理长文本取值，不设武断性能阈值。

When to ask / 询问条件: 当实际用户保存超长备注被拒绝并反馈上限过小时，再调整上限或改为无上限存储。

影响验收的负面用例与错误提示文案；决定数据完整性承诺。

proposed

## D05 · 分类删除的语义（后期引入时）？

推荐删除时必须显式二选一：把其中记录移入未分类，或级联删除并要求二次确认，默认前者；原因是避免无提示丢失记录。

When to ask / 询问条件: 当实现分类删除能力时（P0 不实现）。

影响后期阶段的删除交互与数据保留承诺。

proposed

## D06 · 运行栈与部署形态？

推荐默认 Python 3 标准库（http.server + sqlite3）+ 中文浏览器界面，入口 python3 app.py --port PORT --data-dir DIR，仅回环，数据全部在 DIR 下，无应用依赖安装；这是本次试验环境的明确选择，不是类别约束。

When to ask / 询问条件: 当部署环境没有 Python 3，或需要多实例并发、容器编排时，再评估替代栈。

影响开发者入口、依赖与运维方式；替代方案（如 Node/Django 成品）会引入额外依赖或运维成本。

proposed

## D07 · URL 规范化与去重键范围？

推荐仅做最小规范化（trim、scheme/host 小写、去默认端口、去路径末尾多余斜杠），保留 query 与 fragment 作为身份一部分；对 http/https、跟踪参数等变体不做自动合并。

When to ask / 询问条件: 当用户抱怨同一页面因协议或跟踪参数而被视为不同记录时。

影响重复判定与存储；放宽会带来误合并风险。

proposed

## D08 · 是否需要认证？

推荐默认无认证、仅绑定回环；原因单用户本地使用，避免凭证管理。若验收接受认证参数，则仅作用于显式配置的目标，绝不附加到外部导航或夹具，且不记录凭据值。

When to ask / 询问条件: 当需要从本机以外访问或部署到共享主机时，必须先引入认证与传输加密。

影响安全边界与验收参数；不支持的模式必须显式失败为基础设施/不完整，不静默跳过。

proposed

## D09 · 保存后是否提供立即撤销？

推荐 P0 不提供撤销（P0 无删除能力），仅保证保存与归类可逆（可移动）；撤销随回收站阶段一并引入。

When to ask / 询问条件: 当引入删除或用户反馈误存需要即时撤回时。

影响保存成功后的交互与后续阶段设计。

proposed

## D10 · 何时引入导入/导出？

推荐 P0 不做，按后续阶段引入 Netscape HTML/JSON 元数据导出，并明示导入不去重、导出不等于完整备份。

When to ask / 询问条件: 当用户担心数据锁定或需要换机迁移时。

影响数据可携带性与存储锁定的风险敞口。

proposed

## D11 · 如何验证“跨真实进程重启”的持久化？

推荐默认由操作员控制 before/after：用例先经 UI 保存记录与分类，输出停止并重启（python3 app.py --port PORT --data-dir DIR）的步骤，操作员完成后用例再经 UI 读回数据；仅当用例自身以固定 argv（不启用 shell 插值）启动应用并安全持有该子进程时，才可只终止自己启动的 PID 并重新启动。不得执行任意 shell 命令、不得终止无关进程；不得以文件存在或新建 SQLite 连接作为重启证明，也不要求应用暴露内部数据库连接状态。

When to ask / 询问条件: 当运行环境不允许人工介入、且能提供一个仅管理本用例所启动进程的受控重启器时。

影响 A10 的执行方式与判定；未完成的操作员步骤不得记为通过，刷新不得当作重启。
