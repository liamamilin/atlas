# 核心验收执行说明（core verification）

本目录的 `probe.py` 是**验收编排器**，不是目标实现。它只用 Python 标准库，驱动一个已经实现的目标应用（或自己拉起目标进程），并断言可观察的结果。目标实现必须遵守 `arch` 约定的契约：

- 进程监听 `--addr`（probe 默认 `127.0.0.1:8099`）
- 数据目录由 `--data-dir` 或环境变量 `DATA_DIR` 指定，落盘文件为 `<DATA_DIR>/store.json`
- JSON API 前缀 `/api/*`（`/api/health`、`/api/categories`、`/api/expenses`、`/api/expenses?month=YYYY-MM`），UI 在 `/` 与 `/settings`

## 方式一：probe 自己管理进程（推荐，可完整验证 A05）

```bash
python3 probe.py --server-cmd './expense-tracker --addr {ADDR} --data-dir {DATA_DIR}'
```

probe 会依次做：

1. 创建一次性临时目录 `expense-probe-*`（退出时删除；加 `--keep-data` 可保留以便人工查看）
2. 用该目录拉起目标进程，等待 `GET /api/health` 就绪
3. 执行 A01 分类管理、A02 记录支出、A03 修正并立即重算、A04 月份切换与明细回查
4. **停止进程，再用同一目录重新启动**，执行 A05 重开保留（重启前后逐字段比对，并检查落盘文件里 `amount_cents` 均为 JSON 整数、按月求和等于 API 汇总）

退出码：`0` 表示无失败；`1` 表示有失败。每个用例打印 `PASS` / `FAIL` / `NOT_RUN` 与失败原因。

## 方式二：对已在运行的实例

```bash
python3 probe.py --base-url http://127.0.0.1:8099 --allow-write --store-file /path/to/data/store.json
```

- `--allow-write` 是必需的：probe 会创建 `probe-` 前缀的分类并写入 `probe:` 前缀的用途的支出。
- 强烈建议让目标实例本身指向一次性数据目录，避免污染真实数据。probe 不会删除任何既有记录。
- 该模式下 A05 的“进程重启”一段记为 `NOT_RUN`。操作者手动重启目标后，再执行：

```bash
python3 probe.py --base-url http://127.0.0.1:8099 --allow-write --store-file /path/to/data/store.json --phase persist
```

probe 会比对重启后实例返回的分类与各月汇总，和落盘文件里的记录是否一致。

## 单独重跑某个用例

```bash
python3 probe.py --server-cmd './expense-tracker --addr {ADDR} --data-dir {DATA_DIR}' --phase A03
```

## 各用例验证什么

| 用例 | 断言要点 |
| --- | --- |
| A01 | 创建分类 201 且列表含新分类；重复名 409；空名/纯空白/超 20 字符 400；重命名 200 且旧名消失、新名出现；未知旧名 404；重命名到已占用名 409；删除分类 405；被拒调用后列表内容与长度不变 |
| A02 | 5 笔支出 201 且 `id/date/amount_cents/category/note` 逐字段回显、`amount_cents` 为 int；金额 0/负数/浮点 12.5/字符串/缺失、日期 2026-13-01 / 2026-02-30 / 2026-10-5、未知分类、用途 61 字符一律 400；负例后当月总额 4750 分与 3 笔不变 |
| A03 | 改金额后当月总额 5400、分类合计 3000；改分类后分类合计变为 1500/3000；改用途不改变总额；改日期后记录移出 10 月（2400 分）并完整出现在 11 月（3600 分）；重命名分类后 11 月与 9 月的分类汇总改用新名且金额不变；未知 id 404、非法字段 400 且汇总不变 |
| A04 | 10 月总额 2400 分、显示 `24.00`、分类汇总恰好是该月两个分类且每行带 `total_display`、明细只含 10 月记录；9 月 4200 分 1 笔、11 月 3600 分 2 笔；8 月 0 分 / `0.00` / 空数组；月份参数非法或缺失 400；10+20+30 分得 60 分显示 `0.60`，1005+2010 分得 3015 分（无浮点误差）；`/` 与 `/settings` 返回 200 HTML 且含约定的元素 id |
| A05 | 重启前后分类列表与 4 个月汇总、明细逐字段一致；落盘 `store.json` 无浮点金额字段、`amount_cents` 全为整数、无小数点字面量；落盘按月求和等于 API 汇总 |

## 人工操作步骤（probe 无法自动覆盖的部分）

probe 不驱动浏览器。以下由操作者在本机浏览器完成，按 `arch` 第 7 节的 UI 契约核对：

1. 打开 `http://127.0.0.1:8099/`，录入一条支出（金额 `12.34`、任一分类、日期为本月、用途随意），确认“本月合计”显示 `¥12.34`（严格两位小数），分类汇总出现该分类且金额为 `12.34`。
2. 点击“上个月”，确认合计与分类汇总切换到上一个自然月且明细不含本月记录；再点“下个月”回到本月。
3. 在明细行点编辑，把金额改成 `20.00`，确认本月合计立即变为 `¥20.00`、分类汇总同步变化；再把日期改到上个月，确认该记录从本月合计中移除并出现在上月明细，上月合计相应增加。
4. 打开 `/settings` 新建一个分类，再把另一个分类重命名，确认历史支出的归类随之变化、总额不变。
5. 停止并重启目标进程，刷新页面，确认记录、分类与各月汇总与重启前一致。

## 不会发生的事

- probe 只写入自己创建的临时目录（或你显式用 `--data-dir` / `--store-file` 指定的目录），从不删除既有记录、不清空用户数据。
- probe 不安装依赖、不启动数据库、不访问外网、不做任何“通过”声明以外的认证或认证性结论。
- 若目标进程未按契约实现（例如错误码不是 404/409/405，或金额不是整数分），probe 会以 `FAIL` 与具体断言信息报出，而不是静默放过。
