Atlas 全量辅助生产交接包
日期：2026-10-21

这是一份可交给本机 Codex 的执行材料。它没有启动模型、登记预算、创建正式生产任务或改动用户数据库。

如何使用
1. 解压本包，将整个目录交给正在维护 application-atlas 的 Codex 上下文。
2. 发送下方“启动指令”。Codex 先核对当前本地服务和 Git 状态、登记新的作用域授权，再修正和启动全量入口。
3. 不需要在每一个 20 项批次结束后重复授权。查看 PROGRESS、正式运行日志和实际制品覆盖结果即可。

启动指令
请在 Atlas 仓库按附件 CODEX_INSTRUCTION.txt 执行，完成剩余所有有效叶子的辅助模板生产：每个叶子先做一个核心场景，已有可用模板复用。本轮只对该固定全量辅助计划授权新增最多 7,200 次受控 CLI 调用；保留原 99 次及旧 500 次授权历史，不给严格 G1/T08 扩权。若基线仍为 99，本计划完成后的累计最多为 7,299，不额外叠加原剩余 401 次。固定使用 opencode-go/minimax-m3.1-flash-free；模型并发最多 2，每叶子最多 6 次新增调用，先保留所有叶子的首轮预算。按附件记录正式授权，不继承旧三叶子短窗口；若必须设置窗口，使用自首次真实调用起 30 天且恢复不重置。先完成必要的入口、来源分区和 JSON 修复，然后实际启动；每批 20 项自动接续，单项失败保留证据并继续，额度内修订无需逐项询问。不开发全部应用，不恢复严格 G1/T08，保留旧模板、数据和证据。请持续执行到全部有真实结果，或达到明确的全局停止条件；报告必须区分已准备、已启动、已处理、可用、失败和未处理。

文件说明
- CODEX_INSTRUCTION.txt：完整任务、授权草案、实现范围、运行与验收说明。
- atlas-all-leaves-inventory.json：固定源码的 1,805 叶子、18 已覆盖与 1,787 未覆盖清单，以及来源和覆盖证据。
- pending-initial-plan.json：1,787 项初始顺序；前两项是日常支出记录与个人日历。它不是可绕过注册直接执行的正式请求。
- PROPOSED_RUN_SETTINGS.json：本轮拟定参数；必须随用户执行指令经正式机制生效。
- CHECKSUMS.sha256：本包上述文件的 SHA-256 摘要。

范围与预算解释
以 178d8e2d468d515170c1934804aac436b4b67b62 的目录和已提交目录证据为基线。
1,805 - 18 = 1,787。新叶子通常研究、生成、独审各一次，1,787 × 3 = 5,361 次基础估算。
旧 500 额度已用 99，余 401，不能覆盖全量。因此本启动指令明确提出新的 7,200 次有限授权。
7,200 - 5,361 = 1,839 为恢复与修订余量；全局 7,200 优先，不能给每叶子都保证 6 次。
这不是保证全部成功的预测，不是费用报价，也不是“所有叶子都已入队/运行”的证明。
本地可能有尚未进入 GitHub 证据的可用制品，正式范围应先对账，能复用的继续复用。

事实与建议的区别
清单和已覆盖数量来自已读取的固定源码/制品证据。7,200 次、20 项分批、最多 2 并发、条件性 30 天窗口属于本次执行建议与新的授权草案。
原三叶子试产只证明当时一个场景完整通过，不能推导全目录稳定成功率。
全量生产可能跨越本次会话；必须有真实持久任务或明确的本机运行限制，不能仅声称“会在后台继续”。
