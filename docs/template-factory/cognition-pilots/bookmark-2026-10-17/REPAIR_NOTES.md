# 首版修订要求

保持已确认书签场景、公开调研和经济型模型不变。原候选与报告保留。以下是报告驱动的修订，不开发下游应用，不执行生成程序，不发布。不新增企业功能或把可选打磨变成 P0 硬要求。

1. 修复独立审阅指出的架构与程序矛盾：归类 purge 使用明确的 tombstone/软删除策略保持 SQLite 外键完整性；定义完整 trash 条目、源归类被删除时 restore 默认回退、targetCategoryId 缺省/自指/非法值、PATCH 标题的 titleSource、sort/offset/confirm 的统一错误契约。同步 DECISIONS、架构、用例和 README。
2. A10 的超长归类名应确实是 81 个码点，补恰好 80 成功；不要修改产品上限来迎合错误夹具。补已有范围内的重要正负边界：URL 归一与 userinfo/fragment、非法 categoryId、clear/purge 确认、源归类已删恢复、413、标题 500/备注 10000 码点边界、搜索规范化及跨字段假匹配。保持断言真正作用于应用。
3. 人工补充发现：P0 A01 先 POST 分类、A02/夹具检索使用 q，提前依赖 P1/P2；P1 也不得依赖未交付的 P2 查询。逐阶段检查所有准备、断言和清理依赖。保持阶段故事，P0 用默认分类，不要求后续分类创建/搜索/回收站接口；需要隔离夹具时可读基础列表并在本地识别本 run 数据，但绝不能用客户端过滤替代正在验证的服务端搜索断言。P0 尚无删除能力时可明确留下隔离库夹具，不能让必需清理依赖后续阶段，也不能触碰真实个人库。
4. 真实持久化不能靠新 HTTP 客户端证明。让 A02 验证同一专用测试应用的真实进程重启后数据保留：用户/开发 agent 显式提供重启 adapter（例如 JSON argv，通过 shell=false 调用，默认没有命令，必须只用于专用测试实例）。健康接口有进程内稳定、重启后改变的 instanceId；先验证稳定、运行显式 adapter、等待新 instanceId 并读回原记录。缺 adapter/依赖时记录未完成并非零退出；不能跳过后仍全绿、使用假重启或 mock 应用响应。README 说明该前置条件，包本身不授予执行命令权限，本次生产不运行 adapter。
5. 补真实浏览器验收，覆盖各阶段关键用户交互：P0 表单保存、刷新/重开和点击链接；P1 分类/移动/删除二选一确认/回收站恢复；P2 搜索与分类浏览。架构给明确的最小 DOM/交互契约；用 Playwright 对实际目标操作，不 mock 应用 API 或以检查 HTML 替代互动。外部跳转可用受控外部网页夹具并明确范围，但必须观察真实点击的导航 URL。可采用 @playwright/test 1.63.0 作为固定验收工具版本（不是宣称最新）；只写依赖和安装说明，不在本次任务安装或执行。新增真实 UI 用例应进入规范、阶段、能力映射及统一运行入口，缺浏览器依赖不能伪装成功。
6. 执行指南补充：先核对项目和用户决定；实现当前阶段，准备专用目标和必要 adapter，分别运行该阶段 HTTP/浏览器验收，记录真实命令、应用版本、失败与未完成；验收程序自身缺陷只能基于规范和失败证据修正，禁止弱化断言。阶段状态仍未实现，用例仍未运行。导出/备份明确为本次 P0–P2 范围外的具名后续规划，不宣称已具备；不为此扩成新阶段实现任务。
7. 控制改动：保持未变的 helper/runner/依赖接口可复用时使用 file_plan 的 reuse=true；窄修改使用逐文件 replacements，old 必须精确唯一匹配冻结旧文件。大文件按行为组拆分，阶段模块用薄聚合器保留 getCases 等既有接口，避免再次超过输出限制。文件计划要包含新包全部所需文件，不能漏掉复用文件。新增/修订内容与旧文件组合后必须一致，另开独立审阅再判断。
