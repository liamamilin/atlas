# 书签场景：自动认知生产试产

这是工厂自动生成的新候选验证，和此前人工打磨的 `bookmark-personal` 样板及其 P0 应用验证分开记录。

固定资料范围、provider/model 与用户授权见 [scope.json](scope.json)。隔离任务会把该场景复制为本试产库的 r1，原主目录中的 r2 场景及其内容保持不变。所有模型会话使用 `open-design/deepseek-v4.1-flash`，不发布、不执行生成的应用验收程序。

## 过程与可复现入口

- `run_pilot.py`：首次生产驱动；调用付费 provider，已有库时拒绝重复启动。
- `resume_pilot.py`：首次整包回答触及输出长度上限后，在同一任务上改用分文件生产，复用研究检查点；调用 provider。
- `recover_spec.py`：第二次得到完整规范，仅多一个终止括号；复用完整 JSON 对象继续文件生产，规范字段未修改。校正哈希和代码版本见 [校正记录](spec-framing-recovery.json)。此脚本后续文件/审阅仍调用 provider，不能当作免费重放命令随意运行。
- `collect_evidence.py`：只收集本地记录、校验冻结摘要并复制包，使用 `node --check` 检查语法；不调用模型、不执行包内程序。活动任务未结束时拒绝生成最终结果。
- `run_revision.py` / `retry_revision.py`：首版审阅后的修订和恢复；会调用同一付费 provider。保留首版及失败检查点。
- `run_revision_2.py` / `retry_revision_2.py`：依据 v0.1.1 复审的窄修订及定点恢复，要求见 [修订范围](REPAIR_2_NOTES.md)。同样调用 provider，不执行下游验收。驱动拒绝隐式创建重复修订。
- `run_revision_3.py`：浏览器认证头修复的首次计划；模型未遵循复用范围，已取消，原记录保留，不应重跑。
- `run_scoped_revision_3.py`：相同修复以主机 `edit_paths` 固定两个文件，未选中 18 文件逐字复用；会调用 provider 并另开独立静态审阅。要求见 [单点修复](REPAIR_3_NOTES.md)。
- `run_scoped_revision_4.py`：按真实复审修复计数、错误码分歧及已承诺 UI 能力，固定 7 文件，其余 13 文件复用。
- `run_program_revision_5.py`：固定规范（reuse_spec），只修 A30 的本 run 遗留数据基线与自比较；19 文件逐字复用，不调用模型重写规划。会调用一次文件生成并另开独立审阅，仍可能计费。
- `run_design_probe.py`：对 v0.1.5 规范运行一次真实只读预审，未提供程序正文、不生成程序、不创建生产制品，结果为 blocked，见[报告](design-preflight-probe.json)。不是新生产流程或下游应用的全链路通过记录。首次源码哈希在调用后观察，报告已说明；后续驱动在调用前记录源码与提示哈希。已有探针禁止直接重跑，避免重复计费。

实际运行库、固定输入、事件流、原始模型回答、所有失败尝试、检查点、冻结制品与独立审阅报告在忽略目录 `application-atlas-production-pack/atlas/template-factory/cognition-pilots/bookmark-2026-10-17/`。配置和原始流日志不复制进本文档。事件流已脱敏；格式重放保留脱敏内容，摘要指向该留存文本，不恢复凭据。

研究、规范/文件计划、每个文件及审阅各是独立 CLI 会话；文件会话通过固定规范和已完成文件对齐契约。独立审阅另开只读会话，并不会把作者自评或包内声明当作运行结果。报告结果、制品摘要和导出文件以运行结束后的 `result.json` 为准。

用量记录保留全部会话（包含失败/重试）的 `step_finish` token 字段和可见工具调用。缓存/推理等字段可能与其他字段重叠，不能直接当成唯一计费 token；未结束会话可能缺少最终用量。provider 报告 cost=0 不代表免费，不据此估算费用。

## 验证边界

结构及语法通过只说明包可以被读取、引用关系一致、相应程序能解析。认知审阅只对冻结文档和程序做静态判断；没有部署下游应用，也没有运行本包的 P0/P1/P2 用例。不能沿用旧样板的应用通过报告宣布本候选已可运行。
