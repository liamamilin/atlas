# 工程与产品决策记录（P0）

本文件记录本实现的真实默认值、理由、被拒备选、范围外内容与仍未决的人类决策。
普通可逆选择按已声明默认值执行并记录于此；未虚构任何“已被回答”的问题。

## 采用的技术与工程默认值

1. **运行时保持 CPython 3.10 标准库 + SQLite。**
   实现使用 `ThreadingHTTPServer`、`sqlite3`、`hashlib`/`hmac`/`secrets`、`datetime`。
   理由：CONTRACT 与共同运行环境固定标准库与 SQLite，且不允许安装/构建。
   被拒备选：Flask/FastAPI（需安装）、PostgreSQL `EXCLUDE` 约束（引入外部数据库与部署）。
   说明：某些模板提示更新的运行时不改变共同目标运行时。

2. **时段以 UTC epoch 整数存储与比较（D03）。**
   带显式偏移的 ISO8601 解析为 epoch 作为真实时刻；半开区间 `[start,end)`。
   被拒备选：按本地墙钟存储（无法与相邻/重叠语义一致，且跨越夏令时不可靠）。

3. **重叠唯一占用用应用层串行写事务（D02）。**
   每次写入 `BEGIN IMMEDIATE` → 校验 → `SELECT` 重叠 → `INSERT`；命中即 `409`。
   并发下 `busy_timeout` 让写者排队，因此同一设施重叠恰好一笔成功、不同设施互不阻塞。
   被拒备选：数据库排除约束（SQLite 无原生支持）；纯唯一索引（无法表达区间重叠）。

4. **同起点守卫使用仅对 `status='active'` 生效的部分唯一索引。**
   模板 D02 提到 `UNIQUE(resource_id,start_epoch)`；直接的全局唯一索引会让“取消后重新预约
   同一时段”被永久阻塞。改用 `WHERE status='active'` 的部分唯一索引，既保留同起点守卫，
   又允许软取消后重新占用，语义更正确。
   被拒备选：全局唯一索引（与软取消释放时段冲突）。

5. **软取消 + 幂等（D04）。**
   保留行、`status='cancelled'`、记录 `cancelled_at`；重复取消返回同一记录。
   被拒备选：物理删除（破坏历史，与验收冲突）。

6. **认证用标准库口令哈希 + 服务端会话 Cookie（D05）。**
   PBKDF2-HMAC-SHA256 + 随机盐；会话令牌由 `secrets` 生成并存库；Cookie 设置
   `HttpOnly; SameSite=Lax; Path=/`。角色与 `owner_id` 一律取自会话，忽略请求体中的
   `user_id`/`owner_id`/`role`。
   被拒备选：客户端持有角色/令牌签名（无法满足“角色不可伪造”的硬验收）。

7. **`--init-demo` 仅在空库播种，绝不重置（D06）。**
   仅在 `users` 表为空时创建 admin/alice/bob；重启与再次传入该参数都不会改变既有数据。

8. **UI 时间用可输入显式时区偏移的 ISO8601 文本框（D07）。**
   避免浏览器对时间控件做时区改写，保证按真实时刻比较。UI 为中文，按登录与角色显示控件。

9. **首个写入提交即确认、无审批（D01）。**
   仅保留 `bookings.status`（`active`/`cancelled`），不引入未被要求的审批端点。

10. **`GET /api/resources` 与 `GET /api/availability` 要求已登录。**
    CONTRACT 未显式标注这两个读接口的鉴权。本实现选择要求登录，理由是可用性/设施列表
    属于内部只读数据，登录前置更符合“封闭名单”场景。
    被拒备选：匿名可读。此为可逆的普通选择，已在此记录；若运营方要求公开只读可放宽。

## 明确的越界（本期不做及原因）

- 审批流、按设施规则（营业时间/客人上限/费用/押金）、通知邮件、日历视图、管理员代订、
  重复排期、闭馆封禁时段、配额/等待名单/信用、审计导出、支付账单、多楼宇分组：
  均为成熟类别能力，确认范围只要求核心闭环；除 `status` 与时间戳外不预建字段。
- 邮件、真实住户、支付、公网身份、外部网络、遥测、子进程、任意文件访问、依赖安装:
  确认范围与非功能约束明确禁止。
- 多租户/组织层级、跨主机多副本强一致：超出单社区回环演示边界。
