# 社区共享设施预约与取消

一个仅在本机回环运行的社区共享设施预约应用：设施管理员配置设施，封闭名单内的居民登录后
选择时段预约、查看并取消自己的预约；同一设施重叠时段至多成功一笔，权限由服务端强制执行，
取消保留状态记录并释放原时段，刷新与真实重启后状态一致。

## 运行环境

- CPython 3.10.x（本实验统一解释器）
- 仅使用 Python 标准库（`http.server`、`sqlite3`、`hashlib`、`secrets` 等）
- 无第三方依赖、无构建步骤、无外部网络与外部资源

## 启动方式

```bash
cd app
python3 app.py --port 8765 --data-dir ./data --init-demo
```

- `--port`：监听端口（默认 8000）。
- `--data-dir`：持久数据目录（默认 `./data`），所有持久数据都保存在此目录下的 `app.db`。
- `--init-demo`：**仅用于本实验的本地演示**。它会在一份全新的数据库上补建三个演示账号；
  已存在的账号与任何记录都不会被重置或覆盖。演示口令为合成测试数据，并非真实凭据。
- 服务只绑定 `127.0.0.1`，不对外网开放。

浏览器访问 `http://127.0.0.1:8765/`。演示账号：

| 用户名 | 口令 | 角色 |
| --- | --- | --- |
| `admin` | `AtlasDemo-Admin-9!` | 设施管理员 |
| `alice` | `AtlasDemo-Alice-9!` | 居民 |
| `bob` | `AtlasDemo-Bob-9!` | 居民 |

## 存储

- 所有持久数据位于 `<data-dir>/app.db`（SQLite 单文件）：用户、会话、设施、预约。
- 口令仅以 PBKDF2-HMAC-SHA256（随机盐，120000 次迭代）哈希保存。
- 登录会话由服务端生成不透明令牌并持久化，通过 HttpOnly cookie 下发；角色与归属从不信任客户端提交。
- 预约以 epoch 秒保存，取消只改状态不物理删除，因此历史可追溯。

## 已实现范围

- 登录 / 登出 / 当前用户查询；角色由服务端判定，不可由请求参数伪造。
- 管理员创建设施；所有登录用户可查看设施列表。
- 查看某设施的已占用时段（仅返回占用区间，不暴露他人的个人信息）。
- 居民提交带时区 ISO8601 的起止时间预约；归属者取自会话。
- 居民查看 / 取消**自己**的预约；管理员可查看与取消全部预约。
- 取消幂等（重复取消不报错、不破坏数据），并释放原时段。
- 时段为半开区间 `[start, end)`：相邻可预约，重叠返回 409。
- 并发竞争同一设施重叠时段时，通过 SQLite `BEGIN IMMEDIATE` 写锁保证至多一笔成功。
- 浏览器 UI 提供可理解的反馈，并在登录 / 角色后显示相应控件。

## 数据与依赖边界

- 仅回环本地演示：不集成邮件、真实住户、支付、公网身份服务或任何外部系统。
- 不提供任意文件读写、子进程执行或依赖安装能力。
- 未包含（有意不做，见 `DECISIONS.md`）：账号自助注册、口令找回、预约审批流、
  按用户展示完整日程的日历视图、时区偏好设置、分页与审计日志导出。
