# 工程与产品决策

记录本实现实际采用的默认值、理由、被否方案与仍未决的人类决策。
与蓝图 `DECISIONS.md`（D01–D08）一致的默认值在此落地说明。

## D01 提交即确认，无审批流（采用默认）

- 采用：`POST /api/bookings` 成功即 `status=active`，不引入审批端点。
- 理由：确认场景要求"直接预约、可立即使用"，且未要求审批；保留 `status`
  字段以便后续扩展为 `pending`。
- 被否：提交即 `pending` + 管理员批准。会把核心闭环复杂化并新增未被要求的接口。

## D02 应用层事务校验重叠（采用默认）

- 采用：写入使用 `BEGIN IMMEDIATE` 串行事务，顺序为
  校验 → `SELECT` 重叠（`start < :new_end AND end > :new_start`，仅 `active`）
  → `INSERT`；命中即 409。
- 附加守卫：部分唯一索引 `UNIQUE(resource_id, start_epoch) WHERE status='active'`。
  用**部分**索引而非常规唯一索引，是为了让"取消后同一开始时刻可重新预约"。
- 被否：PostgreSQL `tstzrange` + `EXCLUDE` 约束。能表达"不得重叠"，但引入外部
  数据库与部署，超出"标准库 + SQLite、仅回环"的固定范围。
- 说明：并发保证只覆盖单进程多线程 + 本事务模型，不是跨主机强保证。

## D03 时区以 UTC 实例比较（采用默认）

- 采用：`isoutil.parse_instant` 要求显式偏移，解析为 UTC epoch 整数存储比较；
  对外渲染为 UTC ISO8601；区间为半开 `[start, end)`。
- 理由：契约要求"按真实时刻比较"，且必须拒绝缺少时区的输入。
- 被否：按本地墙钟存储。无法正确处理跨时区/夏令时，与"真实时刻"语义冲突。
- 被否：接受无时区输入并默认本地时区。会静默改变含义，违反"缺时区返回 400"。

## D04 软取消（采用默认）

- 采用：取消只把 `status` 改为 `cancelled` 并记 `cancelled_at`，保留整行；
  重复取消幂等返回同一条记录，不写新行。
- 理由：验收要求保留状态记录、释放时段且不破坏历史。

## D05 标准库哈希 + 服务端会话（采用默认）

- 采用：`hashlib.pbkdf2_hmac('sha256', ...)` 加盐存储口令；
  `secrets.token_urlsafe` 生成会话令牌；`sessions` 表存放令牌与服务端有效期；
  `HttpOnly; SameSite=Lax` Cookie。
- 硬约束：`role` 与 `owner_id` 一律取自会话，忽略请求体里的 `user_id`/`owner_id`/`role`。
- 被否：把角色放在客户端令牌或请求参数中（可直接伪造，违反验收）。
- 未做：`Secure` 标记（本地 http）、CSRF 令牌。见下方未决项。

## D06 `--init-demo` 只补建、不重置（采用默认）

- 采用：逐账号 `SELECT` 后仅在缺失时 `INSERT`；从不更新或删除既有数据。
- 理由：保证真实重启后账户与记录一致，满足验收 A14。

## D07 ISO8601 文本输入框（采用默认）

- 采用：`booking-start` / `booking-end` 为普通文本框，用户输入带偏移的 ISO8601。
- 理由：避免浏览器 `<input type=datetime-local>` 改写/省略时区。
- 被否：日期时间选择器 + 本地时区转换（会与"显式偏移"契约冲突）。

## D08 成熟能力全部推迟（采用默认）

- 采用：审批、规则引擎、通知、等待名单、审计、支付均不实现，仅在数据模型
  预留 `status`/`created_at`/`cancelled_at`/`note`。
- 理由：任务明确要求不为显得完整而加入未要求功能。

## 实现层可逆选择

- **HTTP 版本**：`protocol_version = HTTP/1.1`，所有响应显式带 `Content-Length`。
- **并发**：每请求独立 SQLite 连接 + `busy_timeout=30000`；WAL 模式提升读写并发。
- **静态资源**：`/` 与 `/static/*` 由固定白名单映射提供，杜绝路径穿越。
- **日志**：覆盖 `log_message` 使应用保持安静，不打印请求细节。
- **资源列表**：仅返回 `active=1` 的设施（本期不提供停用/删除，字段预留）。
- **预约权限**：任何已登录用户都可提交预约，owner 恒为会话用户；管理员同样
  可查看全部/取消任意（`GET /api/bookings` 按角色分派）。
- **时间字段名**：对外 JSON 使用 `start`/`end`（契约用词），数据库列沿用
  `start_iso`/`end_iso` 以区别于 epoch 列。

## 明确不在本期范围

- 审批流、按设施规则/费用/押金、通知/邮件、等待名单/配额、日历视图、
  多楼宇分组、审计导出、支付与账单、公网身份/SSO、多租户。
- 物理删除、保留期策略、跨主机并发保证、按本地墙钟的重复排期与夏令时特例。

## 仍需人类决定（未擅自作答）

- 是否需要审批流及哪些设施可自动批准（D01 触发条件）。
- 是否需要配额/等待名单/信用（F18，取决于社区政策）。
- 取消的保留期与用户删除权要求（D04 触发条件）。
- 是否需要外部身份/SSO（本场景明确不支持公网身份）。
- 并发是否需扩展到多进程/多副本或迁移 PostgreSQL（D02 触发条件）。

## 自检状态

生成期不执行任何程序；所有验收用例状态为 `not_run`，由独立操作员在显式目标上运行。
