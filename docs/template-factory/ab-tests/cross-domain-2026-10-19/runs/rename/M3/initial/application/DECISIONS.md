# 工程与产品决策记录（DECISIONS）

记录本实现实际采纳的默认值、理由、被否决的备选，以及仍需人工决定的未决问题。

## 技术栈

- **采纳**：单一 CPython 3.10 标准库 CLI，入口 `python3 app.py --root DIR COMMAND ...`。
  改名是同文件系统内的元数据操作，`os.scandir/os.lstat/os.rename` 足够；符合“无依赖安装、
  无网络、无 shell/子进程”的约束。
- **否决**：Go/Rust 类工具（F2/brename/RnR）——需额外安装，且以正则/递归驱动、作用域更大，
  与“字面替换、单目录、非递归、拒绝冲突、显式确认、幂等”不一致；util-linux `rename`
  默认“没有任何保护”，不作为默认。只借鉴其**设计模式**（默认预览、冲突整体拒绝、
  journal 撤销、明确退出码），不复制任何第三方代码。

## D01 · 陈旧计划的证据强度

- **采纳默认**：`dev + ino + size + mtime_ns`（平台无 `st_mtime_ns` 时回退秒级 `mtime`）。
  默认**不**计算内容哈希。理由：哈希在大批量/大文件上有成本；纳秒字段可用性未获文档逐字确认；
  常规内容改动会改变 size 与 mtime，元数据已足够覆盖绝大多数“预览后源被改动”的情况。
- **可选**：`preview --hash` 额外记录 `sha256`，`apply`/`undo` 会一并核对。
- **未决（需人决定）**：当同一路径可能在极短时间内被**同大小、同时间戳**的内容替换
  （仅哈希可见），或根目录位于时间戳分辨率低（如 FAT 2 秒）的文件系统时，是否强制启用哈希。
  不启用哈希时存在极窄漏检窗口。

## D02 · 网络文件系统上的失败语义

- **采纳默认**：假设本地同文件系统原子改名；跨挂载返回 `EXDEV` 时如实拒绝。
  不承诺 NFS/SMB 等网络文件系统上“失败即未改名”。
- **未决（需人决定）**：当操作者明确把根目录放在网络挂载上时，是否允许以及如何核对。

## D03 · 执行期目标存在性的 TOCTOU

- **采纳默认**：执行前整批预检 + 每步改名**前再次 `lexists` 核查**，遇目标存在即拒绝且不替换。
  不依赖 Linux 专有的 `renameat2/RENAME_NOREPLACE`（Python 标准库未暴露）。
- **代价**：预检与改名之间存在天然极小 TOCTOU 窗口，已在 README 明示。
- **未决（触发条件）**：目录可能被其它进程并发写入（多进程/后台同步）时，是否加锁或改用平台特性。

## D04 · 换名环（a↔b）与内部覆盖

- **采纳默认**：环与“新名落在本批次源文件名内”一律视为计划内部冲突，在**预览阶段整批拒绝**，
  不引入临时名两阶段交换。理由：原子交换需 Linux 专有 `RENAME_EXCHANGE`，超出确认范围。
- **触发条件**：用户确有交换两个文件名或环状改名需求时，再决定是否引入临时名方案（路线图第 6 项）。

## D05 · 计划/回执的持久化与 fsync

- **采纳默认**：回执每完成一步改名即 `flush + fsync` 落盘，并用临时文件 + `os.replace` 原子替换，
  使崩溃后仍可核对与恢复。计划独占创建、创建后不改写。
- **边界**：抓取资料只显示既有工具“有 dump/日志文件”，未确认其崩溃语义；因此**不承诺断电级精确恢复**。
- **未决（需人决定）**：需要断电/崩溃后精确回滚保证（生产级或大批量）时，持久化与恢复协议如何定义。

## D06 · 同名内多次出现查找串的替换次数

- **采纳默认**：替换文件名中**全部**字面出现，并逐条列入计划，供执行前审阅。理由：字面“替换”
  语义下行为可预测。
- **备选（否决）**：只替换第一次（util-linux 默认）——可作为后续 `--first` 选项，不在当前范围。

## 路径与错误处理

- **采纳**：`plan`/`receipt` 的父目录 `realpath` 必须等于 `DIR/.atlas-renamer` 的规范路径，
  在**任何写入之前**校验；拒绝绝对越界、`..` 穿越与外部符号链接状态目录。状态文件本身是
  符号链接时拒绝读取。
- **采纳**：错误分类借 PEP 3151 子类（`FileExistsError`/`PermissionError`/`IsADirectoryError`/
  `NotADirectoryError`），不解析 `errno`。
- **采纳**：失败时先回滚已完成的本批改名（尽力而为），保证不产生部分批次。

## 明确不在范围（及原因）

- 递归、目录/符号链接/隐藏文件过滤：确认范围明确为单目录、非递归、不处理目录与符号链接。
- 正则/模式驱动：确认规则固定为字面文本替换。
- 可选备份 `.bk`：非核心预览→确认→执行→撤销旅程所必需。
- 多轮 undo/redo 链：本场景只要求撤销本次执行。
- 大小写不敏感 / Unicode(NFC/NFD) 等价冲突强保证：未获官方逐字确认，作为后续增强。
- 原子交换：依赖 Linux 专有特性，超出范围。
- 计费、多租户/角色模型、不可篡改审计链、GUI/桌面文件管理器：个人本地 CLI 场景不适用。

## 普通可逆默认（已记录，不阻塞）

- 状态目录名固定为 `.atlas-renamer`（契约要求），状态目录内的计划/回执文件名由应用生成。
- 状态文件使用多行 `indent=2` JSON，UTF-8，`ensure_ascii=False`，便于人工审阅。
- `list` 输出按名称升序，仅含 `name`/`size`。
