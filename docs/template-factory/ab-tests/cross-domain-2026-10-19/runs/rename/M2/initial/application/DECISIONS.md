# 设计决策（DECISIONS）

记录本实现中真实做出的工程/产品默认、被否决的替代方案、明确的范围外内容，
以及尚需人决定的问题。均为普通且可逆的本地实现选择。

## 产品默认

1. **字面替换、跳过无变化项**：`--find` 为非空字面子串；`new == old` 的操作被丢弃，
   不写入计划。理由：无操作的改名会污染回执与冲突判定，且违背“不产生第二轮重命名”。
2. **`--replace` 允许空串**：空替换是为数不多有意义的行为（删除文本），
   但结果名必须仍是合法单文件名，否则整份计划拒绝。
3. **预览即拒绝冲突**：目标名已存在、结果名互相重名、结果名非法，都会让 preview
   直接失败，而不是生成一份注定失败的“危险计划”。理由：契约要求冲突时整批拒绝，
   尽早失败更安全、提示更清晰。
4. **计划与回执不可覆盖**：写出时使用 `O_CREAT|O_EXCL`，已存在即拒绝。
   理由：契约要求计划是真实、稳定的快照；覆盖会破坏可审计性并可能与已发回执不一致。
5. **内容证据为 `sha256` + `size`**：`mtime_ns` 仅记录、不参与过期判定。
   理由：契约只要求“内容被改动则拒绝”；若以 mtime 判定，单纯 `touch` 会造成误拒。
6. **重复执行检测双保险**：先查 `receipts/<plan-id>.json` 是否存在；
   若计划无 `id` 或回执缺失，退回用“源名消失但新名内容匹配”判定已执行。
7. **撤销不做持久化标记**：以文件系统状态判定（新名存在/旧名存在且内容匹配）。
   回执保持不可变，不因撤销而被修改。已撤销的判定为“全部旧名恢复且新名消失”。
8. **大小写折叠判重**：结果名之间与现有文件之间按 `casefold` 比较。
   理由：目标宿主 macOS 通常为大小写不敏感文件系统，`A.txt`/`a.txt` 无法共存；
   否则可能生成在真实磁盘上相撞的计划。
9. **部分失败回滚**：执行/撤销中途 `OSError` 时，把已完成的改名逆序回滚；
   回执写入失败同样回滚，避免留下“改了名却没有回执”的不可撤销状态。

## 被否决的替代方案

- **正则查找**：契约明确要求字面文本，且正则引入转义与不可预期匹配，否决。
- **允许链式改名（a→b 而 b→c 同时进行）**：需要在磁盘上做临时名与拓扑排序，
  风险高且契约要求“目标已存在即拒绝整份计划”，故直接拒绝。
- **用 mtime 判过期**：会因元数据触碰误判，否决（见 5）。
- **在计划文件里追加“已执行”标记**：会破坏计划不可变语义，改为独立回执。
- **为撤销写 `.undone` 标记文件**：契约未要求，且文件系统状态已足够判定，保持状态目录简洁。
- **递归/多目录/删除**：超出已确定范围，否决（见范围外）。

## 明确的范围外（及其理由）

- 递归、多根目录、通配符/正则、删除或回收站：契约限定为单目录字面替换的工作流。
- 图形界面、云盘、并发锁、多用户：契约声明这不是完整桌面文件管理器。
- 内容修改、权限/所有者变更、时间戳恢复：本工具只改名，不动内容。
- 在用户真实下载目录或应用源码/HOME 上运行：契约禁止；演示仅在测试创建的普通文件上。

## 未决、需人决定的问题

- 是否允许“仅大小写不同”的改名（当前为安全起见拒绝），需要确认目标文件系统语义。
- 撤销是否应支持跨多批的历史栈（当前一次执行对应一次撤销）。
- 失败时是否需要机器可读的错误 JSON（当前失败仅 stderr 文本 + 非零退出码）。
