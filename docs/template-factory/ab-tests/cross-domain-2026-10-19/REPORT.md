# 跨品类认知模板与交接形式对照报告

日期：2026-10-19。状态：运行、两次产品修复、限定独立审阅及形式分析已完成；改名首版扩展审阅两次缺字段，严格协议失败如实保留。本轮只做实验与分析，不发布候选、不修改工厂日常目录、不改旧书签 A/B 成绩。

## 结论范围

本轮没有证明模板能稳定提高首次交付质量、稳定加速或降低实际费用。共同规格较强时，无模板也能实现主流程。改名场景的事后探索给出了具体价值信号：无模板首版发生根目录外回执写入，两种模板首版未出现同一问题；但这是一个品类的一次探索性差异，不是普遍有效性证明。

建议 Atlas 默认采用“完整认知库 + 当前阶段执行包 + 独立验收证据”，保留完整规划视图及按主题参考。形式建议与因果证据分开，见 [FORM_ANALYSIS.md](FORM_ANALYSIS.md)。

## 实验设置

三个不同场景，各比较无模板、完整附件、相同知识包分层按需三组，共九个初版条件：

| 场景 | 冻结的具体范围 | 主要实测 |
| --- | --- | --- |
| 月度分类预算 | 单用户、人民币、手工录入，不做银行/支付连接 | 金额精确、月隔离、纠错、中文 CSV、重启、真实浏览器 |
| 社区设施预约 | 一个合成管理员、两个合成居民，回环本地演示 | 服务端身份与权限、时区/冲突、取消历史、真实双连接并发、重启、浏览器 |
| 单目录批量改名 | 普通文件，CLI 预览/确认/应用/撤销，不冒充桌面文件管理器 | 真实文件与多进程调用、防覆盖、计划过期、路径/符号链接、撤销保留数据 |

模板研究、生产、开发、OpenCode 评测均指定 `commandcode/deepseek/deepseek-v4.1-flash`、reasoning effort=high。作者各用独立会话、同品类三组同时间块启动、共同 CPython 3.10.13 标准库契约及工具限制。模板不是上游项目 clone 或现成应用源码；两模板条件持有字节相同的认知包，完整组原生附件提供全文，分层组从 HANDOFF/CURRENT_PHASE/决定开始，全文仍可访问。

作者只能写自己的 app/，不能执行、搜索、安装或读取其他组；独立测试工程 Agent 完整阅读源码后才运行应用。三组同样要求 README 与 DECISIONS。最多一次同输入传输/协议重试；有实际材料失败且有完整交付的组最多一次产品修复。主机未手改生成应用。

主协调器持有分配映射，独立测试与结果审阅不提供映射、模板或开发提示。原文档中的蓝图引用可能泄露处理线索，因此称“独立、条件映射未提供”，不称严格双盲。实际模型记录、输入/包/源码/工具哈希检查见 [integrity.json](integrity.json)。

## 初版结果（包含允许的一次协议重试）

“通过”仅指列出的共同核心检查实际运行通过。各品类检查分组不同，不合计获胜分数。

| 场景 | 无模板 | 完整附件 | 分层按需 |
| --- | --- | --- | --- |
| 预算 | M1：B01–B06、BU01/BU02 通过 | M2：两次清单路径协议失败，未规范交付，未执行 | M3：真实启动 NameError，依赖 API/UI 未运行 |
| 预约 | M3：K01–K07、KU01/KU02 通过 | M1：同项通过；清单协议重试一次 | M2：同项通过 |
| 改名 | M2：F01–F11 通过 | M3：同项通过；provider 流错误重试一次 | M1：同项通过 |

规范交付共八个初版条件完成，一个失败。预约和预算完整组的清单错误均为作者返回 app/app.py 等前缀，而驱动要求相对 app 根的 app.py；CLI 均退出 0，不能称 provider 不会写程序或应用业务失败。原结果未归一化、未选择性执行失败产物。改名完整组首次出现 `provider.invalid-output / stream ended without finish_reason`，CLI 失败保留，第二次同输入交付后才接受运行。

预算 M3 的真实进程在构建 HTTP Handler 时抛 NameError、退出 1；这是一个启动根因，不能把未运行的八项流程当作八个独立业务缺陷。原始模型审阅逐 ID 标记 failed 表达其被阻断，运行证据与本报告仍明确依赖行为未验证。

## 事后探索 EP01：计划标识符与回执路径

独立 Agent 在完成改名 M2 预设核心检查及源码审查后发现潜在风险，随后在阅读 M1/M3 源码前冻结 [EP01 规则](evaluation/EP01.md) 与 [哈希](evaluation/EP01-freeze.json)，对三组统一测试。它不加入 F01–F11、不追改核心成绩。

真实生成计划后，把顶层 id 改为专用测试目录中根目录外的绝对路径；分别测试目标不存在、目标已有已知哨兵文件。只用测试自有目录，不用 ../ 或实际用户文件。

| 初版条件 | 新的根外回执 | 已有根外哨兵 | EP01 结论 |
| --- | --- | --- | --- |
| 无模板 M2 | 确实创建；apply 退出 0 | 未覆盖，拒绝且保留 | 真实目录边界缺陷 |
| 完整附件 M3 | 未创建 | 未改变 | 本探针通过 |
| 分层按需 M1 | 未创建 | 未改变 | 本探针通过 |

两模板首版安全忽略额外 id，并从已验证计划文件名派生回执。无模板首版的缺陷在 [实际 apply 事件](evaluation/results/rename/M2/EP01-initial/absent_target/apply-event.json) 与 [发现记录](evaluation/results/rename/M2/EP01-finding-initial.json) 留存。这里证明了一个新建根外文件的案例，没有证明任意文件覆盖。通过同一探针也不证明所有符号链接、竞争条件或攻击路径安全。

## 独立认知审阅

共同 C01–C05 分别检查范围追踪、实际决策与理由、阶段路线、真正人工问题和证据诚实性，不按文档长度打分，不要求个人工具具备企业计费。

预约三组基本同等获支持；分层 M2 的 C05 为 partial，存在引用未交付文件的文档问题。预算可交付的无模板 M1、分层 M3 在认知维度都获支持，完整 M2 因未交付而未验证，不能据此断言其底层认知包质量差。所有作者自检都记录 not_run，不能从 DECISIONS 的完整性推断应用已跑通。

改名初版的两次 OpenCode 回复都缺少要求的逐应用 exploratory 数组，严格扩展协议失败；原回复实际分析了 EP01，三个应用的 F01–F11 与 C01–C05 字段均完整。第一份响应按字节原样保留为 core-only-assessment.json，单独记录子集有效、扩展字段缺失，不由主机补造 EP01 结论，也不第三次生成。其三组认知维度都获支持。最终轮次的独立结构化审阅通过，核心与 EP01 三组均获运行证据支持，其他组明确沿用首版；这不抹去无模板首版的探索失败。

本样本里无模板的观测开发时间和 input 字段更低，但模板组有协议重试，且并发、缓存、provider 负载、额外材料都会影响时间；不作稳定加速/减速、实际费用因果结论。完整组的原生附件不产生等量 read 事件。分层三组仍分别成功读取 9、11、10 个不同模板文件，其中包含验收代码，不能把“分层”自动当作模型少读。

## 实验偏差与未验证范围

1. **预算 stdin 偏差**：宿主通过 Python heredoc 启动预算块，OpenCode 把相同 622 字符启动脚本附入该品类全部四次作者首条消息。实际会话核对内容和哈希相同；预约没有，改名启动前已暂停并修正。原记录未擦除，预算属于共同额外输入下的探索性比较，不是严格干净输入；相同脚本也不能排除与交接形式的交互。预算修复去掉了脚本，属于轮次控制变化。见 [偏差记录](stdin-protocol-deviation.json)、[实际会话输入核对](actual-input-audit.json)。
2. **v3 工具修正**：首个实际预约 M3 的 v2 并发测试受变量遮蔽影响，浏览器受隔离 HOME 缓存路径影响，工具哈希还误包含证据目录。原工具及运行保留；修正不改产品源码或业务断言，所有有效比较统一使用 v3，按 evidence-index 指向实际证据。不能把原工具故障算应用缺陷。
3. **强共同规格与禁止作者执行**：大部分领域难点已经明示，本轮测实施支持；正常可自测 coding agent 可能在交付前发现启动错误。不能直接推广到稀疏想法、开放工具的真实开发完成率。
4. **样本与匿名限制**：每格一个初始应用，重试只用于预定协议/传输问题；形式分析计划在首次结果后记录，EP01 为事后探索。同模型家族、文档来源线索与共享 provider 负载均限制推断，不宣称统计证明或严格双盲。
5. **通过范围有限**：预算零预算、改名某些元数据过期/临时回执符号链接/外部写竞争等源码观察未在共同套件全部运行，不把它们当已证明漏洞或已证明安全。浏览器只覆盖两项真实操作，不等于移动端、可访问性或全部错误反馈成熟。
6. **模板本身未完成运行认证**：三份新认知包通过结构/冻结与独立静态审阅，但自带验收程序仅做语法检查，未整套执行；本报告依据外部共同套件。没有自动升级 L2/L3、发布候选或确认生产目录场景，旧书签 17 项程序的待办保持原状。
