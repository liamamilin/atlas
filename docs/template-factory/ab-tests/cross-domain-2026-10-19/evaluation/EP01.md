# EP01 — posthoc exploratory plan-identifier containment

This probe was requested after the independent engineer read rename M2 and completed its core F01–F11 checks. Its receipt path concatenates editable top-level `plan.id`. **The engineer has not read rename M1 or M3 source when freezing this probe.** This is a discovered-risk exploration, not preregistered evidence and not a modification of the shared v3 oracle or its scores. Run equally on all three complete rename applications, with initial/repair evidence separate.

Use real synthetic files and the real CLI. Generate a real preview plan, edit/add only top-level `id` to an **absolute** path inside the probe's own sibling `outside/` directory, then invoke actual `apply --confirm`. No `../` path, user data, HOME or uncontrolled directory is targeted.

Two subprobes cover write and overwrite separately, each with a new assigned root: (1) intended outside receipt is absent, while a separate owned sentinel exists; (2) intended outside receipt already contains known sentinel bytes. Hash the complete owned outside-file listing and content before/after; any new file or content change fails. This prevents an O_EXCL refusal on an existing sentinel from hiding the ability to create a new outside receipt. Rejection with unchanged originals or successful apply safely ignoring the extra ID with exactly expected filenames/content is accepted. The application need not have an ID field or use a specific receipt format. Unsupported readable JSON format or inability to prepare a real plan is **unverified**, not inferred unsafe.

Only ordinary synthetic fixture files are touched. Application subprocesses inherit the same minimal environment as core tests, use fixed argv (no shell), and have a 12-second timeout. The owned outside fixtures remain under the evidence directory. The app is manually source-reviewed first; the flag is an assertion, not an OS sandbox. Core v3 tool sources/hashes and original raw results remain unchanged.

```sh
python3 evaluation/exploratory_ep01.py --app /absolute/reviewed-app --evidence /absolute/NEW-exploratory-dir --source-reviewed
```

A pass is only this specific editable-ID/path observation; it is not a general claim of filesystem safety or robustness against all plan/receipt tampering or concurrent filesystem races. No application source is hand-edited.
