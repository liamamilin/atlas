## 这次比较什么

三个场景分别强调不同难点：个人月度预算的金额与月份一致性、社区设施预约的身份/冲突/生命周期、单目录批量改名的真实文件保护及撤销。范围是具体工作流，不冒充完整金融系统、社区管理平台或桌面文件管理器。

每个场景三个条件：仅共同需求与契约、完整认知材料交接、相同材料的阶段入口与按需引用。共九次初版开发。模板由 OpenCode 研究与生成，并通过 Atlas 的认知包渲染/校验/冻结及开发包导出，不给开发者旧应用代码。两种模板条件的底层包字节必须相同；完整形式通过 CLI 的文本附件提供合并全稿，分层形式从 HANDOFF/CURRENT_PHASE/决策开始，全文仍可访问。确切交付变更在 protocol-delivery-amendment.json 留存，不能预先假定附件全被读入或分层一定少读。

独立测试工程 Agent 在模板生产前冻结了共同规则。随后在任何应用生成/运行前，修正了公开元数据、合法计划格式和浏览器日期控件的适配问题；旧版完整保存在 evaluation/oracle-v1/，修正原因和 v2 冻结分别保留。首次实际运行预约 M3 后，又发现并修正并发测试的模块同名遮蔽、隔离 HOME 下的浏览器缓存定位，以及工具哈希误包含证据目录三项技术问题；v2 原始源码和运行证据保留，v3 不改业务判定条件，统一用于当前比较。没有根据某组实际成绩调宽标准。每格 evidence-index.json 将逻辑轮次指向有效证据，避免把旧工具故障当产品失败。

## 固定控制与解释边界

共同请求、API/CLI 集成契约、运行环境、模型、工具权限与可选修复机会在同一场景保持一致。开发者只可写自己 app/，不能执行、安装、搜索或访问其他条件。每次调用使用独立会话，基础设施超时 1800 秒；传输/协议错误最多按同输入再试一次，原失败保留，不依据应用成绩挑更好的重跑结果。每个条件最多一次产品修复机会，反馈为同一颗粒度的失败现象/步骤/期望，首轮和修复后分开记录。

独立结果审阅只收到匿名应用源码、共同规则和真实运行证据，不收到模板、条件映射或开发提示。API、浏览器、CLI、静态检查和未验证项分别判定，不能用接口通过代替 UI 可用，也不能把不同品类的分组数加成一个获胜分数。公开数据及合成账号/文件用于测试，不使用实际账目、住户或下载文件。

共同 P0 规格故意写得比较明确，因而主要验证模板的实施支持，不能充分证明它帮用户发现了未说出的成熟产品需求。所有条件都同样交付 README/DECISIONS，另按五个预先冻结的维度做定性认知审阅：范围追踪、决策理由、阶段路线、人工问题、证据诚实性。不把企业计费等不适用功能强加成失败项。

最佳形式分析结合逐品类的实际缺陷、认知审阅、原始交付和修复状态、实际读取/截断、可见用量及耗时。单次每格生成只提供探索证据；材料变短、可见字段变少或某组恰好成功，均不足以证明普遍更好或真实计费更低。

原预算四次作者调用都附入了同一段 622 字符的宿主启动脚本，实际会话核对内容/哈希相同；这是保留的协议偏差，不称严格干净输入。改名启动前暂停，实验驱动显式隔离 stdin 后恢复，实际调用已核对干净；预算修复也去掉了额外脚本。详见 stdin-protocol-deviation.json。作者禁止执行；EP01 事后探索不改共同核心成绩；评测未提供条件映射，文档仍可能暴露来源，不保证严格双盲。

## 记录与恢复

- protocol.json、protocol-amendment.json、protocol-delivery-amendment.json：原方案和模型调用前的控制修订。
- cases/：固定共同请求、Atlas 叶子、公开调研、模板生产及冻结开发包。
- evaluation/：独立规则、版本保留和真实测试工具；results/ 保存各匿名应用初版与修复证据。
- runs/：隔离开发会话、原始事件、输入哈希、交付回执与不可变应用源码。
- reviews/：未提供条件映射的独立结果审阅；协议失败原样保留。
- metrics.json：分调用可见字段与实际读取；CLI 事件与会话导出用量分别列出、不相加，缺失字段保留；不当成唯一计费 token 或账单。

模型调研重复输出本地 S01 时，主机保留严格校验失败，只去掉这条重复本地来源，外部事实/ID/摘要/未知项原样保留；Atlas 按固定实验场景注入 S01。此归一化单独记载，不把非法原响应改成通过。场景的 ready 状态只是用户授权实验的派生输入，未确认或修改工厂数据库中的草案。

运行中的调用不要重复发起。先看各阶段 process.json、result/failure.json 和会话日志；已有 result 作为检查点复用。缺失结束回执的运行必须核对所属进程，不能因找到了源码就推断 CLI 成功。
