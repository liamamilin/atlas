# 决策与默认值

## D01 · 金额如何表示与取整？

以整数“分”存储与计算，响应渲染为两位小数字符串；对超过两位小数或非正数输入直接拒绝而非静默舍入。理由：避免二进制浮点误差（S12），并满足场景“不静默取整或裁剪输入”。可逆。

When to ask / 询问条件: 当使用者明确希望自动舍入到分、或需要接受超过两位的小数输入时。

数据模型、输入校验、汇总公式与 CSV 导出的数值格式。

默认采用（可逆）

## D02 · 超支是否跨月结转？

P0 仅在当月展示负剩余，不自动结转下月。理由：已确认验收只承诺当月计划/实际/剩余；跨月 rollover 属成熟扩展（S05）。可逆。

When to ask / 询问条件: 当使用者要求上月超支影响下月可用额度、或需要结转语义时。

汇总公式、月切换展示与后续阶段规划。

默认采用（可逆）

## D03 · 本地数据如何持久化与写入保护？

SQLite 单库（CONTRACT 固定），以事务/临时文件方式原子写入，且只写入 --data-dir。理由：单机集中持久化并降低损坏风险（S13,S01）。可逆。

When to ask / 询问条件: 当需要多设备同步、备份轮换或对崩溃恢复作出承诺时。

存储布局、启动参数与恢复策略。

默认采用

## D04 · 是否需要完整编辑历史/审计日志？

P0 不建完整编辑历史，以导出 CSV 作为最小审计与恢复起点。理由：据可用一手文档未见主流产品提供完整编辑历史（S01 未验证项）。

When to ask / 询问条件: 当使用者要求改账留痕、回溯历史版本或合规审计时。

数据模型（历史表）、UI 展示与导出内容。

待人类确认

## D05 · CSV 导出采用何种方言？

UTF-8、RFC 4180 引号规则、QUOTE_MINIMAL、CRLF、表头 date,category,amount,note。理由：S10/S11 给出信息性标准与标准库行为；与 CONTRACT 一致。已定。

When to ask / 询问条件: 当目标环境要求其他编码、分隔符或 Excel 本地化行为时。

导出实现、往返测试与字段格式。

已定（与 CONTRACT 一致）

## D06 · 是否支持删除/归档分类？

P0 不支持删除分类，未使用分类保留可见。理由：场景要求未使用分类仍可见，契约未定义删除语义（S02 分类为月内对象）。可逆。

When to ask / 询问条件: 当使用者要求清理、重命名或归档分类时。

API 表面、月内隔离与历史数据一致性。

默认采用（可逆，后续阶段）
