# 中文生活待购与灵感收藏夹：独立盲评标准

版本：bookmark-ab-rubric-v1
冻结日期：2026-10-18
状态：在接触匿名实现及测试证据之前冻结

## 评测边界

目标是个人使用的中文本地网页应用：保存商品、教程或灵感网页 URL，可选标题、备注及归类；允许先存入未分类；能够创建归类、移动记录、按归类浏览、关键字搜索、打开原网页，并在刷新及服务重启后保留数据。

共同环境为 Python 3 标准库及 SQLite，loopback HTTP。统一入口：

    python3 app.py --port PORT --data-dir DIR

评测不规定 API 路径、状态码、数据库表、HTML 结构、testid 或视觉布局。不要求账户、支付、协作、云同步、部署平台、编辑/删除记录、导入导出、自动抓取网页标题、全文检索或复杂标签体系。

评测者保持只读；运行、启动、浏览器操作及会写入数据或测试产物的检查，由父代理或实施者执行并提供证据。两组使用独立空数据目录、相同测试数据、同等资源及相同操作顺序。

## 测试数据

URL 为合成测试数据；不要求应用抓取其内容。打开原网页的证据是浏览器发起正确导航或展示正确目标 URL，无需外网页面加载成功。

- A：URL `https://example.com/item/lamp?source=collection&variant=warm#details`；不填标题、备注或归类。
- B：URL `https://example.com/item/bookshelf`；标题“折叠书架”；备注“小户型，周末量尺寸”；归类“待购”。
- C：URL `https://example.com/tutorial/bread`；标题“酸面包教程”；备注“周日尝试”；先不归类。
- 两个归类：“待购”“学习”。

允许使用产品自身合理的等效交互路径。URL 采用浏览器正常规范化后的等价判断，不能丢失有意义的路径、查询参数或片段。

## 显式需求及必要交付检查

每项记录：操作、预期、实测结果、证据位置、判断及影响。

| ID | 检查及可复现操作 | 预期 |
| --- | --- | --- |
| R01 | 在共同环境以指定命令、端口和空数据目录启动，通过 loopback 地址访问。 | 中文网页可用，无账户或共同环境之外的运行依赖；指定端口及数据目录有效。 |
| R02 | 保存 A，再保存含标题和备注的 C；刷新并查看记录。 | 仅 URL 即可保存；可选标题和备注能保存并呈现；无标题记录仍可识别和打开。 |
| R03 | 查找 A 和 C 的未分类入口或等效视图。 | 无须先建归类即可保存，并能日后找回未分类记录；不要求入口名称固定。 |
| R04 | 创建“待购”“学习”，保存 B 时选择“待购”，通过该归类浏览。 | 用户可新建归类，并在保存时选择归类；B 可在相应归类中找到。 |
| R05 | 将 C 从未分类移至“学习”，将 B 从“待购”移至“学习”，刷新并逐一查看相关归类。 | 移动实际改变归属；目的归类可找到记录，原归属不再保留该次移动的归属；标题、备注及 URL 保持完整，无意外复制或丢失。 |
| R06 | 在能覆盖相应记录的搜索范围内，以“书架”查找 B，以“面包”查找 C，再输入不存在的词并清除查询。 | 关键字搜索能找回标题包含该词的记录；结果与当前范围一致；空结果可理解；清除查询后能继续浏览。全局或归类内搜索均可，但范围必须可理解。 |
| R07 | 从可见列表或详情打开 A、B、C 的原网页。 | 导航指向对应原 URL；A 的路径、查询参数和片段得到保留。新标签页或当前标签页均可。 |
| R08 | 完成以上操作后刷新；正常停止服务，以相同数据目录重新启动；重查记录、字段、归属及搜索。另以新的空目录启动检查隔离。 | 刷新及正常重启后，已确认保存的内容和移动结果保留；新数据目录不混入旧目录记录。 |
| R09 | 观察保存、归类和移动后的反馈；已有数据时尝试空 URL 保存，再重新查看已有数据。 | 用户可从更新后的界面或明确提示理解结果；空 URL 不应被报告为成功保存的有效网页记录；无效操作不会破坏已有记录，用户能够继续操作。 |

R09 接受浏览器原生表单校验，不强制 toast、弹窗或特定文案。操作结果直接体现在列表中也属于有效反馈。若出现其他实际失败，应检查其提示是否与最终状态一致，以及已有数据是否完整。

## 成熟度探索：单独报告

这些项目用于揭示日常使用风险，不增加显式需求，不因功能缺失直接判定需求未满足。

- M01 恢复与状态：突然终止服务后的恢复、多标签页先后操作、重复点击保存。记录实际丢失、重复或不一致；不预设并发架构。
- M02 真实输入边界：中文、空格、引号、长标题和备注、带查询参数的 URL、重复 URL。重复处理可以允许或去重，但反馈和结果应一致；不预设长度上限。
- M03 失败处理：端口占用、不可用数据目录或实际发生的持久化错误。检查是否解释失败、避免虚假成功及破坏已有数据。仅在独立测试目录中执行。
- M04 内容安全：标题和备注中的 HTML 特殊字符及无害脚本探针是否作为内容呈现。仅用本地无害标记验证，不访问外部地址。
- M05 上手与浏览：首次使用能否找到保存、归类、未分类、搜索和原网页入口；空状态和空搜索结果是否帮助继续操作。记录具体障碍及触发步骤，不按个人审美评分。

成熟度探索发现的真实数据丢失、脚本执行或无法继续使用等问题应如实说明严重性，同时标明它来自探索，不能事后冒充显式功能要求。未执行的探索只标为未验证。

## 证据及判断规则

每个需求项使用以下结果：

- 通过：有直接运行证据支持全部预期。
- 部分满足：已证实部分行为满足、部分行为存在明确缺失，列明两者。
- 不满足：有可复现证据表明预期失败。
- 未验证：缺少足够运行证据，或测试环境阻止判断。

不得把“未验证”写成“失败”或“通过”。源码检查可以解释行为及支持明确的静态缺陷，但不能单独证明启动、浏览器交互或持久化已经成功。区分观察事实、源码推断和缺失证据。

每个问题需包含：匿名实现、检查 ID、文件及行号（如适用）、触发操作、实际结果、用户后果、证据位置和可执行的修复方向。无依据的猜测、风格偏好和未经请求的重构不是阻塞问题。

没有合格率、总分、任意延迟阈值或按代码行数、文档量计分。耗时如有测量，描述环境、操作和观测值；不能把一个未经需求支持的数字变成通过门槛。

## 比较与结论

先比较核心闭环能否完成，以及是否存在数据丢失、错误归属、无法启动或无法保存等实证问题；再逐项比较需求覆盖、反馈可理解性和交付证据；成熟度观察独立列出。不得用探索功能数量抵消核心需求缺失，也不根据视觉精致程度推断正确性。

若两组存在不同取舍且证据不足以形成明确优劣，直接报告取舍或无法区分，不强行选出赢家。最终是否完成及如何集成由父代理决定。

这是单个应用、单次成对实验。结果只能说明本次观察到的表现，不能统计证明条件导致质量差异，也不能推广为普遍因果结论。

## 冻结约束

看到实现后不调整测试目标、判定门槛或优先级以适配某组。出现歧义时，记录歧义并对 X/Y 使用同一解释；需要新增探索时，标为冻结标准之外的补充，不回写既有结果。
