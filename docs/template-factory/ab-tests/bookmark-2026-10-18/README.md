# 认知模板的真实开发 A/B

2026-10-18，用户要求使用 OpenCode 分别在有模板和无模板的条件下开发，再由独立 agent 评测。当前状态以最终 REPORT.md 为准；没有报告前不宣称任何一组通过。

## 问题和范围

使用同一个已确认的“生活待购与灵感收藏夹”需求，观察认知模板是否改变 coding agent 的实际交付：保存 URL/标题/备注，默认未分类，新建归类、保存时选归类、移动、按归类浏览、关键字搜索、打开原网页，以及刷新和服务重启后的保留。

单个场景、单次配对是实践验证，不能给出统计因果结论。模板从其他产品生成，也可能包含不必要复杂度；保留这种负面结果，不预设模板组胜出。

## 对照和冻结

- 模型均为 `commandcode/deepseek/deepseek-v4.1-flash`，按用户本轮要求切换，CLI 相同、独立新会话、reasoning effort=high。旧 provider 尝试保留在 `pre-switch-open-design/`，不计入主要 A/B 结论。
- 同一中文场景和完整用户流程；共同运行环境为 Python 3 标准库和 SQLite，入口 `python3 app.py --port PORT --data-dir DIR`，只监听回环。不安装依赖，不提供旧实现。
- 该环境控制会覆盖模板推荐的 Node 技术栈；因此这也是认知材料能否适配同一运行环境的试验，不代表原推荐技术栈的直接验证。
- 一组额外获得冻结自动模板 v0.1.12，另一组没有模板。模板包含产品定义、调研、架构、阶段、决策、Agent 指南和验收代码；不提供已实现应用。
- 两组均只允许读取各自材料，并通过文件工具在各自 app/ 中写完整源码；最终响应只返回小型元数据，主机冻结后在独立步骤运行。没有网络检索、shell、跨组读取权限。旧尝试出现整份源码最终响应截断，新一轮在启动前统一改为逐文件写入。额外上下文/token 是处理条件的一部分，不强行等长。
- 每组一次首版生成；若出现实际核心阻断，最多各一次基于相同评测协议的反馈修复机会。首版、反馈和修复版单独冻结，不覆盖结果。主代理不手工修应用。
- 每次调用 1800 秒只是基础设施超时，不是性能合格门槛。
- 实现开始前，由独立 agent 制定并冻结 [评测规则](evaluation/rubric.md)；规则与输入哈希保存在 control/。X/Y 随机分配，映射在最终盲评完成前不提供给评测者。

## 实测与盲评

运行测试工具按匿名应用和冻结规则，为不同 UI 编写操作适配，行为断言一致。原独立测试子 agent 在准备工具后触发账号用量限制，后续由主代理执行工具。通过真实浏览器操作、独立数据目录、同目录重启及新目录隔离获得证据；外链导航由浏览器拦截并本地返回合成页面，保留实际目标 URL，绝不访问外站。生成应用在最小环境中运行，不继承模型凭据，不操作日常 Atlas 服务和数据。

独立的 OpenCode 只读新会话按冻结规则审核匿名源码和实测证据，同样使用用户指定的新 provider。核心 R01–R09 与成熟度探索 M01–M05 分开；模板专用路由、错误码、testid 不作为共同评分。未运行/缺证据不记为通过，测试脚本或环境问题不直接算产品失败。评测者可能从产物风格推断条件，因此这是“不给条件映射的匿名评测”，不声称完全消除可识别线索。

X 的首轮独立审阅指出“长备注可能被截断”但证据未覆盖。随后对双方添加同一 M02b 补充探索：通过 UI 提交 3,420 码点备注，捕获实际请求，再刷新读回。该探针在查看实现之后加入，单独标记 posthoc，不改九项预先冻结的核心判定。表单传输的 CRLF 与 textarea 逻辑 LF 分开记录，JSON 原值保留；没有用截短、trim 或宽松匹配掩盖丢字。最终配对审阅会重新审核双方完整证据，不接收 X 的先前结论来替代判断。

Y 的新 provider 调用留下完整九文件源码与最终文件清单，但 CLI 以 1 退出，保留 `provider.invalid-output` 原始事件。工厂调用状态仍为失败；`recover_completed.py` 只从完整最终元数据核对现存文件并原样冻结，供本轮实测试用，没有补写缺失源码或把失败改为成功。CLI 成败与应用运行证据分别报告。两组事件流末尾都是最终文本、没有最终 stop 的 step_finish 使用量；X 的进程正常退出不受此日志格式影响，但双方累计 token 字段都可能缺少最终一段，不能当完整账单。

测试工具联调记录另存：X 的初次 option 可见性等待、外链重定向记录，以及补充探针对 HTML CRLF 的误判均保留旧记录并在修正工具后重新执行。最终比较只使用双方最终冻结源码对应的正式 evidence/ 和 supplement/。源码未由测试者修改。

## 记录

- `control/`：原始输入、相同实现提示词、条件映射、CLI 日志、调用结果和冻结协议。不要在盲评前交给评测者。
- `blind/X/`、`blind/Y/`：原样应用、源码哈希和实际证据。
- `evaluation/`：事先冻结规则、运行脚本与报告、独立评测。
- 调用用量按 OpenCode 报告的各字段分别统计；input/output/reasoning/cache 可能重叠，cost=0 不代表免费。耗时分别记录生成和运行，不用模型会话数冒充请求数。

运行指令：先 `python3 run_experiment.py prepare` 冻结输入，保存规则并记录哈希后再 `python3 run_experiment.py generate`。已存在结果不会覆盖。本目录是受控实践记录，不是通用工厂运行验收已集成的声明。
