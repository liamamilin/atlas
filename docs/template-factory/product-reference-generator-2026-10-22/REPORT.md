# 产品参考规格生成改造

日期：2026-10-22。来源：用户提供的 `atlas-reference-examples-2026-10-22/` 三份产品参考样稿及 GENERATOR_GUIDE。此轮是生成器开发和本地验证，**生产保持暂停，新增真实模型调用 0，不恢复严格 G1/T08，不开发示例应用**。

## 从样稿吸收的变化

| 参考案例 | 应吸收的产品判断 | 落地位置 |
|---|---|---|
| 个人收藏夹 | 单人产品不凭空增加后台；完整保存、查找、整理、恢复及长期使用；页面共用不等于全部能力同阶段开发 | product_shape、角色、入口状态、按操作选范围、延期操作保留 |
| 团队项目看板 | 管理员不自动读取业务内容；角色和数据范围进入每个实际操作；状态与归档分别表达；跨页结果一致 | roles/actions/surfaces/journeys/rules/assertions 的稳定 ID 关联 |
| 团队活动报名 | 一次操作影响多个角色和页面；容量、截止、重复请求、通知失败、人员交接需闭合 | 对象状态与显式 transitions、操作前置/效果/失败恢复、跨角色旅程和声明式验收 |

上述业务规则属于样稿的目标设计，未转成上游事实或已生产模板。新叶子必须提出自己的产品判断，不能复制样稿的 URL、看板状态、名额或通知策略。

## 新的产物与流程

新增 `atlas.product-reference.v1`，与原 product-blueprint 分开。规范包含产品边界、角色、业务对象、操作、入口、旅程、规则、声明式验收、开发范围、依据和未知项。宿主状态不属于作者内容，输入 `passed` 或 runtime 状态会被拒绝。

常规生成保持三类主要会话，不为每个维度增加一次调用：

1. **固定材料研究**：读取既有叶子/场景和固定案例材料，形成源码定位、事实和缺口。现有发现/固定源码能力继续复用；新 profile 不自行发现或替换来源。
2. **完整产品建模**：一次会话内推导角色 → 对象/状态 → 操作 → 入口 → 旅程 → 共用规则 → 声明式验收 → P0/P1 选择。没有 1–5 个功能的上限，也没有页面数量配额；适用性由目标产品决定。
3. **独立完整审阅**：新会话先提出自己的检查问题，再检查范围、旅程、权限/状态、来源、验收、切片及限制。逐条观察接受/拒绝并说明理由；核心矛盾不可降级为美化建议。

两次模型调用之间由宿主检查 ID、引用、操作入口、角色匹配、状态转换、断言覆盖、依赖循环和核心未知。新 profile 独立绑定版本、提示、固定输入和文件字节，不修改 `full-leaf-v1` 及旧冻结检查点。

研究/作者/审阅分别持久化输入、绑定、返回及会话身份；成功检查点重放不再次调用。启动意图不确定时拒绝盲目补调。内容 `needs_changes` 被保留，不当作协议失败自动再审。新规格不能复用旧规格的 pass。

审阅材料保留原 JSON，并生成完整结构视图、按 JSON pointer/SHA 绑定的长文本分页和固定源码视图；实际工具读取内容须覆盖且与原字节一致。读取过行号但内容伪造、材料中途改变或只读部分内容都不能通过。

## 完整参考与开发切片

`select_scope` 从选定旅程及显式操作依赖计算角色、对象、规则、入口、断言和依据。规则引用的对象及对象关系也纳入依赖；同页面的其他操作不自动进入本阶段。混合 P0/P1 的断言不会被偷偷拆成已覆盖，若因此失去所选操作/规则/旅程的验收覆盖，必须修订规格。

返回范围清单和完整原规格，明确 deferred_action_ids。参考阶段只有声明式验收，不生成空 `probe.py` 冒充标准开发包。未来选定范围后，技术设计、可执行验收与标准开发交接仍需按开发包合同另行生成和验证。

通过独立静态审阅的 reference.zip 有自己的类型、输入/规格/提示/案例/审阅摘要、会话、文件清单和状态；不直接当作旧 blueprint 导入，不自动发布。它不证明应用运行或服务在线。

## 用户入口与草案阅读

工厂新增 `?view=references`“产品参考”入口：

- 阅读三份原始设计样稿，按原包 SHA 核验；明确未独审、未运行。
- 上传 ProductReference JSON 草案，查看关联和按旅程选定的开发范围。
- 导出带摘要清单的**未审阅参考包**；不是标准开发包，不修改生产目录、CaseLibrary、队列或预算。
- Markdown 关联 ID 可跳转，嵌入 HTML 不执行，远程图片不加载。

接口：

- `GET /api/factory/product-reference-examples[?key=01-personal-bookmarks]`
- `POST /api/factory/product-references/preview`
- `POST /api/factory/product-references/export-preview`

POST 输入为 `{reference, source_ids?: string[], scope_id?: string}`。这里调用者提交的 source_ids **只用于草案结构检查**，状态始终 source_verification/independent_review/application_runtime = not_run，不能登记为受信案例证据。
