## 5. 真实调用前必须补齐的宿主衔接

### 5.1 单项引用与六项汇总引用一致

当前 cognition.py 只将 program-evidence/ 写入 phase 的 design_context；六维合并 validate_review 却读取共享 context 的 tree_manifest。
因此新 phase 若合法引用 program-evidence/prepared/acceptance/p0_organize.py，单项能通过，汇总仍可能报 review cites nonexistent source file。

最小修复：把同一个已严格校验的 23 文件包，以相同路径和相同字节供六维合并校验使用。可将其镜像至共享 context/program-evidence/；如现有结构更适合逐维固定 inventory 合并，也必须保持同样严格性。
- 每一维仍必须先按自己实际见到的 inventory 校验。
- 其他五维的模型可见投影不加入补证文件、不改变提示。
- 合并时保留合法的原引用；禁止删引用、替成 DRAFT.md 或放宽“文件存在/身份”校验。
- 不允许某维引用它没有见过的材料。
- 不把补证历史授权当成当前调用的系统指令。

### 5.2 同时处理内层 phase 与外层旧 blocked 缓存

普通同任务重试会先命中外层六维旧汇总，甚至不会进入单维重审；仅允许新 phase projection 不够。

建立受正式授权约束的追加记录机制：
- 原 phase blocked、原五项 passed、原六维 blocked 总览及其原始报告/输入永不覆盖。
- 新 phase 结果保存为一份追加记录，绑定旧 CP、原 proposal、新 projection、grant、CLI reservation 和恢复 attempt。
- 新六维组合记录引用五份核验一致的旧 passed 与这份新的 phase 结果，保留各自来源，不重写旧总览。
- 新 phase 与新组合的 scope 元数据应准确说明“静态规格及补充的既有程序证据审阅，未执行程序、未验证实际 P0”；不继续声称审阅未见任何程序。其他五维与原历史报告的 scope 不改写。
- 建立显式、可审计的有效审阅选择/替代关系；只能由合法补证资格产生。
- R7 后续程序消费必须使用该有效六维组合；不得沿用旧 blocked 总览，也不得仅看新 phase 而绕过其他维度。
- 没有授权、身份不匹配或普通恢复调用，仍执行原 checkpoint_changed/旧结果逻辑；不得全局放宽检查点不可变规则。
- 存储可增加带 recovery id 的追加键，但预算逻辑仍归原 phase scope，不能把新存储键解释成免费首次调用。

登记独立于旧 R5 protocol grant 的、仅适用当前 R7 phase 的证据补充重审资格。

### 6.4 原子恢复与幂等

通过正式事务在加锁后再次核验当前 job failed/attempt1、父与后继 paused、active0、77 次基线、7/7、旧 grant1/1、proposal/CP/字节/期限和一次性资格。
登记/激活恢复关系与同 job 的恢复就绪状态必须事务一致；失败不得留下半激活资格或可无授权启动的任务。
保持同一 job，正式推进下一 attempt，原 attempt1 的历史与失败事件保留。不得创建替代 job/product/campaign 绕过当前历史。
父计划保持 paused 直到恢复回执、状态和资格读回验证完成，再通过正式 action resume；禁止用通用 batch retry 误启旧 R5/R6 失败任务。
同 request_key 的重放返回同一恢复/回执，不再增加 attempt、不再登记额度、不改变截止；不同 request_key 也不能为同一已绑定补证重复铸造资格。

实际 CLI 启动需同时受唯一 reservation、token/lease 与授权消费状态约束：在 Popen 或任何 provider 启动之前，以同一写事务原子校验并占用唯一补证资格与预算 reservation，确认启动后记录 started 与真实调用。队列登记本身不能伪报已调用；Popen 后启动标记写入失败也不得自动释放资格或重新启动，应保留占用/uncertain 并核对原进程证据。
如果能证明未启动，可复用同一未消费资格；一旦已经启动或无法排除已启动，不得通过崩溃恢复再自动发第二次调用。
网络/外部进程无法靠数据库事务保证绝对 exactly-once：结果丢失或启动状态不确定时，应保留 uncertain 状态和原始证据，不能盲重发。
模型已返回 blocked/uncertain、协议失败或超时，都不产生第二次自动补证调用资格。

在登记、恢复及每次新调用启动前按既有机制检查绝对截止。到期不得新增生产调用，不通过延长 CLI timeout、排队时间或暂停来重开窗口。
