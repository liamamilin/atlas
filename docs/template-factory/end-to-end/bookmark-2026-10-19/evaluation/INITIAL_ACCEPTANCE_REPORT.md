# Initial bookmark app acceptance report

The frozen P0 UI workflow and real process restart passed in `initial-retry-3`. The runner verified the frozen ZIP/receipt and unchanged application source hashes, used the declared `python3 -m app --host 0.0.0.0 --port 8000 --data-dir /state/data`, isolated state in a dedicated Docker volume, published only on `127.0.0.1`, and drove the UI using Chromium. The browser context allowed only the app and local fixture origins. Docker used a dedicated bridge; bridge egress was not blocked.

All initial UI checks passed: save in the default category; create a category; save and move a record; browse categories; search by title and URL; click both saved fixture URLs; verify XSS-shaped title safety; reject empty, malformed, JavaScript, and data URLs without changing the bookmark inventory; reject blank and duplicate category names; and observe duplicate URL submission. The duplicate URL action created another row (`1 -> 2`), which remains an observation because the frozen P0 contract does not require URL uniqueness. After an actual Docker container restart, the stored collections, bookmarks, move, searches, and exact destination URLs remained available. The container `StartedAt` changed. Source hashes matched before and after. The run's owned resources were all removed and absence-verified.

A separate, explicitly post-hoc HTTP exploration (`posthoc-http-3`) found two issues in the initial app. First, a URL containing CRLF was accepted with HTTP 303 and persisted. A no-follow request to `/go/1` returned HTTP 302 with an injected `X-Codex-Probe` response header. Second, in 20 simultaneous pairs of same-name category requests, all rounds had one HTTP 303 and one HTTP 400, with no HTTP 500, but six of the 303-acknowledged categories were absent from the subsequent rendered inventory. The raw HTML snapshots, response headers, request statuses, Docker logs, and cleanup evidence are in `posthoc-http-3/`; these are exploratory findings outside the frozen P0 verdict.

`initial-retry-1/2` and `posthoc-http-1/2` retain earlier environment or harness failures. Their `classification-correction.json` files explain why those runs are not product evidence. The machine-readable roll-up is `INITIAL_ACCEPTANCE_REPORT.json`.
