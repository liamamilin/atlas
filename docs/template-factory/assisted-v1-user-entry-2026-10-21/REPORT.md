# Atlas 辅助模板工厂 V1：收口与用户入口

本轮以已验证的Codex辅助生产范围收口。现有16份辅助模板全部接入叶子、场景、固定案例与制品路径；6份具有核心运行示例，10份应用未运行。没有将辅助试产升级成严格G1/T08。

## 使用路径

- 浏览类型 → 叶子 → 应用场景与模板 → 对应场景 → 辅助模板 → 阅读/标准开发包。
- 应用实证 → 选择固定案例版本 → 辅助试用模板 → 查看/导出。
- 工厂制品页可以按名称和辅助运行状态查找；场景链接精确筛选并可返回全部模板。

可从[家庭库存叶子](http://127.0.0.1:5188/types/home-inventory-application)、[专注计时叶子](http://127.0.0.1:5188/types/focus-timer)、[笔记叶子](http://127.0.0.1:5188/types/note-taking-application)开始。

每份模板显示适用用户、问题、P0核心能力、已知限制、固定仓库commit/许可证与共享案例版本。已有示例提供使用说明、源码ZIP和原运行证据。标准开发包可直接下载，也保留原阶段导出表单。Codex开始说明可复制，指向HANDOFF.md、CURRENT_PHASE.json、ACCEPTANCE_CONTRACT.json、APP_DELIVERY.md、PROJECT_DECISIONS.json，完整认知按需读取。

## 范围与状态

| 状态 | 模板 |
|---|---|
|已有核心运行示例（6）|书签、月度预算、多项目会议笔记、家庭库存、晚餐计划、聚餐投票|
|应用未运行（10）|专注计时、出行英语、个人书架、城市行程、项目工时、力量训练日志、文章大纲、时间块顺延、流程图、沙箱文件整理|

示例状态只表示历史报告所列核心旅程已验证，不证明严格工厂验收、正式发布或本机服务当前在线。未运行模板没有虚构源码/运行证据链接。若绑定文件丢失或SHA变化，相关下载不可用，核心运行徽标降为证据不可核对，不继续显示通过。原正式发布区仍读取published和原catalog_eligible条件，没有改门禁。

辅助V1承诺的流程：Codex选择/研究真实案例和编写场景、规范及验收 → 现有服务保存案例与场景 → 冻结/导出/导入 → Codex消费标准包实现代表应用 → 浏览器及持久化实测 → 登记可回查的辅助材料。研究、写模板、开发、人工浏览器验证仍需Codex介入；不是自治生产或全叶子覆盖。浏览与下载不要求已配置provider或Docker；严格验收能力单独保留。

## 实现与合同

- `examples/assisted-trials/CATALOG.json`为16份现有制品的只读导航侧表，绑定原artifact_id/digest和既有标准包、说明、源码、证据SHA。产品/场景内容从真实冻结包读取，不复制另建可漂移的规格。
- `GET /api/factory/assisted-templates`支持leaf、scenario_id、case_id、case_revision、artifact_id交集筛选；返回内容、固定案例、辅助状态与可用下载。
- `GET /api/factory/assisted-templates/<id>/files/<kind>`只允许development/guide/source/evidence四个已登记文件；限制在仓库docs/examples下，拒绝绝对路径、越界、符号链接、未知身份和摘要变化。没有任意文件读取或新写入端点。
- 原`GET artifacts`增加只读scenario_id投影，来自宿主job.snapshot.scenario.id；不按标题猜测，不改制品及摘要。按场景能同时展示辅助与原正式制品。
- 新的用户信息不写acceptance、publication、预算、job、grant或G1。原导入/下载/标准阶段导出继续工作，原文件不重打。
- 聚餐许可证入口读取共享案例固定COPYING，不改旧冻结正文或原case。
- API重启现场发现原刷新失败提示恢复后残留；拆分刷新错误与操作错误。刷新成功清除前者，操作失败保留；加载中不再误显示“没有模板”。

## 实际验证

1. 正式本机API读取16份记录，准确6/10；逐一按叶子/场景/案例查回。34个真实文件下载逐一验证SHA；每份标准包的六个开始文件均存在，见REAL_API_CHECKS.json。
2. SCENARIO_ID_CHECKS.json核对16份模板与宿主场景ID对应，原正式模板不因只支持辅助索引而被隐藏。
3. 真实IAB浏览器走通家庭库存、专注计时、会议笔记三条路径；点击标准包下载、回查Homebox/Joplin r2、阅读说明并复制Codex文本。验证未运行场景没有示例下载。实际筛选6/10及逐步页面文本见BROWSER_RESULTS.json和01–12文本，截图见six-core-examples.png、codex-start.png。
4. 新增8项后端回归：历史状态不冒充在线/严格验收、筛选、文件变更拒绝、版本不符、非辅助不能借用证据、路径和符号链接、未运行缺链接、只读场景身份。
5. 后端完整770项，8项显式Docker opt-in跳过，其余通过；不把跳过算运行通过。既有认知包21项回归通过。日志见backend-full-tests.log、backend-blueprint-tests.log。
6. 类型检查、前端9项单测、构建通过。完整工厂E2E31项通过；最后新增刷新恢复用例后的入口专项5项通过。常规E2E17项通过。精确提交的CI另行核对，不用本地结果代替远端状态。
7. PRESERVATION_BEFORE/AFTER核对81个既有ZIP及数据库文件（包含六个应用数据库）及17张受保护历史表摘要不变，包含原预算、grant、任务、制品、场景、案例与G1记录。未新建campaign、重置调用或改写失败记录。

没有新增OpenCode受控模型调用，原CLI87/500、书签业务修复8/8保持；严格G1仍blocked，T08未启动。本轮也未运行新的示例应用。

## 后续内容生产

继续已有MANIFEST、执行说明、produce_batch.py、CaseLibrary及导出工具。按真实需求选场景，不默认扩大覆盖或增加代表应用。生产完成后将制品和已核对材料登记到CATALOG.json，绑定固定摘要；取得核心运行证据后才更新辅助状态。新增登记应执行目录、文件摘要与入口回归。

已知边界：侧表引用当前已登记的制品身份；新机器须先恢复原工厂数据或按正式导入结果更新绑定，缺失时显示不可用，不自动伪造身份。源码或说明修改需要明确更新交付/摘要关联。历史示例仍有各自非核心缺口，按其原报告保留，不宣称本轮补齐。
