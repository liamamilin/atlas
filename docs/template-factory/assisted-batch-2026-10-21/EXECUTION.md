# 辅助小批次统一执行说明 v1

执行对象为 MANIFEST.json 已固定的三个不同叶子；代表场景在开始时固定为家庭库存，不因失败替换样本。研究与编写由 Codex 完成，不冒称 OpenCode 自动生产或独立审阅。

1. 读取正式 applications/<leaf>.md，保存正文摘要；场景须保留叶子定义核心，明确用户、目标、完整核心旅程与后置范围。
2. 通过现有场景服务保存草案，保存 ID/r1。重复执行使用已保存 ID，校验相同内容；不重新创建身份或静默覆盖修订。
3. 查找已有共享案例。没有合适记录时，固定真实公开仓库 commit、代码/文档路径与行号、文件摘要和许可证。代码观察、文档声明、目标推断、上游运行分别说明；本轮上游未运行、独立证据审阅 pending。
4. 经 CaseLibrary.commit_research 保存共享记录和场景关联；稳定幂等键，应用实证和模板引用同一 case_id/revision/digest，重复执行不新增案例身份。
5. 编写该场景 definition.json、acceptance/ 核心验收程序、边界/错误要求、数据和交互契约、P0与后置缺口。必须在开发应用前完成。
6. 统一调用 examples/assisted-trials/export_trial.py。它调用现有 render/freeze/export_development；已存在的输出只校验摘要、固定输入和库存，不覆盖。冻结快照与可导入认知包结构不同，导入前须验外层后保留来源摘要映射。
7. 经 POST /api/factory/blueprints/import 登记辅助模板，保存真实响应与目录地址，重复导入复用。读取详情、共享案例并从既有 development-package 接口导出/下载，验证契约及来源字节一致。
8. 仅家庭库存：将已导出的标准开发包交给新的开发上下文。新上下文先读 HANDOFF/CURRENT_PHASE/契约，登记消费摘要后实现独立源码。不得读取或改写原三个应用数据库。
9. 主上下文实际启动代表应用，操作3–5组浏览器旅程，核对核心结果、刷新、停进程/同目录重启。其他两个明确标记 not_run，不以静态导出冒称运行通过。
10. 单项失败保留 failure.json 和恢复步骤，继续其他项；最终报告完成/失败、目录/下载入口、人工步骤和正式历史只读状态。抽一个完成项重复执行，证明案例身份、制品、输出及用户库均未改变。

此说明不增加调度平台、宽松模式、模型资格或预算。新增 OpenCode 调用若发生仍须计入原500；本轮优先Codex直接研究/编写，原87/500、业务修复8/8及严格G1/T08不重置。
