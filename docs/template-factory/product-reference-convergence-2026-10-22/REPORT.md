# 两样本认知参考模板收敛

本轮保持全量派发暂停，沿用原计划与账本，仅处理书签和同机聚餐投票两个固定样本。生产渠道为 OpenCode CLI 的 `open-design/deepseek-v4.1-flash`，不开发应用，不推进严格 G1/T08。

## 已实现的共性修复

- 向生成模型提供完整输出 schema、字段类型、枚举和固定来源 ID；确定性检查聚合对象、动作、断言、范围切片的引用与覆盖错误，避免逐个报错消耗调用。
- 固定研究记录由宿主保留，生成内容引用既有观察；模型不得改写案例身份、源码版本或已接受的研究观察。
- 新修订绑定父候选、原失败、输入、案例、提示及精确源码 CI；优先支持受限 JSON Pointer 补丁，兼容完整 reference 返回。缓存、实际交付和阶段计账在恢复后复用。
- 独立审阅绑定新输入摘要，核验全部规定材料的真实读取。标准结构副本未读全时，仅在完整权威 JSON、长字段分页、源码及原始会话事件证明等价完整阅读的情况下生成明确的 `canonical_equivalent` 证明；正式导入重新计算，不相信单独的声明。
- 已真实交付但读取不完整的 `needs_changes` 只能作为经身份验证的未合格修订线索，不能成为通过证据。新版本仍要独立完整复审；原始失败、返回和未生成的合格回执状态不被覆写。
- 新增已审阅产品参考目录、详情阅读、固定案例回查和冻结 ZIP 下载；下载使用安全 ASCII 文件名。原正式模板与辅助应用目录保持原含义。

## 交付边界

本轮新制品类型为完整产品认知参考包 `atlas.product-reference.v1`，包含产品形态、对象、角色、规则、动作、用户旅程、交互界面、范围切片、断言、案例研究与独审记录。它不是带实现代码及可执行验收程序的旧标准开发包。静态通过不表示应用运行通过，也不表示严格正式发布。

### 投票的准确停止点

`polling-application/r3/OUTCOME.json` 的宿主失败是 `readable/source/upstream/COPYING` 未完整读取。不能只修这个门禁就视为通过：同一真实独审还明确提出了 7 项内容问题，原文和输入摘要保存在 `generation/review/RESULT.json`，汇总见 `READ_AND_CONTENT_AUDIT.json`。

1. 跨投票断言实际依赖 `select_poll`，声明的动作集合却未包含，导致被错误计入推迟该动作的核心切片。
2. 核心旅程与界面仍提及被切片推迟的投票码检查及投票目录界面。
3. “展示投票码原选项”的替换提示与不披露个人选项的隐私规则冲突。
4. 错误口令、空或过短口令、失败计数与成员功能可用性没有独立失败断言。
5. 丢失主办口令后“新建同目录投票恢复”的说明不可达，创建本身也需要解锁。
6. 空问题拒绝分支缺少不落盘断言。
7. 主办者门禁断言包含关闭和重开，却未关联对应旅程。

阅读审计还发现 COPYING 为 0/661 行、Vote.php 为 0/123 行；Poll.php 为 640/1045 行，README 为 71/71 行。引用观察在原始返回中均被接受不等于已完整阅读全部规定文件。不存在 `REVIEW_RESULT.json` 或冻结 ZIP，不补造合格回执。

两个叶子各自已用满原每叶 6 次，pilot 为 12/12。本轮新增 8 次，计划新增从 178 到 186，加原历史 99 次累计 **285**；活动调用 0。原 7,200 新增上限、30 天绝对截止、历史调用及失败不变。本试跑已通过正式服务暂停，回执 `PILOT_PAUSE_RECEIPT.json`；全量仍为用户暂停。后续修订没有自动启动。
