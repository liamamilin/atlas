# 运行阶段验收

需要 Node 和 Playwright Chromium。在本目录执行 `npm install`，再执行 `npx playwright install chromium`。版本固定在 package.json；若机器已有相同版本，可设置 NODE_PATH 指向它的 node_modules，无需重复安装。

先由开发 agent 实现目标应用，再在自己的目录启动只监听本地的预览。运行示例：

```sh
node acceptance/run.cjs --base-url http://127.0.0.1:5220 --phase P0 --out /tmp/bookmark-P0.json
```

程序每个用例使用新的浏览器上下文，仅使用合成测试记录，不读取或清理用户真实收藏。只允许访问指定本地预览来源；外部链接点击记录真实导航请求后阻断出站，不访问网页内容。退出码 0 表示选中的测试通过，非零表示失败或执行环境/参数错误；报告区分未选阶段，不能把它们当作已验收。

P0 的十项测试包含正常流程、同一持久 profile 的浏览器重启、首次打开/已有库读取故障、写事务中止、新建/编辑危险 URL 与 HTML 注入、保存期间外发检查和重复提交。A01 的临时 profile 在结束后清理，不操作用户 profile。外链点击用例仅允许所点击目标的一次请求尝试；预览服务的 CSP 拦截也不能掩盖尝试外发。此网络观察覆盖测试操作及结束后 100ms，不证明任意延时或所有侧信道。P1 五项检查删除后刷新/恢复与导入导出，含混合有效/无效批次；P2 两项检查去重与批量事务，包含写事务数量与失败回滚。尚未实现的阶段执行时应失败，而非被标绿。

`--case A01` 可只运行一个用例；`--fault cancel-submit` 仅用于验收工具负向自检：在浏览器侧故意阻止保存提交，A01 应失败。该模式不是产品验收，也不能把它的预期失败作为产品通过证据。

当前存储故障注入针对默认 IndexedDB，替换仓储必须提供等价故障适配，不能直接把这些结果推及其他存储。本程序的中文 role/label 是明确的适配契约。若目标用不同文案或框架，修改有记录的 UI 适配层，保留相同的行为断言。所有测试操作仅发生在新的自动化浏览器上下文。默认等待 5 秒可通过 BOOKMARK_TEST_TIMEOUT_MS 调整，这是测试环境参数，不是产品 SLA。
