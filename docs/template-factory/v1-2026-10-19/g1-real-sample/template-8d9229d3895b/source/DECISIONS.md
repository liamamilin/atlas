# 决策与默认值

## D01 · 记录应归属于单一“归类”，还是允许像标签一样同时属于多个？

单选归类（bookmark.category_id 标量外键）。场景流程明确“选择一个简单归类”，单归属让移动、计数与浏览语义无歧义；未来若需多值可迁移到关联表而不丢数据。

When to ask / 询问条件: 当真实用户反馈同一条记录必须同时属于多个主题，或需要跨主题交叉检索时再评估多标签。

决定数据模型（标量外键 vs 关联表）以及浏览、计数与检索的实现路径。

decided

## D02 · 保存时不选归类，应阻止保存还是落入默认“未整理”？

落入默认“未整理”，保存始终成功。场景流程第3步要求未经整理的链接可先进入默认归类，快速保存不应打断浏览。

When to ask / 询问条件: 当目标用户群要求强制归类（例如团队共享库）时再改为必选。

决定保存接口是否允许缺省 category，以及首启预置数据内容。

decided

## D03 · 在保存或移动界面输入一个尚不存在的归类名，应自动创建还是报错？

自动创建（名称大小写不敏感去重），重名则复用现有归类；保持保存流程不中断。

When to ask / 询问条件: 当出现拼写错误导致归类碎片化的证据时，改为只允许从既有归类中选择。

决定 categories 的唯一约束、写入事务边界与 409 的语义。

decided

## D04 · 删除是立即物理删除，还是软删除到可恢复区并支持短时撤销？

软删除：记录标记 trashed_at，默认视图排除，提供撤销恢复；场景要求可恢复的失败。

When to ask / 询问条件: 当用户要求彻底清除隐私数据或回收站增长需要释放空间时，再提供永久删除与清空。

决定数据模型的 trashed_at 列、列表过滤条件，以及 /restore 与 purge 接口。

decided

## D05 · 标题、描述与图标是否依赖第三方抓取服务？

本地优先：图标由域名派生本地路由，第三方元数据抓取为可选增强且失败静默降级，保证离线可保存。

When to ask / 询问条件: 当部署环境确认可访问外部服务且用户需要富预览时再启用增强。

决定保存流程的时延与可用性依赖，以及收藏响应中的 favicon/title 字段形态。

decided

## D06 · 同一 URL 再次保存时，阻止还是允许？

自 P1/F14 起默认检测并返回 409 duplicate_url（附已有 id 供跳转查看），保存方显式 allow_duplicate 时可强制新增；P0 核心用例不依赖去重，软删除记录不参与判定；场景与成熟产品都倾向一址一记录。

When to ask / 询问条件: 当用户明确需要对同一地址保留多个不同上下文的记录时再放宽。

决定服务层去重查询、allow_duplicate 语义与导入时的合并或跳过策略（不使用 url 唯一索引）。

decided

## D07 · 关键字应匹配哪些字段？

标题加域名(hostname)加描述，大小写不敏感，可与归类过滤叠加；不检索正文（无抓取）。

When to ask / 询问条件: 当需要按网页正文全文检索时再引入抓取与索引（属后期能力）。

决定查询实现与检索参数语义。

decided

## D08 · 采用何种运行时与持久化方式？

python-web 加 Python 3.12 标准库 http.server 加单文件 SQLite；满足离线、单用户与可独立验收，无需外部依赖。

When to ask / 询问条件: 当需要多用户、并发写入或托管部署时再引入 Web 框架与服务端数据库。

决定交付 profile、验收方式与部署命令形态。

decided

## D09 · 是否需要登录或口令？

默认无认证；交付进程在独立验收网络中监听测试者可路由的接口（`--host 0.0.0.0`），日常本机使用可绑定 127.0.0.1；不引入凭据文件，符合个人本地库的定位。

When to ask / 询问条件: 当应用需要暴露到局域网或公网时，必须加入认证，否则只允许本机绑定。

决定部署方式与验收的认证契约（验收默认不携带凭据）。

decided

## D10 · 导入/导出采用什么格式？

Netscape 浏览器书签 HTML（本类型的交换约定），归类映射为文件夹或标签字段。

When to ask / 询问条件: 当需要与某个具体产品双向同步时再适配其专有格式。

决定 P1 导入/导出的解析与生成实现。

decided

## D11 · 是否提供云同步或多用户共享？

P0 不做：本地单实例，数据在单一 SQLite 文件；跨设备属后期能力。

When to ask / 询问条件: 当用户明确需要在多设备访问同一库时再设计同步或托管。

影响运行形态与数据归属，不阻塞 P0 核心旅程。

deferred

## D12 · 归类是否需要嵌套层级，或与标签并存？

P0 使用扁平单选归类加“未整理”收件区；嵌套与标签属成熟能力，按需在后期启用。

When to ask / 询问条件: 当扁平归类数量增长到难以浏览，或需要交叉主题时。

影响侧栏结构与检索实现，可后续迁移而不破坏现有数据。

deferred

## D13 · 是否需要保存网页副本并检测失效链接？

本期不做：抓取与归档在离线验收下不可验证；先保证引用记录与打开回跳。

When to ask / 询问条件: 当用户明确要求内容留存，或需要清理死链时再评估。

涉及外部抓取与存储扩展，属后期可选能力，不纳入 P0/P1 验收。

open
