# 模型临时错误自动重试

2026-10-23。此前仅恢复了暂停批次，尚未实现自动重试；本次补齐持续批量流程的恢复和错误记录。

## 行为

- 临时 HTTP 408、425、429、500、502、503、504，超时、临时连接失败或连接中断：一次请求最多尝试 **3 次，含首次**，默认等待 **2 秒、4 秒**。
- `Retry-After` 要求更长等待时遵守它；超过 60 秒时保存并暂停，不提前重试。永久请求错误、认证失败、模型或地址配置错误不自动重试。
- 明确余额或额度耗尽仍按既有规则切换至 OpenCode Go / `deepseek-v4.1-flash`。如果 Go 遇到临时错误，后续重试留在 Go，模型缓存和回执也使用实际服务身份。
- 重试耗尽后状态为 `paused_model`；已完成目标和已读取资料保留，未完成目标不伪装成成功。继续同一任务只处理未完成目标。
- 运行记录增加 `model_retry_policy`、`model_errors`、`model_retry`，保留阶段、provider、model、上游 HTTP 状态、脱敏错误摘要、尝试次数与等待时间。保存重试等待状态后再等待，便于事后排查。
- 不持久保存请求头或密钥；上游响应即使反射自定义格式的密钥，也先替换密钥再截断摘要。

这次只为项目发现与整理的模型请求增加自动重试；现有通用模型接口、认证及额度切换边界保持原有行为。模型返回无效业务 JSON 的格式重试仍独立且有上限。

## 验证

[LIVE_RECOVERY.json](LIVE_RECOVERY.json)：在隔离配置中只注入首次 HTTP 503，等待后通过真实 Open Design 请求得到正确 JSON，再次同样请求命中缓存。没有向正在运行的生产批次注入故障，也没有改写本机模型配置。这能证明自动恢复路径可用，不能反推此前丢失的 HTTP 错误详情。

95 项相关测试通过：项目库与批量 60 项（包含新增 9 项恢复测试）、模型切换 10 项、GitHub 设置 5 项、模型设置 20 项。覆盖瞬时失败成功、失败耗尽暂停、限流等待、永久错误不重试、Go 切换后重试、脱敏、暂停后恢复不重放已保存目标。Ruff 和补丁空白检查通过。见 [CHECKS.json](CHECKS.json)。

新 API 已实际记录 `max_attempts: 3` 的重试策略，当前 100 叶子任务沿用原 ID，并从已完成 288 个候选处继续。加载前后项目、场景、关联、收藏及候选表校验一致，已完成目标一致。服务加载与数据检查见 [SERVICE.json](SERVICE.json)，接入后的实际进度见 [PROGRESS.json](PROGRESS.json)。本批尚未完成，因此本次不做整批质量验收，也不启动下一批 100 个叶子。
