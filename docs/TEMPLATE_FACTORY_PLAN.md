## 目标与已确认边界

生产目录由 **叶子类型 + 应用场景** 构成。场景描述用户、目标、核心流程和可观察验收条件，经确认后才能送入模板生产。工厂支持批量目录项、受控并发、持久化状态及失败恢复。

生产 agent 暂时统一使用 **OpenCode CLI**。provider/model 可配置，优先经济型模型；Atlas 不直接调用模型 API，不静默换成更贵的模型，也不预设搜索次数。搜索能力与计费以实际 provider/工具为准。

**生产和验收分开。** Docker 不是生产前置条件。搜索、选型、固定源码、改造、参数化、形式检查和冻结交付完成后，生产任务即可完成。原项目的 Docker 试跑不再是生产阶段。验收单独排队，可按需选择源码审阅或运行验收；等待、失败、环境不可用均不占用生产并发。

## 当前范围

1. 场景手动创建、修订、确认与归档；CLI 批量提出场景草案，每条草案自动进入独立 Agent 审阅，不能自动确认。已有场景支持单项或批量送审。
2. 顶部“模板工厂”入口，目录/任务批次/制品视图；叶子页展示场景及已发布模板。
3. SQLite 持久队列与不可变任务输入；独立 worker、批次暂停/继续/取消、任务重试、租约与迟到结果隔离。
4. CLI 搜索、固定 GitHub commit、源码勘察、模板改造；保留来源、阶段检查点及所有尝试。
5. `project_name` 参数与显式文本文件清单；在全新目录确定性渲染，无须模型、安装或宿主命令；模板包/应用包下载。
6. 生产冻结候选；独立 Harness 只读源码审阅；可选 Docker 安装/构建/启动和浏览器/CLI 运行验收。
7. 验收绑定制品摘要、方法、范围、结果与证据。修复产生新的生产任务和冻结制品，不覆盖原版本；源码修复默认复用冻结计划，只有显式选择才重建技术计划，场景与验收条件仍固定。
8. 显式审阅发布/下架；已发布模板可以从对应叶子页创建应用包。

## 状态与等级

生产状态、验收状态、等级、发布状态分别记录。

| 等级 | 当前定义 | 不能由此推断 |
| --- | --- | --- |
| L0 候选 | 形式检查、参数化与两组名称渲染通过，制品冻结 | 应用已经运行成功 |
| L1 可行 | 至少一种独立验收通过：Harness 源码审阅或运行验收 | 源码审阅等同实际运行 |
| L2 标准 | 已满足 L1，且用户明确记录人工完整性审阅 | 全面安全认证、跨平台认证 |
| L3 成熟 | 后续需要实际下游使用证据；首版不提供自动晋级 | 多次生成或模型自评即成熟 |

Harness 审阅按固定场景逐项给出代码文件引用与理由，结果为通过、阻断问题或待确认。provider/协议/环境错误单独记录，不显示为通过。审阅通过只表示所审阅范围内未发现阻断问题。

运行验收在两个新目录渲染不同项目名称，使用固定计划执行。首版支持静态 Web、Python Web、Node Web 和 CLI 的 Linux 容器配置；不支持的环境可生成 `review-only` 计划并走源码审阅，不伪造运行证据。

发布要求至少一种独立验收通过，加上用户明确审阅；不强制 Docker 运行验收。L0 仍可下载和试用。修订版需要重新送验。

## 技术实现

- `template_factory/store.py`：场景版本、批次/任务、事件、检查点、不可变制品和独立验收记录。
- `worker.py`：单调度器进程锁；生产和验收使用独立线程池/槽位，生产批次并发 1–8，验收独立容量 2；取消撤销所有权。
- `cli.py`：独立 Git 根、正确 `PWD`、任务专用只读 agent、JSONL 事件解析、超时取消、日志脱敏。只允许输入及清理后的源码读取；shell/edit/插件/MCP/skill 禁止。提供文件清单，关闭可跨路径搜索的 glob/grep。
- `sources.py`：GitHub 元数据、固定 commit、归档安全提取、明确许可证与来源声明保留。
- `pipeline.py`：生产到冻结交付；另行执行 Harness 审阅或运行验收；修复从冻结版本创建新制品。支持完整文件覆盖与精确文本替换：旧文本须唯一匹配，缺失/重复/路径冲突均失败，不执行模型提供的补丁命令。
- `scenario_review.py`：独立场景审阅协议，检查类型匹配、区分度、流程、验收和范围；校验原文引用、对照 ID 及五项结论，整体结果由各项结论推导。报告绑定场景版本、叶子与对照内容，更新后标为过期；提供建议，不变更确认状态。
- `artifacts.py`：有限参数协议、哈希清单、完整性检查、确定性 ZIP 和应用渲染。
- `runtime.py`：候选安装/启动命令仅在 Docker 执行，限制资源/权限/挂载；浏览器限制到当前应用源。
- `api.py` 与 `/factory` 页面：目录编辑、批次控制、证据、验收、发布、下载、修订和实例化。

## 已知边界

- 来源是公开 GitHub 仓库；缺失或不明确许可证会停止该项，其他项继续。支持候选不等于承诺全部 1,805 个叶子都能自动成功生产。
- 模型参与验收计划和源码审阅，结论存在模型局限；实际运行证据另列。当前没有全平台/完整供应链安全认证。
- Docker 不挂载 provider 凭据、socket、其他项目或源码目录，容器仅挂载待验实例。容器默认 bridge 网络，没有宣称已隔离出站网络。
- 本地单机能力，worker 使用 POSIX 文件锁。多主机调度、自动更新上游、定期重新认证、配额/成本结算、保留期清理留在后续，不冒充首版已有功能。
- 并发实测如涉及外发 Atlas 类型正文，按相应授权执行；未批准时不绕过自动审批。

## 2026-10-17 自动认知生产增量

生产目录选择已确认场景后，可启动“生产认知模板”。每项独立研究品类、分步生成规范/文件计划与验收代码，由 Atlas 生成主文档、指令与哈希清单并冻结；随后自动排入独立认知审阅。研究检查点可复用，结构失败会携带真实错误和前次输出进行有限修复；失败不创建虚假合格制品。

审阅只读冻结包，逐项检查八个认知维度并引用文件。结果分为通过、阻断、待确认与未完成，均不自动发布或按旧代码模板规则晋级。页面可重新审阅、重试未完成审阅、填写意见并生产修订版；修订固定原场景与研究并保留原制品。

剩余顺序：完成本次真实书签流水线的独立审阅与必要修订 → 用另一类确认场景验证泛化 → 接入项目决策编辑和实际阶段验收 → 根据真实证据明确认知包发布与等级。已有队列支持多场景受控并发，但首例成功不等于全品类质量保证。详见 [验证与边界](template-factory/2026-10-17-cognitive-production.md)。

批量扩大前，继续根据真实试产检查阶段依赖、程序缺陷和产品契约。后续生产效率改进优先稳定跨版本 ID、复用已验证的通用验收工具及按文件提供相关上下文；当前多文件隔离并不等于已证明规模化成本。不得因为模型自评或首例静态通过就自动发布。
