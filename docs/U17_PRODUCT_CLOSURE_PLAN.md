# U17 产品化收口开发计划

日期：2026-09-22  
状态：执行中  
目标：在当前核心功能已经可用的基础上，完成发布前的产品化收口，并通过可重复的开发、检查、浏览器验收和修复循环形成发布候选。

## 1. 完成范围

本计划聚焦产品完整性，不继续追求模型输出指标，也不在本轮建设通用 coding agent harness。

本轮必须交付：

- 核心路径从搜索/浏览到项目完成可以独立走通。
- 项目详情页能区分阻塞当前迭代的问题、可选建议和历史信息。
- 新用户可以理解 Atlas、OpenCode、项目、迭代、任务和验收之间的关系。
- 空状态、加载、失败、处理中、成功和恢复动作都有明确反馈。
- 中文默认、英文切换和关键术语保持一致。
- 自动检查、真实浏览器路径和发布文档形成可重复记录。

明确不纳入本轮：

- 自动回滚/撤销。
- 多 provider 产品化、云端执行和团队协作。
- 并行任务、运行中接管和自动发布。
- 只改善内部指标、不改善用户完成任务能力的性能调优。

## 2. 优先级与阶段

### P0-A：发布基线与核心路径复验

目标：确认当前代码、文档和本地运行方式是同一个发布候选。

任务：

1. 确认 Git 工作区干净、前后端可启动、API 健康检查通过。
2. 运行前端类型检查、生产构建、后端回归、静态脚本检查和文档/JSON 校验。
3. 复验首页、浏览类型、类型叶子、项目列表、项目详情和语言切换。
4. 复验失败、停止、超时、应用冲突、验收失败和清理路径。
5. 把发现的问题按阻塞、误导、可恢复性和纯视觉问题分级。

完成条件：核心路径和 P0 自动检查全部通过；每个异常状态都有安全结束或继续动作。

### P0-B：工作台状态认知收口

目标：用户一眼知道“现在处于什么状态、什么会阻止当前迭代、下一步做什么”。

任务：

1. 将待处理事项分成“阻塞当前迭代”和“可选建议/以后处理”。
2. 已完成迭代不再被历史建议或未批准的非本轮文档显示成未完成。
3. 首屏保留阶段、当前迭代、下一项和完成度；历史证据默认收起。
4. 对没有活动迭代、已有完成迭代、存在失败任务和存在外部变化分别提供不同文案。
5. 复验刷新、返回、切换项目和重新进入后状态不漂移。

完成条件：已完成项目显示完成；活动迭代只显示与当前迭代相关的阻塞项；用户无需阅读长页面判断能否继续。

### P1-A：首次使用引导与示例入口

目标：第一次使用的开发者可以在不阅读完整设计文档的情况下完成第一次成功路径。

任务：

1. 在首页或项目入口增加“从案例开始”的明确入口。
2. 提供新想法、已有项目改进、Agent Harness 调研三个案例说明，明确适用场景和预期产物。
3. 在项目工作台首次进入时解释资料、需求、文档、基线、迭代、任务和验收的关系。
4. 明确 Atlas 负责项目知识、编排和验收；OpenCode 负责实际 agent 执行。
5. 在本地服务未启动或 OpenCode 不可用时，显示面向用户的检查步骤，而不是只显示连接错误。
6. 让用户可以跳过引导，并在教程中再次打开。

完成条件：新用户可以从案例入口创建项目，知道下一步和完成标准；高级技术信息仍可按需查看。

### P1-B：发布候选与文档收口

目标：把当前结果整理成可以交接、复验和发布的候选版本。

任务：

1. 更新发布检查清单中已验证和仍未覆盖的项目。
2. 更新 README、产品打磨计划和开发规划中的当前状态与限制。
3. 记录构建体积提示、OpenCode 单 provider 限制和未实现能力。
4. 生成发布说明，包含核心路径、已知限制、启动方式和恢复方式。
5. 在发布候选分支上重新执行自动检查和浏览器复验。

完成条件：发布文档与实际行为一致；未完成能力明确标为范围外或后续计划；工作区干净。

## 3. 每轮执行循环

每轮严格按以下顺序执行：

1. **规划**：从本计划选择一个最小用户可感知主题，写出完成条件。
2. **开发**：修改实现、文案或文档，不混入无关功能。
3. **自动检查**：运行与改动匹配的类型检查、构建、回归或静态检查。
4. **浏览器验收**：在真实页面检查正常、空、错、处理中和完成状态；涉及数据写入时使用隔离项目或只读路径。
5. **修复**：任何阻塞或误导都回到当前轮修复，不把失败留到最后统一处理。
6. **记录**：更新本计划、发布清单或对应验证档案，记录限制和证据。
7. **提交**：工作区干净后提交并推送发布候选分支。

## 4. 发布门槛

满足以下条件才算本计划完成：

- 核心路径从搜索/浏览到项目完成通过一次真实浏览器复验。
- 新想法和已有项目入口都能走到工作区，状态不混用。
- 失败、停止、超时、应用冲突和验收失败都有保留证据及继续/安全结束动作。
- 已完成迭代显示完成，不被历史项目建议误导。
- 首次使用者能从案例或教程理解下一步，不需要先阅读内部设计文档。
- 前端类型检查、生产构建、后端回归、静态检查和 `git diff --check` 通过。
- 发布清单、README、开发规划和本计划的状态一致。
- Git 工作区干净，并形成可交接的发布候选提交。
