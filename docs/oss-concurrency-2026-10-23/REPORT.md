# 两路模型并发验收

2026-10-23，已为当前 100 叶子任务启用两路模型提取并发。原先 GitHub 资料读取已有 4 路并发，模型组逐个等待；现在两个模型组可同时请求，每组仍整理 4 个项目。

## 实现与边界

- 默认模型并发数为 2，资料读取仍为 4。叶子依次推进；场景、候选、来源、许可证及入库规则保持一致。
- 模型组隔离调用计数、回执、重试和缓存状态，保存时加锁汇总到当前运行记录。数据库项目写入与单项检查点由同一协调线程顺序完成。
- 一组模型服务不可用时，其他已成功的组仍保存；尚未完成目标保持待恢复，后续排队组停止发起请求。临时错误重试、认证边界和额度耗尽后的 Go 切换仍有效。
- `run.concurrency` 记录实际并发，`run.model_tasks` 保留各组状态、开始与完成时间。顶层调用计数及回执为汇总值，不叠加重复计数。
- 可用 `ATLAS_OSS_MODEL_CONCURRENCY=1` 退回串行；接受 1–4 的配置。默认每批 8 个候选只包含两个模型组。
