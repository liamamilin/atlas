# 团队项目看板：交接说明

## 先确认本文件的使用模式

**默认用途是校准 Atlas 模板生成器。** 在这个模式下，读取 `PRODUCT_REFERENCE.md`，借鉴其角色、页面、流程、状态、权限和验收之间的关系及内容深度；不要自动开发团队看板应用，不要把本样稿的业务规则硬编码为其他叶子的默认规则。

**只有用户明确选择“实现此产品”时，才执行下文的默认 P0 开发范围。** 本样稿是目标设计示例，当前没有应用运行或独立审阅通过的证据。

## 开始阅读

1. 完整阅读 `PRODUCT_REFERENCE.md` 的范围、角色和对象生命周期，确认私有项目、管理员边界、任务状态与归档的不同含义。
2. 阅读 P01–P09、J01–J08 与 R01–R12。页面可以采用合适布局，但逻辑页面、可直接访问的任务详情和操作合同需要保留。
3. 按 A01–A14 和 A16 建立 P0 验证计划；A15 属于 P1。断言是未来需要验证的目标，不能预填通过。

## 用户选择实现时的默认范围

实现完整 P0：首次初始化、真实登录与邀请、创建项目及首位负责人、项目成员管理、任务创建/编辑/分配/截止日、三状态看板与列表、评论、并发编辑冲突、权限撤回、任务和项目归档恢复、刷新与重启持久化。P1 导出、保存筛选及其他扩展不自动加入首版。

先检查当前项目已有的栈、账号体系、数据模型和测试方式，选择兼容实现；本包不指定必须使用某种语言、框架或数据库。没有现成实现时，应记录选型理由及启动方式，并采用支持事务和版本比较的持久化方案。身份鉴别必须真实生效，不能以页面上的角色切换器模拟多人权限。

初始化只能由本机维护者在未初始化状态下执行；维护者创建首位管理员后，通过组织邀请产生其他账号。账号停用前须移交负责人；重新启用只恢复仍存在成员关系的访问，不恢复旧任务分配。失联负责人按 R12 的本机命令合同恢复，提供预览、显式项目 ID 与目标现有成员、确认及审计；不得以组织管理员自动读取全部私有项目代替恢复设计。

建议先完成数据、权限与事务边界，再实现页面。看板、列表、详情共用业务服务与规则；任务状态更新、现任负责人变化和活动记录需要一致提交。编辑接口携带原版本并拒绝冲突，前端保留未提交输入；不要采用静默覆盖。

## 版本范围与结果记录

- 保留参考规格中的完整全貌，同时在实现说明中逐项映射 P0 的页面、旅程、规则和断言；P1 标为未实现，不能删掉全景后再声称产品全部完成。
- 为实际程序补充技术方案、接口与数据说明、启动命令、已执行验证和已知缺口。初始页面为空时应能完成首次使用旅程，不以预置示例数据掩盖初始化问题。
- 至少用两个普通账号和一个组织管理员验证私有范围、权限撤回及并发编辑；使用隔离数据验证归档恢复、刷新和同目录重启。
- 只在实际执行后记录通过，失败和未运行分开。A14 的重启检查必须针对交付的真实应用和存储目录。
- 保留用户已有项目、数据和指令；默认本地开发与测试，不自动部署公网、不发送真实邀请邮件、不导入未知用户数据。

交付应包含源码、安装与启动步骤、初始化与测试账号创建方法、规格到实现的映射、实际验收记录、数据备份/恢复说明以及剩余缺口。需要改变 R01–R12 或默认 P0 范围时，先解释具体冲突并形成显式规格修订，不能通过删断言取得通过。
