# 团队项目看板：产品参考规格

版本：示例 v1 · 2026-10-22  
用途：校准 Atlas 的产品参考模板生成器；用户明确选择开发此产品时，作为开发范围依据。  
性质：全部具体行为均为本样稿的目标设计，尚未由上游源码或实际应用运行证明。

## 1. 产品范围

为一个组织内的多个小团队提供固定三列的项目看板，让成员知道任务由谁负责、处于什么状态、何时到期，以及讨论和修改发生了什么。支持多个项目，但不支持多组织租户、复杂工单体系、工时计费和自定义工作流。

项目默认且始终为私有项目，只有显式加入的有效项目成员能够发现和读取。组织管理员管理账号与组织角色，不因此获得所有项目的读取权限。成员可以创建项目，创建者自动成为该项目的首位负责人；一个项目始终只有一位有效负责人。

固定任务状态为“待办、进行中、已完成”，活跃项目内未归档任务允许任意两种状态直接切换，包括待办直接完成及已完成重新进入待办；每次变更均记录。任务归档与任务状态分开：归档表示从日常工作视图移出，原业务状态保留。项目归档使其内容只读，不批量改变任务的状态或独立归档标记。

附件、外部集成、甘特图、依赖网络、工作流定制和组织公开项目明确延期。当前产品支持中文文本与本组织账号，不要求邮件服务或第三方登录才能完成首次使用。

## 2. 角色、权限与可见范围

| 角色 | 目标与职责 | 允许操作 | 边界 |
|---|---|---|---|
| `U_MEMBER` 项目成员 | 创建和推进任务、讨论、查询自己的工作 | 读本项目；创建、编辑、分配、移动任务；发表评论；归档已完成任务；恢复任务 | 不能管理项目成员、转移负责人、修改组织角色；看不到未加入的项目 |
| `U_OWNER` 项目负责人 | 维护项目秩序与人员 | 拥有成员能力；管理项目设置、成员、负责人移交；归档任意状态任务；归档和恢复项目 | 权限限定于负责的项目；不能凭此改变组织账号权限 |
| `U_ADMIN` 组织管理员 | 初始化组织、管理组织账号与管理员角色 | 创建邀请、停用普通账号、管理组织角色 | 必须先加入项目才可读项目内容；不能强行给自己加入私有项目 |

一个账号可以同时承担多个角色。成员可编辑本项目内其他成员创建的任务，但操作必须进入活动记录。评论作者名称作为历史归属保留；成员退出后，旧评论不消失。

首位管理员通过服务所在机器的一次性初始化命令创建，命令只在未初始化数据库上有效，创建组织和账号须原子完成。浏览器公开注册不能抢占管理员。组织邀请使用可复制的一次性链接；链接使用后失效，过期或已撤销的链接不能创建账号。项目负责人只能邀请已加入本组织的有效账号进入项目。

## 3. 业务对象与生命周期

| 对象 | 关键内容 | 生命周期及约束 |
|---|---|---|
| `O_USER` 账号 | 显示名、登录标识、组织角色、有效状态 | 邀请待接受 → 有效 ↔ 停用；停用撤销会话但保留未删除的项目成员关系与历史作者身份；重新启用后须重新登录 |
| `O_PROJECT` 项目 | 名称、说明、负责人、成员、归档时间、版本号 | 活跃 ↔ 已归档；创建事务同时产生负责人和成员关系；不提供永久删除 |
| `O_MEMBERSHIP` 项目成员关系 | 项目、账号、项目角色 | 加入 → 移除；负责人必须先移交职责才能退出或被移除 |
| `O_TASK` 任务 | 标题、描述、状态、负责人、截止日期、创建者、归档时间、版本号 | 三种状态任意两种之间可直接转换；另有归档/恢复；状态切换与归档彼此独立 |
| `O_COMMENT` 评论 | 任务、作者、正文、创建时间 | P0 只允许追加，避免修改讨论历史；不支持富文本执行或附件 |
| `O_ACTIVITY` 活动记录 | 操作者、对象、动作、变更摘要、时间 | 追加保存，关联任务或项目；记录负责人、截止日、状态、归档和权限变更 |

任务负责人可以为空；非空时必须是当前有效项目成员。截止日期为日历日期，不包含时分秒；“逾期”按组织时区判断，为截止日已过去且任务未完成、未归档。P0 在初始化时明确组织时区，后续修改归入 P1，并先提示其对逾期显示的影响。

## 4. 页面目录与详细规格

以下是逻辑页面；任务详情允许以抽屉呈现，但必须有可以直接访问的地址。不得靠页面布局变化丢失其规格。加载中保留稳定标题和已有数据；网络读取失败提供重试，禁止展示成“没有内容”；服务端明确返回无权限时清除该页面的已加载私有内容并退出项目，未提交的本地编辑文字按 P06 处理。

### P01 账户与首次进入

- **目的与区块**：未登录时显示登录或邀请接受表单；已登录时显示当前账号、退出及改密入口；未初始化时只说明需要本机初始化，不提供抢注入口。
- **操作与结果**：有效邀请填写显示名和密码后进入 P02；登录失败保持登录标识，清空密码；改密要求当前密码，成功后撤销其他会话。
- **状态与恢复**：邀请过期、已用和已撤销分别说明；登录失效返回本页，认证完成后回到仍有访问权的原地址。无需搜索、筛选、批量或导出。

### P02 我的项目

- **目的与数据**：展示当前账号加入的项目，分“活跃”和“已归档”，列出名称、个人角色、活动时间；组织管理员也只看到自己的项目。
- **操作**：任意有效成员可创建项目；名称和说明有效后进入 P03，创建者已具有负责人权限。搜索只匹配可见项目名称，按最近活动或名称排序，不做跨项目全文搜索。
- **状态**：首次无项目时提供创建入口和“请负责人邀请”说明；无搜索结果可清空条件。创建失败保留输入；重复提交不能创建两个项目。P0 无批量和导出。

### P03 项目看板

- **目的与区块**：标题及只读标记、成员和列表入口、筛选条、三列任务卡。卡片显示标题、负责人、截止日、评论数；默认只含未归档任务。
- **操作**：新建打开 P06；卡片打开 P05。拖动或菜单移动到目标状态，等服务器确认后更新卡片、列计数和活动记录。跨列位置按最近移动时间排序，P0 不承诺自定义排序持久化。
- **查询**：标题关键词、负责人、逾期条件按 AND 组合；“未分配”单独可选。筛选条件保留在地址参数中。移动后若不再匹配当前筛选，应说明卡片已移出当前结果。
- **异常**：空列与整个项目无任务分别引导；移动失败回到原列；权限撤回后停止写入并退出项目；项目已归档时展示原因，全部内容操作禁用。P0 无批量和导出。

### P04 任务列表

- **目的与数据**：以表格呈现与 P03 相同的未归档任务，列为标题、状态、负责人、截止日和更新时间。
- **查询与操作**：支持与看板相同的筛选，增加状态筛选；按更新时间、截止日或标题排序；空截止日排在末尾。分页只改变结果窗口，变更筛选后回到第一页。点击进入 P05，创建进入 P06。
- **状态**：明确区分没有任务与没有匹配；失败保留原筛选和最后成功结果并标记未刷新。P0 不提供批量或导出按钮。P1 可导出当前筛选的全部记录，导出前说明数量；无权访问的记录不得出现在结果中。

### P05 任务详情与讨论

- **区块**：标题、描述、状态、负责人、截止日期、创建/更新时间、评论流和活动记录。只读取当前项目可见任务，直达隐藏任务地址返回统一不可访问反馈，不泄漏标题。
- **操作**：编辑进入 P06；移动状态遵守 P03 同一规则；评论提交成功后追加并清空输入，失败保留正文。成员可归档已完成任务；负责人归档未完成任务时须确认提示“移出日常视图，但不标为完成”。
- **归档与异常**：已归档任务只读，可以在活跃项目内恢复；恢复后保留原状态。项目归档后评论和恢复操作都暂停。不存在、权限撤回和读取失败分别提供可行返回/重试路径。此页无需搜索、批量或导出。

### P06 任务创建与编辑

- **表单**：标题必填，描述可空，负责人可为空或选当前成员，截止日期可空；新建默认待办。用户未保存离开时提示保留编辑或放弃。
- **提交合同**：编辑携带读取时的任务版本；版本相同时原子保存并返回 P05，原始看板/列表筛选上下文保留。不得通过覆盖整个对象删除其他用户新添的信息。
- **恢复**：校验失败就地说明且保留输入；负责人已离开项目时要求重新选择。并发版本冲突显示当前服务器值与本地未保存值，允许复制、重新载入后明确重提，不自动最后写入获胜。权限失效时拒绝提交并保留本地文本供复制，不允许继续取得新私有数据。无需查询、批量和导出。

### P07 项目设置与成员

- **数据**：成员能查看项目说明和成员；负责人可编辑名称说明、邀请现有账号、移除成员及移交负责人。组织账号搜索只对负责人开放，仅返回本组织有效账号的显示名和登录标识。
- **前置与结果**：移交目标必须是已有有效项目成员；事务完成后新负责人即时生效，旧负责人保留普通成员身份。移除成员前显示将清空的现任任务分配数量。
- **归档**：负责人可归档/恢复项目；归档项目保留成员访问和历史读取，名称、说明及任务内容均只读。成员管理及负责人移交属于治理操作，归档期间仍允许；这不授权编辑其他项目内容。
- **错误与恢复**：自己是唯一负责人时不能退出；失去负责人资格后提交须拒绝。失败保留表单；不提供批量移除或成员导出。

### P08 归档与历史

- **目的**：在项目内查询已归档任务及活动记录，保留任务原状态、归档人和时间。活动流按时间倒序，可按任务、操作者和动作类型筛选。
- **操作**：任务归档区支持标题、负责人和原状态筛选；打开 P05。活跃项目的有效成员可恢复任务；项目已归档时提示先由负责人恢复项目。恢复后任务从归档区移出，在原状态列重新出现。
- **状态**：无归档与无匹配分开显示；历史作者停用后仍显示其保留名称。P0 无永久删除、批量恢复或导出；读取失败不能误报历史已清空。

### P09 组织成员管理

- **权限与数据**：仅组织管理员可进入；展示账号、有效状态、组织角色、待处理邀请。可以搜索显示名/登录标识，筛选有效、停用或邀请待接受；不显示私有项目名称、任务和评论。
- **操作**：发出/撤销组织邀请，停用账号，调整管理员角色。不能撤回或停用最后一位有效管理员。停用账号若仍为某项目负责人则拒绝，仅提示待移交项目数量，由其先移交；允许停用时清空该账号在各项目的现任任务分配，但不向管理员泄漏项目/任务内容。
- **恢复与边界**：停用立即撤销会话但保留尚未删除的项目成员关系。管理员可在停用账号行“重新启用”，账号重新登录后恢复仍存在关系所允许的访问，已删除关系和被清空的任务分配不恢复。失联负责人按 R12 的本机维护合同恢复；Web 管理员无接管入口。操作失败保留选择，不提供批量停用或账号导出。

## 5. 端到端旅程

| ID | 旅程与角色 | 步骤与完成结果 | 异常/恢复 |
|---|---|---|---|
| J01 | 首次启动：维护者、管理员 | 一次性初始化组织和首位管理员 → P01 登录 → P09 邀请成员 → 成员接受邀请 → P02 | 已初始化时命令拒绝；重复/过期邀请不可复用 |
| J02 | 建项目与加入：成员、负责人 | P02 创建项目并成为负责人 → P07 邀请组织成员 → 被邀者 P02 可发现项目 → P03 | 非组织账号先由管理员邀请；未加入者无法猜地址读取 |
| J03 | 创建与分配：项目成员 | P03/P04 → P06 填写任务、负责人和截止日 → P05 确认 → P03/P04 与被分配者筛选结果同步 | 负责人失效或保存失败保留输入；重复提交只产生一条任务 |
| J04 | 推进和反馈：多人 | P03 移动状态 → P05 添加评论 → 其他成员刷新看板/列表/详情获得相同状态与评论数 | 移动失败回滚；已归档/撤权后提交拒绝 |
| J05 | 日常查询：项目成员 | P02 找项目 → P03/P04 筛选我的/未分配/逾期 → P05 处理 → 返回原筛选 | 条目不再匹配时说明变化；无结果可重置筛选 |
| J06 | 人员变化：负责人、管理员 | P07 移交负责人或移除成员 → 所有当前分配与访问同步变化 → 必要时 P09 停用账号 | 负责人未移交不能停用；被撤权者已打开页面也不能继续读取或写入 |
| J07 | 整理与恢复：项目成员、负责人 | 完成任务 → P05 归档 → P08 查询 → 恢复到原状态；项目负责人可将整个项目归档 | 项目归档后内容只读；恢复项目不自动恢复独立归档任务 |
| J08 | 长期回查：项目成员 | P02 已归档项目 → P08 历史 → P05 旧任务与评论 | 退出项目后历史入口同样失效；作者停用不删除历史归属 |

## 6. 统一业务规则

- **R01 可见范围**：列表、搜索、详情、下载及所有写入在服务端检查当前身份和项目成员关系；隐藏按钮不替代权限判断。
- **R02 初始化唯一**：同一组织只能有一次初始化结果；项目创建原子产生负责人，不能留下无负责人项目。
- **R03 状态独立**：任务状态只取三值；归档不改变状态。恢复任务保留原状态，恢复项目保留各任务自己的归档标记。
- **R04 一致更新**：状态、负责人、截止日、归档变化与活动记录在同一提交中完成；看板、列表、详情按同一已提交数据计算。
- **R05 并发保护**：任务编辑使用版本比较；冲突返回当前版本与差异，不覆盖本地输入，不静默覆盖他人修改。
- **R06 成员移除**：成员关系立即失效；其在该项目的任务现任负责人字段清空，并记录系统变更，历史分配/评论归属保留。组织账号停用对该账号的所有项目执行同样清空规则，重新启用不自动恢复旧分配。此治理动作可影响归档任务元数据，不恢复内容可写性。
- **R07 负责人约束**：移交和移除原子检查；唯一项目负责人不能自行退出，账号停用前须移交其全部项目，包括归档项目。
- **R08 日期语义**：截止日期按组织时区的日历日解释；当天不算逾期，已完成及归档任务不算逾期。
- **R09 只读规则**：项目归档禁止新建、编辑、移动、评论和任务归档/恢复；仅保留读取与负责人治理、项目恢复。
- **R10 重复提交**：创建项目、创建任务和提交评论要识别同一提交的重复请求；重试不能产生重复对象。
- **R11 查询语义**：同名筛选条件在看板和列表含义相同；搜索只在有权访问的数据内发生；P1 导出必须复用同一筛选条件及权限规则。
- **R12 人工恢复与历史**：不提供永久删除。失联负责人仅由本机维护者恢复：显式指定项目 ID、目标现有有效项目成员及原因，预览原/新负责人并确认后原子移交，旧负责人保留成员关系。记录维护身份、原因、前后值和时间，不自动加入操作者、不导出私有内容，Web 管理员没有该入口。无合格目标则拒绝；维护者可改为给原负责人生成一次性改密令牌并撤销旧会话，保留恢复审计，不能以清空项目或越权添加成员替代恢复。

## 7. 声明式验收

| ID | 操作与可观察结果 | 关联 |
|---|---|---|
| A01 | 初始化后再初始化被拒绝，不新增第二组织；首次创建项目后创建者确为唯一负责人 | J01/J02、R02 |
| A02 | 管理员未加入私有项目时，搜索、直达详情和任务 API 均不能读取该项目内容 | P02/P05/P09、R01 |
| A03 | 重复提交同一任务创建请求，只得到一个任务；P03、P04、P05 身份一致 | J03、R10 |
| A04 | 任务可待办直接完成、完成再回待办，也可进入进行中；看板列、列表状态、详情和活动记录一致，移动失败全部保留原值 | J04、R03/R04 |

## 8. 可开发版本

**P0：真实团队协作闭环。** 包含 P01–P09 的 P0 能力、J01–J08、R01–R12 和 A01–A14、A16。必须支持真实身份、私有项目权限、初始化、组织邀请、成员邀请、三状态任务、负责人/截止日、评论、并发冲突、归档恢复与持久化。P0 不含邮件通知、实时推送、文件附件、批量修改或导出；页面提供刷新即可取得他人已提交变化，不承诺实时同步。

**P1：提高日常整理效率。** 在 P0 上增加当前筛选结果导出、保存个人筛选、分页性能和明确的活动历史检索优化；新增批量操作前单独定义部分失败与权限变化规则。新增时保持 R01–R12，补充 A15 及相应负向断言。P1 不因扩展方便性改变 P0 的权限或归档语义。
