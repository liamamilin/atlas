# Atlas 产品参考模板样稿

日期：2026-10-22。用途：为 Atlas 的“完整产品参考系”定义可阅读、可比较的目标产物，并交给 Codex 参考。

本包提供三份完整设计样稿：个人收藏夹、团队项目看板、团队活动报名。它们分别检验单人使用、多角色协作和运营交接。样稿中的业务规则是明确的目标设计；没有通过本包创建实际应用，没有声称上游或目标应用运行通过，也没有给现有 Atlas 制品登记通过状态。

## 先读什么

1. 先读本文件，理解三份产品的适用范围。
2. 阅读 `01-personal-bookmarks/PRODUCT_REFERENCE.md`，看一个单人产品怎样描述完整页面、状态和长期使用。
3. 阅读 `02-team-project-board/PRODUCT_REFERENCE.md`，看成员、项目负责人和管理员的权限如何进入页面与旅程。
4. 阅读 `03-team-event-registration/PRODUCT_REFERENCE.md`，看一个操作怎样影响其他角色的页面、业务状态和后续工作。
5. 阅读 `GENERATOR_GUIDE.md`，将三份样稿的共同结构用于 Atlas 生成器。
6. 只有用户明确选择实现某个产品时，才阅读该目录的 `HANDOFF.md` 并进入该产品的 P0 开发。

## 三份样稿的差异

| 样稿 | 产品形态 | 主要检验点 |
|---|---|---|
| 个人收藏夹 | 单人、本机或私有实例 | 完整 URL、搜索字段、分类语义、整理与恢复、长期数据维护 |
| 团队项目看板 | 单组织、多项目协作 | 页面与实际操作权限、任务状态、成员交接、跨页一致性、编辑冲突 |
| 团队活动报名 | 单组织、内部免费活动 | 成员／运营／管理员交接、容量、重复提交、取消、截止、历史与通知 |

每份产品参考都包含：定位与边界、角色权限、业务对象和生命周期、页面目录、逐页规格、完整旅程、业务规则、声明式验收、P0/P1 范围，以及来源／设计／未知说明。

页面中的搜索、筛选、排序、批量、导出按适用性描述。没有必要的能力会明确排除或延期，不要求每页都凑齐这些操作。

## 两种使用方式

### A. 改进 Atlas 生成器（本包默认用途）

让 Codex 学习这些产物包含哪些信息、关系怎样闭合，再改造 Atlas 的结构化规格、生成、校验、阅读视图与导出。不能把本包直接注册为“真实模型生产通过”，也不能仅复制同样的章节标题就声称新生成器达到了同样深度。

现有案例研究、固定来源、调用记录、制品和用户数据继续保留。旧核心场景模板仍按原有类型展示；新增的产品参考规格有自己的版本与审阅状态。

### B. 开发某个示例应用（须用户选定）

把对应产品目录交给 coding agent，先读取 `PRODUCT_REFERENCE.md`，再按 `HANDOFF.md` 选择 P0。P0 必须完成选定旅程及必要依赖，其他能力保留在全景中，不能在文档里消失。实际技术栈应结合现有项目选择。

本包不自动授权外部发布、部署、发送通知、修改生产数据或启动另外两个应用。

## 如何看待来源

样稿中的具体设计默认属于“本参考产品的目标设计”。出现上游仓库链接时，只作为明确标记的参考线索；未在本包完成固定源码核查的内容不能登记为上游观察。不得用上游项目名称给整份设计背书。

用户确认某个产品形态后，可以在 Atlas 的正式研究阶段为相应结论补充固定案例与证据；设计结论依然可以与上游不同，只需写明原因。标记为“未知”的内容应保持可见。

## 交给 Codex 的启动语

请以附件三份 PRODUCT_REFERENCE.md 为目标产物样例，改进 Atlas 的产品参考模板生成器。先阅读 GENERATOR_GUIDE.md，提取共同的角色、页面、操作、对象状态、旅程、规则、验收和开发范围结构，再落到版本化数据模型、生成提示、关系校验、只读展示和导出。保留旧制品、研究、调用账本和冻结历史，新增产物类型不能伪装成旧开发包。优先验证生成内容是否达到样稿的具体程度，不以章节齐全或字数代替产品完整性。本次任务是改进生成器；除非我明确选择某一产品，不要直接开发这三个示例应用。
