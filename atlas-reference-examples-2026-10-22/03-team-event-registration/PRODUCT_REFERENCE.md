# 团队活动报名：完整产品参考样稿

版本：2026-10-22。性质：**目标产品设计**。本文所有具体业务规则均为本样稿提出的设计选择；没有把它们描述为某个开源项目的已验证事实，也没有宣称应用已实现或运行通过。

## 1. 产品定位与边界

产品服务一个组织的内部免费活动：运营发布活动，成员报名、取消及查询历史，组织管理员维护账户和权限。它要解决的完整问题是“活动可发现、名额可信、变更可知、责任可交接、历史可追溯”。首页是活动列表，不另外制造没有必要的仪表盘。

本版本只有一个组织，时区固定为北京时间 Asia/Shanghai；所有用户看到同一时区，时间以服务端判断。没有付费票务、候补、抽签、多人代报名、签到、外部公开报名和多组织切换。一个成员只能为自己报名。活动有一个负责运营，不设置复杂审批。

开发 profile：组织内 Web 应用，可用现有可靠认证；没有现成认证时实现本地账户、密码哈希和服务端会话。禁止网页自注册。首位管理员通过一次性本机初始化命令创建；初始化成功后再次执行不能重建组织或覆盖账户。之后由管理员建成员、重置初始凭据和授予角色。SSO 与邮件邀请属于待集成项。

## 2. 角色、权限和责任

所有启用账户都有普通成员能力，额外角色可以组合。拥有组织管理员身份不会自动取得运营权限。

| 角色 | 能做什么 | 数据范围及限制 |
|---|---|---|
| 普通成员 | 浏览已发布活动；本人报名、取消；看本人报名和通知 | 看不到其他成员报名名单；草稿不可见 |
| 活动运营 | 新建活动；管理自己负责的活动、报名名单及通知重试 | 不能编辑其他运营的活动；不能管理账户或给自己授权 |
| 组织管理员 | 建停用账户、授撤角色、转移活动负责人、设组织信息 | 转移时只看必要活动标识和数量；不能借管理员角色发布活动或读取名单 |

管理员可以明确给自己增加运营角色，授权变更必须留记录。撤销运营角色或停用负责人前，必须把该人的全部活动（含历史活动）转交给另一位启用的运营；无接收人就拒绝提交，并提示先授予接收人角色。转移是管理职责交接，不改活动内容、报名和原作者记录。账户停用即时使会话失效，但不自动取消已有报名。

## 3. 业务对象与状态

| 对象 | 关键内容 | 状态与生命周期 |
|---|---|---|
| 成员 | 登录标识、显示名、角色、启用状态 | 启用／停用；历史记录保留成员标识及当时显示名 |
| 活动 | 标题、说明、地点、开始结束、报名截止、容量、负责人、版本 | 草稿 → 已发布 → 已取消；已结束由当前时间推导，归档是独立展示标记 |
| 报名 | 活动、成员、当前状态、状态时间 | 已报名／本人取消／运营取消／活动取消；每活动每成员只有一条当前记录，变更历史追加保存 |
| 通知事件与收件记录 | 业务事件、活动版本、接收人、内容、处理状态 | 待发送／已送达／失败；收件人另有未读／已读状态 |

“可报名、已满、报名截止、进行中、已结束”是由活动状态、时间和有效报名数计算的展示状态，不由运营手工填写。活动详情、列表、名单和本人报名必须采用同一判断。

状态标签依次优先：草稿、已取消、已结束、进行中、已截止、已满、可报名。

## 5. 每页规格

长列表每页 20 条；搜索与筛选叠加，排序以 ID 打破同值，清空条件恢复默认。

### P01 登录与首次进入

提供登录标识、密码和明确的错误反馈；初始凭据登录后先完成密码修改，再进入 P02。登录前访问受限链接，成功后回到仍有权访问的原页面；否则回首页并说明权限变化。初始化尚未完成时只展示“请在服务器完成管理员初始化”，不暴露公开创建管理员表单。本页没有搜索、筛选、排序、批量或导出。提交时防重复点击；密码错误不透露账户是否存在。网络错误可重试，密码不保存在浏览器持久存储中。

忘记密码由管理员在 P09 重置，下次登录必须改密。

### P02 活动列表／首页

展示标题、时间、地点、报名状态、容量与已报名数；默认列出未取消、未归档且尚未结束的已发布活动，开始时间升序。搜索只匹配标题和地点；可筛选“可报名／已满／已截止”和“包含历史”。历史入口能查看已结束活动；本人已报名但活动取消或归档时，仍可从 P04 进入。点击卡片到 P03。不提供成员批量操作或导出。首次无活动提示稍后查看；筛选无结果提供清空条件；加载失败保留条件并重试，旧数据须标记未刷新。

### P03 活动详情

展示说明、地点、三个时间、容量、负责运营显示名、最新变更说明和本人报名状态。可报名时显示报名按钮；已报名显示取消按钮及取消期限；其他状态写明原因。报名成功留在本页，显示“已报名”并链接 P04。取消成功更新名额及本人状态。成员只看人数，不看名单。本页不需要搜索、批量或导出。不存在或无权访问的活动不泄露草稿内容；最后名额被占用时保持详情、刷新余量并说明失败。提交超时先查询当前报名结果，再决定是否重试。

### P04 我的报名

展示当前成员的活动、开始时间、报名状态和最近变更；默认未来活动，可筛选历史及报名状态，按开始时间或最近变更排序，搜索活动标题。点击进入 P03；可取消的记录提供同样的确认操作。历史包含本人取消、运营取消及活动取消，不因归档消失。没有记录时引导去 P02。无批量取消或导出，避免误取消多项。加载失败不伪装空列表；登录失效回 P01，恢复后保留筛选。

### P05 我负责的活动

仅列当前运营负责的活动，显示草稿、发布状态、时间、报名数、通知失败数和归档标记。支持标题搜索，按状态/归档筛选，按开始时间或更新时间排序；新建到 P06，名单到 P07，通知失败到 P08。草稿可删除；已发布活动不可硬删除。结束或取消的活动可归档、恢复；P1 支持勾选后批量归档，逐项显示成功和不符合条件的原因，不把部分失败报告为全成功。无活动时引导创建；权限收回后移除业务管理入口并停止展示名单。无导出。

### P06 创建／编辑活动

表单包含标题、说明、地点、起止时间、报名截止和正整数容量；草稿允许未填完，发布必须完整。保存草稿留在编辑页；发布成功回详情并给出成员视角入口。已发布活动修改时显示差异；时间、地点变化必须填写原因，确认后通知当前有效报名者。减少容量低于有效报名数时拒绝并保留输入。活动开始后表单只读，仍未结束时可以取消整场活动；取消必须填原因并再次确认。无搜索、排序、批量或导出。字段错误在原位提示；保存失败保留输入；版本冲突显示服务端最新版本并要求重新核对，禁止静默覆盖。

### P07 活动报名名单

只供该活动负责运营访问。展示活动状态、容量、有效报名数，以及成员显示名、登录标识、当前状态、报名和变更时间。可搜索姓名/登录标识，按报名状态筛选，按报名时间排序。活动开始前可取消一条有效报名，必须填写原因；结果更新计数并通知该成员。无批量取消。P1 CSV 导出采用当前筛选，包含当前显示字段；导出时重新校验权限，文件中用户输入按文本安全处理。空名单与无匹配结果分别说明；加载失败可重试；权限撤回后立即停止读取、操作和导出。

### P08 通知中心

成员区只展示本人通知，包含报名结果、运营取消、活动重要变更和整场取消；按时间倒序，可筛选未读，点击后标已读并到最新详情。P1 可批量标已读。运营管理区仅显示自己负责活动的通知投递状态，可按活动/失败筛选，失败记录可重试；不提供手工发送任意营销消息或导出。空状态说明没有通知；失败通知不会冒充已送达。旧通知保留事件版本，重试不会改写当前活动状态。业务操作已经成功时，页面可提示“操作成功，部分通知待送达”。

### P09 成员与角色

管理员可按登录标识/姓名搜索，按角色和启用状态筛选，按姓名排序。新建账户后显示一次性的初始凭据交付说明；不得在日志中记录密码。修改角色、重置凭据、停用及活动转交都要显示作用对象并确认。撤销当前唯一启用管理员的权限或将其停用必须拒绝。转移负责人展示活动数量和接收运营，不展示参与者名单。无批量授权、批量停用或成员导出。表单失败保留非敏感输入；并发授权变化发生时重新校验唯一管理员条件，不采用旧页面判断。

### P10 组织设置

展示组织名称、支持联系人说明、固定时区和当前认证 profile；只有管理员能修改名称和联系说明。保存后成员页面使用新信息，不改变历史活动时间。时区在本版只读，SSO/邮件配置显示未集成，不能画出可操作的假入口。本页不需要搜索、筛选、批量或导出。保存失败保留输入，权限失效转只读提示；初始化完成后组织不会因该页面为空而被重复创建。

## 6. 完整用户旅程

**J01 初始化与首次使用。** 维护者用本机命令创建首个管理员；管理员登录 P01、修改初始凭据，在 P10 填组织信息，在 P09 建成员并给至少一个人运营角色。运营首次进入 P05 创建活动；成员首次登录 P02，没有活动时看到明确空状态，而不是无法完成的引导。

**J02 发布到报名的跨角色交接。** 运营从 P05 到 P06 保存草稿、完善后发布；活动从只对负责运营可见变为成员可见。成员在 P02 发现活动，到 P03 报名，P04 出现记录；运营刷新 P07 看到同一条有效报名和一致计数。正常通知随后到 P08，通知投递不是报名成功的前提。

**J03 取消与再次报名。** 成员在开始前从 P03/P04 取消，当前记录变为本人取消，名额释放；另一成员可在仍开放报名时取得名额。原成员再次报名要重新检查截止和容量，恢复同一条当前记录并追加历史，不能产生第二个有效名额。运营取消同理，但原因和操作者保留；它属于纠错，不构成永久禁报。

**J04 活动变更或整场取消。** 运营在开始前修改时间/地点，确认差异及原因；已报名者在 P08 和详情获知新安排。整场取消在结束前允许，所有当时有效报名转为活动取消；此前个人取消记录保持原状态，活动状态仍显示已取消。活动和历史不删除，待投递通知失败可重试。

**J05 截止、结束与长期历史。** 到达报名截止后新报名被拒绝；开始前仍可取消，但释放名额不会使截止自动失效。开始后停止个人/运营单条取消，结束后只读。运营可归档已结束或取消活动；成员从 P04 持续查到原记录，运营从 P05 的归档筛选恢复展示。

**J06 负责人交接与权限收回。** 管理员选择接收运营，事务内完成全部活动转交和原账号角色撤销/停用。新负责人在 P05/P07 接管，旧负责人即使保留已打开的页面也无法继续提交。报名状态、计数和历史不随人员交接改变。

## 7. 统一业务规则

- **R01 身份与权限：** 所有读写在服务端校验启用状态、角色及负责关系；隐藏按钮不能代替授权。唯一启用管理员不能被删除、停用或撤权。
- **R02 时间：** 开始早于结束，截止不晚于开始；发布时截止必须在未来。比较边界为服务端当前时间严格小于截止/开始，恰好相等即不再允许相应动作。
- **R03 名额：** 只有已报名记录占名额。资格、重复记录和容量检查及写入在同一原子事务内完成；两个并发请求争最后名额只能一方成功。
- **R04 重复提交：** 每次新的业务意图携带新的操作 ID；同一操作 ID 重放只返回原操作回执，不重复改变状态，复用 ID 却改变请求内容必须拒绝。报名后已取消时，延迟重放旧报名请求不能再次报名；真正再次报名使用新操作 ID，并重新校验截止、资格及名额。旧取消请求也不能取消后来新报名的状态。响应同时提供当前报名状态/版本，界面读取当前状态，不能用旧成功回执覆盖新状态；当前已报名时另一次报名也不能重复占位。
- **R05 取消：** 个人及单条运营取消只允许开始前；取消释放名额但不修改截止。整场取消只允许结束前；它关闭所有新报名并保留历史。
- **R06 修改：** 已发布活动开始前可编辑，之后只允许结束前整场取消。容量不得低于有效报名数；新开始时间必须仍在未来。截止可改到当前/过去以关闭报名，或改到未来重新开放，但不得晚于开始；界面必须明确提示重新开放的效果。
- **R07 保存冲突：** 活动每次修改递增版本；旧版本提交必须拒绝并要求重新核对。取消后不能通过旧编辑表单重新发布。
- **R08 通知：** 业务事务保存通知事件，投递异步进行；投递失败不回滚报名、发布或取消。按事件版本和接收人去重；重试只处理通知，不再次执行原业务操作。
- **R09 历史与归档：** 已发布活动及报名不硬删除；归档只改变列表展示，不改报名、通知及统计。停用成员的报名仍占名额，负责运营可按 R05 取消。
- **R10 交接与数据范围：** 撤运营或停用负责人前，必须原子转交全部活动给启用运营。管理员角色不自动拥有名单权限；导出和重试通知同样受负责关系限制。
