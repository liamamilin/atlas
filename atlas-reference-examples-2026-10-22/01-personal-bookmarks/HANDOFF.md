# Codex 使用说明：个人收藏夹参考样稿

## 默认用途：校准 Atlas 生成器

先完整阅读同目录 `PRODUCT_REFERENCE.md`。当前用户要求是获得完整产品参考模板；仅收到这两个文件时，不要自动开始开发收藏夹应用、启动模型批量生产、重写旧书签模板、迁移用户数据库或部署服务。

请将样稿作为 Atlas 目标输出的参考，重点保留以下关系：

1. 产品形态先固定为单人、本机或私有实例，所以只有 OWNER 与 SYSTEM，没有人为补出的管理员或运营后台。
2. 页面 P01–P08 有目的、数据范围、操作条件、成功去向和失败恢复；不适用搜索/批量等能力的页面应明确说明。
3. J01–J08 将页面操作与 Bookmark/Category 状态串成完整流程，覆盖首次、日常、管理、异常和长期使用。
4. R01–R10 是跨页面共同遵守的产品规则；A01–A10 是声明式验收目标，当前均未运行。
5. P0 与 P1 从同一份完整参考规格选范围。P1 在当前未开发时仍是可阅读的参考内容，不能假称已经提供。
6. 来源指针不等于已核查事实。全部具体行为目前都是目标设计，不得填入“上游已实现”或“独审已通过”。

如任务是改造 Atlas，优先实现能承载这些关联的规格、验证和阅读视图。不要把本稿压回一个 audience、1–5 条文字功能、整组来源引用和一个含混 arch 字符串，也不要机械要求所有品类有八个页面。

## 只有用户明确选择开发此应用时，才执行以下内容

默认开发范围为 `PRODUCT_REFERENCE.md` 第 9 节 P0。先检查现有仓库、应用、数据和开发规则；选择与现状兼容的技术栈，记录关键默认决定。不要因为正文展示了 P1 就一并实现所有能力，也不要未经说明缩掉 P0 的分类删除、归档、回收恢复和冲突反馈。

建议开发顺序：

1. 建立 Bookmark/Category 的持久化、状态转换、事务和版本检查；先写清统一 URL 校验与分类规范化函数。
2. 实现 P02/P03，使新建、编辑、打开原链接、移动分类能真实运行。
3. 实现 P01/P04 的查询、分页、分类计数和分类生命周期，确保不同入口共用规则。
4. 实现 P05/P06，验证 active → archived → trashed → archived → active 的完整去向。
5. 加入 P08 只读信息、错误恢复和同目录重启验证，提供实际启动与停止说明。

优先验证下列容易遗漏的行为：

- `http://intranet/guide?q=1#intro` 等单标签 hostname 可以保存，不需要实际联网验证。
- 保存和打开 URL 保留 path、query、参数顺序和 fragment；应用不能把导航链接简化为域名。
- 搜索只匹配标题、hostname、描述；分类独立筛选，URL 路径或分类名里的文字不应成为搜索误命中。
- 删除分类只把所有状态下的收藏变为未分类，不删除收藏；改名保留身份。
- archived 收藏被删除后恢复仍 archived；分类已删除时恢复为未分类。
- 保存失败保留表单输入，多标签页旧 revision 不能覆盖新版本；失败不能留下新建一半的分类。
- 正常停止并用同一数据目录重启后，收藏、分类和状态可读回。

运行证据必须绑定实际代码与实际数据目录；仅阅读规格或通过语法检查不能写成应用通过。验证使用独立测试数据，不清理用户既有收藏。页面、规则和声明式验收编号应在实施报告中保持可追踪。

## 交付及变更处理

应用开发交付应包括实际源码、启动方法、当前实现范围、真实验证记录和已知缺口。默认只在本地启动；外部发布、远端访问和认证方案须遵守用户对部署的实际指令，本稿不自动授予发布权限。

发现规格冲突时记录冲突条目、相关页面/规则编号、建议选择和影响，并对同一参考规格作可追溯修订。不要通过删掉验收或把未实现能力标为“不适用”来消除冲突。旧书签 G1、旧冻结模板和用户数据库保持原样，除非用户另有明确任务。
