# 个人收藏夹：完整产品参考规格

版本：`product-reference-example.v1`，2026-10-22。本文是一份目标产品设计样稿，供 Atlas 生成器和 Codex 校准产品理解；没有实施、运行或验收通过声明。它不修改旧书签模板、严格 G1 合同或历史验收结果。

## 1. 产品定位与明确范围

帮助一个人把以后还会用到的网页保存下来，通过分类、检索和整理再次找到，并在长期使用中处理失效、归档、误删和数据迁移。成功的产品体验是：用户能在几十秒内存下一条链接，在数月后仍能准确找到并打开它，而且整理和误操作不会悄悄丢失资料。

本产品形态为单人、本机或由用户自行控制的私有实例。没有账号、团队空间、管理员或运营人员；同一个所有者负责收藏与数据维护。默认运行地址只供本机访问。公网部署、多人权限、云同步、跨设备冲突解决属于其他产品形态，不是本稿隐含要求。

完整参考范围包括收藏新建与编辑、分类管理、列表检索、归档、回收恢复、批量整理、JSON 导入导出及本地备份说明。不会自动抓取网页正文、缩略图、标题或可达性；不依赖网页仍能访问才能保存。浏览器扩展、标签体系、全文剪藏、智能推荐、附件和分享链接暂不设计。

**完整产品参考与开发切片分开。** 下文描述目标产品全貌；第 9 节的 P0 是第一版需要实现的完整闭环，P1 是已说明但可后置的能力。参考规格中的 P1 不得被宣称已经实现，也不能因为当前不开发就从参考系中删除。

## 2. 角色、职责与权限

| 参与者 | 目标与职责 | 可以做什么 | 不承担什么 |
|---|---|---|---|
| `OWNER` 收藏夹所有者 | 保存、查找、整理自己的资料，维护本地数据 | 访问全部页面；管理所有收藏与分类；归档、删除、恢复、导入导出；按明确操作生成备份 | 不管理其他用户；没有跨租户和管理员权限 |
| `SYSTEM` 本地应用进程 | 校验、持久化、计算计数、生成下载文件 | 根据 OWNER 的明确操作执行事务；报告错误；读取自身数据目录 | 不自动访问收藏网站、不上传数据、不定时清空回收站、不自行发布服务 |

“私有实例”不是已实现认证的承诺。若用户决定让远端设备访问，须另行选择访问控制和部署方式；当前无账号设计不应直接暴露到公网。

## 3. 核心对象与生命周期

### 3.1 `Bookmark` 收藏

字段包括稳定 `id`、`original_url`、由 URL 解析得到的 `hostname`、可选 `title`、可选纯文本 `description`、可空 `category_id`、`state`、`created_at`、`updated_at`、`trashed_at`、`restore_state` 和用于防覆盖的 `revision`。

`state` 只取 `active`、`archived`、`trashed`。新收藏为 active；归档与取消归档在 active/archived 间切换；二者均可移入回收站，移入时保存原状态到 restore_state。恢复时回到原状态，并清空 trashed_at 和 restore_state。永久删除属于 P1，执行后本应用不再提供撤销；本地备份恢复是独立维护行为。

标题为空时，列表显示 hostname 作为替代文案；不把替代文案写回 title。打开链接不会修改 updated_at。数据修改、移动分类和状态切换会增加 revision；打开、查询、筛选和下载不会改变收藏内容。

### 3.2 `Category` 分类

字段为稳定 `id`、`name`、`created_at`、`updated_at`。收藏最多属于一个分类；“未分类”由空 category_id 表达，不是可改名或删除的真实分类行。分类名称去除首尾空白后为 1–64 个字符；按不区分大小写的规范化名称判重。

分类改名保留 id。删除分类会把所有 active、archived、trashed 收藏的 category_id 设为空，保留收藏及其状态；以后从回收站恢复也保持未分类。分类没有隐含的“删除整个文件夹内容”行为。

### 3.3 `ImportPreview` 导入预览（P1）

状态为 `validating → ready → committed`，或者 `validating/ready → failed/expired`。它绑定文件摘要、解析版本和当前数据修订标识，记录合法记录、重复项、错误项、将新建的分类及待确认数量。预览本身不写入收藏或分类；确认后对本次选定的合法新增项执行一个原子事务。

### 3.4 数据文件与备份（P1）

业务导出用于迁移可用收藏，备份用于保留整个本地实例。业务导出不包含回收站、应用配置或运行凭据；完整备份包括本应用的数据和必要配置，并标明文件版本与生成时间。备份不是“已经验证可恢复”的证据；没有做过真实恢复演练时应明确显示未验证。

## 5. 每个页面的详细规格

### P01 收藏首页

**目的与区块。** 顶部提供新建按钮、查询框；侧栏提供全部/未分类/各分类筛选；主体是结果数量、排序、列表和分页。每条收藏展示替代后的标题、hostname、描述摘要、分类、更新时间及明确操作入口。标题点击通过 `P01.open` 打开原链接，独立的“详情”入口通过 `P01.detail` 打开 P03，避免一次点击含义不清。

**数据范围与检索。** 只查询 active 收藏。`P01.search` 对标题、hostname、描述做不区分大小写的连续子串匹配；完整查询字符串作为一个条件，不默认拆词或使用正则。URL 路径、查询串、fragment 和分类名不参与关键字匹配。`P01.filter` 与搜索按 AND 组合，分类是独立条件。结果数为当前全部匹配数，不限于当前分页。默认 updated_at 倒序，同时间按 id 稳定排序；可选创建时间倒序、标题升序。每页 50 条，搜索覆盖整个 active 集合。

**操作与去向。** `P01.create` 进入 P02 新建；`P01.detail` 进入 P03。P1 的批量移动、归档、移入回收站只作用于显式选中的 id；“全选”仅选当前页，并展示数量。改变搜索、筛选、排序或分页即清空选择。筛选结果导出作用于当前条件命中的全部 active 收藏，按钮明确显示总数，不能把它误解为已勾选项导出。

**空与错误。** 全库首次为空时显示“保存第一条收藏”和解释，不显示报错。已有收藏但没有匹配结果时显示当前条件及“清除条件”，不诱导用户重复新建。加载失败保留查询条件并提供重试；不能把失败显示为 0 条收藏。写操作失败保留原列表，不预先移除记录，显示可重试动作。

### P02 新建与编辑

**目的与区块。** 表单包含 URL、标题、描述、分类和保存/取消。URL 必填，标题最多 200 字符、描述最多 2,000 字符。描述按纯文本处理，不执行 HTML。分类可选未分类、既有分类，或输入新分类名；若新名与既有分类规范化后相同，复用既有分类。

**数据与条件。** 新建编辑草稿不算已保存对象。仅 active/archived 收藏可编辑；trashed 收藏显示只读说明及 P06 恢复入口。URL 按 R01 校验。编辑加载 record revision，提交时检查版本；新建收藏与顺带新建分类在同一事务中提交，避免收藏失败却留下孤立分类。

**成功与取消。** `P02.save` 成功后进入 P03，显示保存后的值与当前状态；编辑 archived 收藏不会使其自动 active。`P02.cancel` 返回来源页面。存在未保存修改时离开应给出取消离开/放弃修改选择；浏览器关闭或刷新受浏览器能力限制，本版不承诺草稿自动恢复。

**异常与恢复。** 非法 URL、过长字段、分类重名冲突在对应字段附近显示原因，并保留所有输入。提交的 URL 已存在于其他收藏时，说明它位于收藏、归档还是回收站并给出对应入口，不自动覆盖或恢复。编辑同一条收藏保留原 URL 不算重复。选择的分类在提交前被删除时，要求重新选择分类。存储失败保留草稿和重试按钮；不得显示已保存。记录已被其他标签页修改时拒绝覆盖，展示最新记录信息和“保留当前输入后重新加载”的操作，不能静默采用最后一次提交。

**适用能力。** 页面不设搜索、分页、批量或导出，这些能力在此不适用。

### P03 收藏详情

**区块与范围。** 展示标题、完整 original_url、hostname、描述、分类、状态和创建/更新时间，允许复制 URL。URL 与描述都进行安全文本呈现；不加载第三方网页预览。active/archived 收藏均可查看；trashed 记录显示回收状态和恢复入口，禁止直接编辑。

**操作。** `P03.open` 只在用户明确点击时用新标签打开 original_url；导航属性按 R02。`P03.edit` 进入 P02。`P03.move` 选择目标分类后保存并更新当前详情。`P03.archive` 把 active 改为 archived；`P03.unarchive` 执行相反动作，两者成功后留在详情并显示新状态。`P03.trash` 显示收藏标题和“可在回收站恢复”的确认，成功后返回来源列表（无来源时返回 P01），显示“已移入回收站”及 P06 恢复入口。

**异常。** id 不存在时显示“收藏不存在”并提供 P01；已永久删除的链接不能返回空白详情。分类被删除后显示未分类。写入失败保持旧状态和操作入口，避免按钮表现为成功但对象未改变。页面无列表搜索、批量和导出；下载业务数据由 P07 或 P01 的导出入口负责。

### P04 分类管理

**区块与数据。** 展示分类名称及 active/archived/trashed 三个明确分栏计数，并有“未分类”只读汇总。计数是当前实例全量状态计数，不受 P01 查询条件影响。分类名称升序排列；名称筛选只作用于本页分类名，与收藏搜索独立。

**操作。** `P04.create` 校验名称后创建；`P04.rename` 修改名称但保留 id 和全部关联；`P04.open` 进入 P01 并选中该分类。`P04.delete` 必须说明“将使 X 条收藏变为未分类，不删除收藏”，其中 X 包含三种状态；确认后在同一事务内解除关联并删除分类。未分类不可重命名、不可删除。

**空与错误。** 首次无分类时说明收藏仍可保存到未分类，提供新建入口。名称重复时指出既有名称；提交时分类已被删除或计数变化，重新读取当前影响范围后再确认，不沿用错误计数。删除失败不能只删分类而留下失效外键。本版不提供分类批量删除或单独分类导出，避免改变收藏范围的含义。

### P05 归档

**目的与范围。** 保存暂时不常用的资料。只查询 archived 收藏，布局、搜索字段、分类过滤和排序规则与 P01 相同，页面始终显示“归档”范围。归档不是回收站，也不设自动到期。

**操作。** `P05.detail/open` 查看或打开；`P05.restore_active` 恢复 active，成功后从当前归档结果移出，并提供“去收藏列表查看”；`P05.trash` 保存 restore_state=archived 后移入回收站。P1 批量取消归档/删除使用与 P01 相同的选择规则和事务规则。P1 的筛选结果导出包含当前条件匹配的全部 archived 收藏，并在导出文件中保留 archived 状态。

**空与恢复。** 归档为空时说明用途并提供 P01。无结果与加载失败分开呈现。搜索或状态变更后当前分页为空时回到最后一个有效页；服务失败则留在原页等待重试，不能以缩页掩盖错误。

### P06 回收站

**目的与范围。** 只查询 trashed 收藏，展示删除时间、原状态和恢复后的目标位置；默认 trashed_at 倒序。支持标题/hostname/描述检索和分类筛选，不把原 URL 路径加入搜索。

**恢复。** `P06.restore` 恢复到 restore_state 指定的 active 或 archived；分类已经删除则为未分类，成功提示明确告诉用户去 P01 还是 P05。不把所有恢复项无条件放进首页。恢复后的对象从回收站结果移出。

**永久删除。** P1 的 `P06.purge` 和批量永久删除显示标题/数量及不可撤销说明，确认后执行；没有定时清空，没有进入页面就清理。回收站不提供业务导出入口，若需要保留其内容应使用完整备份。

**异常。** 回收站为空时说明“删除的收藏会暂存于此”。对象已被恢复时提示最新状态并提供对应详情；永久删除失败保持记录，允许重试。批量恢复遇到任何版本冲突时整批拒绝，重新读取状态后让用户重新选择。

### P07 导入导出（P1）

**输入与预览。** 接受 `atlas.bookmarks-transfer.v1` JSON 业务格式，单文件最多 5 MiB、5,000 条收藏。根对象包含 schema、categories 和 bookmarks 数组；categories 的每项含文件内唯一 key 与 name，bookmarks 每项含 original_url、title、description、可空 category_key 和 active/archived 状态。category_key 只能引用本文件分类，不是本地分类 id。导入不采纳外部本地 id、revision、时间戳或应用配置，新记录时间以本次导入为准。空分类和回收站不属于业务迁移范围。暂不承诺兼容浏览器 HTML 或其他产品的 CSV。

**导入语义。** `P07.preview` 先检查文件、schema 和逐条内容。JSON 语法错误或不支持的 schema 拒绝整个文件；单条错误在预览表中显示行号与原因。按去除 URL 首尾空白后的 original_url 精确字符串判重，不移除 query、fragment，不推断两个不同 URL 等价。同一文件重复项保留第一条有效记录；与本地任意状态重复则默认跳过。重复项若在回收站，明确提示到 P06 恢复，不隐式恢复或覆盖。

**确认与结果。** `P07.commit` 让用户明确确认“导入 N 条合法新增项，跳过 M 条重复，排除 K 条错误”。只为将导入的记录创建必要分类；名称匹配已有分类时复用。确认前本地数据已变化则要求重新预览。导入事务失败全部回滚，不留下部分收藏或孤立分类；成功显示新增/跳过/错误数量，并可进入 P01 或 P05 查找。记录导入结果摘要，但不永久保留上传文件中的额外敏感内容。

**导出语义。** `P07.export_all` 导出全部 active+archived 收藏；P01/P05 的筛选导出共用同一格式且清楚标明筛选范围。单个导出超过上述文件大小或条数限制时，按同一快照分成符合限制的 JSON 文件并打包下载，页面显示分片数量；导入首版逐个选择解压后的 JSON 文件，不宣称支持直接导入 ZIP。导出只是创建下载文件，不更改状态、不删除数据。下载生成失败可重试；文件名含日期与范围，内容是生成时一致的快照。完整备份由 P08 负责，不能把业务导出称为完整数据库备份。

### P08 设置与数据维护

**只读区块。** P0 展示应用版本、存储方式、可识别的数据目录、三种状态的收藏数量和分类数；给出“备份前不要删除该目录”的简明说明。这里不展示数据库连接凭据，也不把本机路径发送到外部服务。

**P1 维护能力。** `P08.backup` 在数据库一致性保障下生成完整本地备份，展示大小、时间、格式版本、摘要以及“恢复未验证/已由本机执行演练”的真实状态。运行中的数据库不得直接复制成一个可能不完整的文件后宣称成功。

**恢复边界。** 首版提供停止应用、备份现有数据、校验待恢复文件、恢复到独立目录并启动核对的离线步骤。页面不提供运行中覆盖数据库的按钮；恢复需要用户明确执行，不自动替换当前数据。本版没有“清空所有数据”快捷操作，避免把维护变成误删入口。

**异常。** 存储不可写、空间不足、备份失败显示原因与重试条件；不能只生成一个空文件作为成功结果。P08 不提供收藏检索、批量整理或分类筛选，它们由对应业务页面承担。

## 7. 关键规则

- **R01 URL 接受范围。** 去除输入首尾空白后保存；只接受显式 `http://` 或 `https://`，须能解析出非空 hostname；拒绝内嵌用户名/密码、控制字符和未编码的空白。单标签主机合法，例如 `http://intranet/guide?q=1#intro` 和 `http://localhost:8080/a`。不要求 DNS 或 HTTP 请求成功。`javascript:`、缺 scheme、空 host 均拒绝且无写入。
- **R02 原 URL 保存与打开。** 保存 original_url 的原始有效字符串，不剥离 path/query/fragment，不改参数顺序、不擅自去重或加追踪参数。打开控件的原始 href 属性采用该值，`target=_blank` 并使用适当的 opener 隔离。浏览器自己的导航规范化不等于应用改写；fragment 保留在导航 URL 中，不声称它会发送给服务器。解析出的 hostname 只用于展示与搜索。
- **R03 搜索规则。** 只匹配 title、hostname、description；分类通过独立条件筛选；URL 路径/query/fragment 不因恰好包含关键字而命中。空查询表示当前状态及分类范围内全部数据。大小写不敏感；不承诺模糊匹配、中文分词或自动纠错。
- **R04 分类删除。** 删除分类与全部状态收藏的解绑必须原子完成，绝不级联删除收藏。规范化名称重复时复用或明确拒绝，不能生成视觉同名分类。
- **R05 状态语义。** 归档、回收、恢复、永久删除是不同操作。恢复保留进入回收站之前的状态；回收站无自动清理期。trashed 收藏不出现在 P01/P05，不允许直接编辑。
- **R06 原子写入与冲突。** 保存、分类删除、导入和批量操作失败时不留下部分结果。针对旧 revision 的写操作拒绝覆盖；批量中任一所选记录冲突则整批拒绝，说明需重新读取。
- **R07 数量与选择。** 结果数覆盖当前完整查询集合；分类计数明确区分状态。选择集只包含当前页手动勾选 id，查询范围变化即清空。导出范围与选择范围在按钮上分别说明。
- **R08 唯一性与数据可携带性。** 在 active/archived/trashed 全部记录中，去除首尾空白后的 original_url 精确字符串唯一；手工重复新建或编辑成另一条已存在的 URL 时拒绝并提供原记录入口，永久删除后才可重新新建同 URL。不同 query、fragment 或不同 URL 字符串不自动视为同一资源。业务 JSON 导出只含选定的 active/archived 收藏及其引用分类；完整本地备份另行处理。导入默认跳过精确 URL 重复，任何覆盖策略都不属于本版默认行为。
- **R09 隐私与联网。** 应用不为了保存、预览或检查链接而自动访问第三方网站。只有用户主动打开链接才发生浏览器导航；业务数据不自动上传。
- **R10 证据诚实。** 规格完整、静态审阅通过、程序已生成、应用已运行、恢复已验证是不同状态；只有实际执行证据才能标后两者。
